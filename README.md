# 리그 오브 레전드 밸런스 패치 예측

과거 패치 이력에서 **개발사의 밸런스 조정 기준을 역추출**하고, 그 기준으로 다음 패치 내용을 예측한 뒤, 실제 패치와 대조해 **적중률을 측정하는** 시스템.

## 현재 상태

**데이터 확보 가능성을 확인하는 단계.** 계획서는 아직 없다.

슬레이 더 스파이어 2 시뮬레이터로 시작했다가 2026-08-24 에 주제를 바꿨다 — 게임을 재구현해야 해서 AI 부분에 도달하기 전에 무너질 구조였다. 이전 문서와 접은 이유는 [`docs/archive/`](docs/archive/)에 있다.

**계획서를 쓰기 전에 데이터부터 확인하고 있다.** 이전 주제에서 그 순서를 거꾸로 해서 계획서를 두 번 썼다.

## 무엇을 만드나

| 산출물 | 내용 |
| --- | --- |
| **밸런스 기준 문서** | 승률·픽률·밴율이 어떤 상태일 때 무엇을 어떻게 조정하는가 |
| **예측 시스템** | 현재 통계 → 다음 패치에서 조정될 챔피언·방향·항목·폭 |
| **검증 리포트** | 과거 패치 백테스트 적중률 + 통계 베이스라인과의 비교 |

## 증명하려는 것

| # | 주장 | 어떻게 |
| --- | --- | --- |
| 1 | 공개 데이터만으로 조정 기준을 문서화할 수 있다 | 규칙이 실제 패치를 얼마나 설명하는가 |
| 2 | 그 기준으로 다음 조정을 예측할 수 있다 | 과거 패치 백테스트 |
| 3 | **어디까지 예측되고 어디부터 안 되는가** | 대상·방향·항목·폭의 단계별 적중률 격차 |
| 4 | LLM·RAG·Agent 가 이 문제에서 값을 하는가 | **통계 베이스라인과의 비교표** |

**3번이 가장 정직한 결과다.** "다 맞힌다"가 아니라 "여기까지는 공개 신호로 설명되고 그 너머는 내부 판단이다"를 가르는 것.

### 증명하지 않는 것

- ❌ 우리가 개발사보다 밸런스를 잘 잡는다 — 판단을 **예측**하는 것이지 평가가 아니다
- ❌ 예측이 정확하다 — 정확도는 측정 대상이지 전제가 아니다
- ❌ 개발사의 내부 프로세스가 이렇다 — **관측된 패턴**일 뿐이다
- ❌ 이 도구로 밸런스를 대신 잡을 수 있다 — 판단 보조다

전부 실제로 요청해서 확인했다. 주소·형식·기간·검증 상태는 [`docs/spec/data-sources.md`](docs/spec/data-sources.md)에 있다.

**확정한 범위**: `world` 지역 · `ranked_solo_5x5` · **2023년 이후** (에메랄드 티어 추가로 그 전과 모집단이 다르다)

## 시작하기

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pre-commit install

cp .env.example .env
```

검사:

```bash
ruff check .      # 린팅
ruff format .     # 포매팅
pytest            # 테스트
mypy              # 정적 타입 검사
```

`pre-commit` 이 커밋 전에 ruff 를 돌린다. **`pytest` 와 `mypy` 는 자동으로 돌지 않으므로 직접 실행한다.**

## 기술 스택

| 기술 | 용도 |
| --- | --- |
| Python 3.11 | 전반 |
| pandas | 집계 |
| scipy · scikit-learn | **통계 베이스라인** — LLM 이 값을 하는지 비교 대상 |
| pydantic | 구조화 출력 강제 |
| anthropic | 패치 노트 구조화 · 규칙 추출 · 에이전트 |
| pytest · ruff · mypy · pre-commit | 코드 품질 |

버전 기준은 [`requirements.txt`](requirements.txt)와 [`requirements-dev.txt`](requirements-dev.txt), 근거는 [ADR-0001](docs/adr/0001-python-environment-and-tooling.md)에 있다.

### 도입하지 않는 것

| 기술 | 사유 |
| --- | --- |
| 파인튜닝 (LoRA·SFT) | 데이터가 표에 가까워 언어 모델의 강점이 안 살아난다. **판단 근거가 안 남아** 기획 산출물이 되지 못한다. 패치마다 재학습해야 한다 |
| 벡터 검색을 수치 조회에 | SQL 이 더 정확하고 빠르다. 벡터는 **텍스트**에만 쓴다 |
| LangChain / LangGraph | 도구 몇 개짜리 단일 루프라 오케스트레이션이 과하다 |
| FastAPI | 지금은 API 로 감쌀 이유가 없다 |

미뤄 둔 것은 [`docs/followups.md`](docs/followups.md)에 있다.
