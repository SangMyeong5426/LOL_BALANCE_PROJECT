## 한 줄

**「어느 쪽으로 조정할까」는 잘 맞고, 「누구를 조정할까」는 잘 안 맞는다.**

```
② 방향  너프냐 버프냐    AUC 0.900 (기준선 0.796)      ← 규칙으로 잡힌다
① 대상  누가 조정되나    R-정확도 27.4% (기준선 15.0% · 1.8배)  ← 잘 안 잡힌다
        누가 너프되나    R-정확도 22.9% (기준선  3.4% · 6.7배)  ← 좁히면 낫다
③ 효과  조정이 먹혔나    버프만 균형 쪽으로 확실히 움직인다 (63.1% vs 대조군 50.5%)
```

**LLM 판단은 다수결을 못 이겼다.** 대화 속 판단(`B6`)은 유의하지 않게, 로컬
모델 에이전트(`B8`)는 **같은 이웃을 보고도 유의하게** 졌다
([아래](#같은-이웃으로-다시-쟀다--에이전트-b8-2026-09-18)). 그래서 도구는 예측을 통계
모델에 맡기고, LLM 에는 **근거를 풀어 쓰는 해설**을 맡긴다.

본 분석은 공개 데이터를 쓴다 — 솔랭 승률·픽률·밴율과 프로 경기 픽·밴.
한때 프로 경기를 확장 분석으로 따로 뒀는데, **도구는 이미 그것을 쓰고 있어 문서만
어긋나 있었다**([ADR 0008](../adr/0008-pro-play-in-the-main-analysis.md)). 솔랭만
쓰는 arm 도 표에 그대로 있으므로 「넣으면 얼마나 오르나」는 같은 자리에서 읽힌다.

#### 프로 경기 피처의 기여는 버프에서만 선다 (2026-09-01)

`A7p`(프로 경기 피처)와 `A7`(뺀 것)을 **같은 재표본에서 짝지어** 뺐다. 각각의

말할 수 없다**가 맞는 표현이다 — 프로 피처가 값을 하는지는 ② 방향에서 따로 봐야 한다.

### 자르는 방식을 바꿔 봤다 — **F1 은 비슷하고 정밀도가 갈린다**

같은 라벨 3,263행, 같은 점수, 자르는 방식만 다르다.

| | 정밀도 | 재현율 | F1 | MCC | 정확도 | 몇 종이 걸리나 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 전부 「조정 안 됨」 | 0.0% | 0.0% | 0.000 | 0.000 | 85.3% | 0 |
| 점수 0.5 로 자른다 | 23.4% | 39.4% | 0.294 | 0.141 | 72.1% | 약 550종 |
| F1 최적 문턱 (0.44) | 19.9% | 60.0% | 0.299 | 0.131 | 58.6% | 더 많다 |
| 패치 안에서 K개 | 28.7% | 28.7% | 0.287 | **0.165** | 79.0% | 패치마다 다름 |
| **패치 안에서 상위 5** | **40.0%** | 7.9% | 0.132 | 0.124 | 84.7% | **항상 5종** |

**F1 로는 문턱과 순위가 사실상 같다**(0.287 vs 0.294 vs 0.299). 순위를 쓰는 이유는
성적이 아니라 **운영**이다 — 문턱으로 자르면 몇 종이 걸릴지 모르는데(어떤 패치는 80종),
밸런스 회의 전에 550종을 볼 수는 없다. **상위 5의 정밀도 40.0% 가 모든 방식 중 제일
높고, 개수도 고정된다.**

### 정확도로 보고하지 않는 이유

클래스가 85.3% 로 쏠려 있어 **아무것도 예측하지 않아도 정확도 85.3% 가 나온다.**
그래서 이 저장소는 정확도 대신 **기준선 대비 배수와 순위 지표**로 보고한다.

전 챔피언 5종 다중분류(너프·버프·adjust·mixed·조정 안 됨)를 그대로 돌리면 그것이
드러난다 — 정확도 0.850 인데 **Cohen κ 0.016**, macro F1 0.197 이다. 균형 가중을
주면 κ 0.071 로 오르고 정확도는 0.489 로 떨어진다. **모델을 다수 클래스로 도망가게
두면 지표가 좋아 보이는데 아무 일도 안 한 것이다.**

### 점수는 확률이 아니다

`class_weight="balanced"` 로 학습해 양성 쪽이 부풀려져 있다. 구간별 실제 조정률은
[아래](#점수를-확률로-읽으면-안-된다-2026-08-29)에 있다 — 「0.72」는 32% 쯤이다.
**Brier 0.134 · LogLoss 0.417 은 ② 에서만 재고**, ① 에서는 눈금을 안 맞췄다. 세 과제가
전부 줄 세우기라 필요가 없어서다.

### 세 번 밀어 봤을 때는 안 움직였다 — **조합 하나를 안 해 봤다**

한때 이렇게 적어 뒀다.

| 시도 | 전 | 후 |

| **부스팅 트리** (표 데이터의 표준 강자) | 25.6% | **25.8%** |

그리고 「모델 한계가 아니라 데이터 한계다」로 결론지었다. **틀렸다.**

**프로 피처를 부스팅에는 안 붙여 봤다.**

| | R-정확도 | AUC |
| --- | ---: | ---: |
| `A7` 부스팅 | 26.7% | 0.620 |
| **`A7p` 부스팅 + 프로** | **27.4%** | **0.625** |

**이 +0.7%p 는 평가 구간 한 번의 값이고, 짝지은 부트스트랩 구간
[−0.0147, +0.0271] 안이다** — [프로 경기 피처의 기여는 버프에서만 선다](#프로-경기-피처의-기여는-버프에서만-선다-2026-09-01).

**시드 8개에서 전부 같은 값이다**(표준편차 0.000). 회귀는 피처를 더해서 쓰므로
「프로에서 세면서 솔랭 승률은 낮다」 같은 조건을 표현하지 못한다. 트리는 그
상호작용을 나눠 담는다 — [부스팅을 넣은 이유](../../src/lol_balance/arms.py)와
같은 논리다.

왜 회귀에서는 안 보였는지도 이제 안다. 프로 픽·밴율의 신호가 **방향에 따라
반대**라 「조정되나」 하나로 물으면 상쇄된다.

기준선이 3%대다. **배수로 본다.**

「조정되나」로 물으면 1.8배인데 「너프되나」로 좁히면 6.7배다. 「조정 전부」에는
mixed·adjust 277건이 섞여 있고 그것이 거의 예측이 안 된다.

**프로 피처는 버프 대상에서 크게 산다**(R-정확도 11.1% → **15.3%** · AUC 0.706 →
**0.724**). 너프 대상에서도 이제 오른다(22.3% → 22.9% · 0.778 → 0.794).

이력 피처는 **신호가 분명히 있다** — 최근 5패치 조정 횟수가 늘수록 다음 패치 조정률이 16.9% → 35.4% 로 단조 증가하고, 기존 피처와 상관도 낮다(`pick_rate` +0.149 · `ban_rate` +0.190).

한때 「신호는 있는데 안 먹는다」로 적어 뒀다가 2026-08-27 에 뒤집었다. 패치 노트의 **핫픽스 절을 통째로 못 읽고 있었고**(53건), 핫픽스는 정확히 「방금 손댄 챔피언을 곧바로 또 손대는」 사례라 **이력 피처가 맞혀야 할 자리가 오답으로 채워져 있었다.** 고치니 `A7h` 가 `A7` 아래(25.6% < 25.8%)에서 위(27.1% > 26.7%)로 올라가고, 순열 중요도 합계도 −0.93% → **+0.34%** 가 됐다.

**그래도 `A7p`(27.4%)를 못 넘고, 패치 안 변별은 여전히 약하다**(AUC 0.545). 「이 챔피언이 자주 손대는 축인가」는 말하지만 「이번 패치에 손댈까」는 덜 말한다. 자세한 것은 [prediction-signals](../spec/prediction-signals.md#뒤집혔다-2026-08-27--핫픽스-누락이-이력-신호를-누르고-있었다).

### 천장을 쟀다 (2026-08-28) — **27.4% 에서 47.1% 사이가 남은 전부다**

「더 발전시킬 여지가 있나」를 재려고 **평가 구간 자체로 학습해 봤다.** 부정행위라
쓸 수 없는 값이지만, **이 피처로 낼 수 있는 상한**이 된다.

| | R-정확도 |
| --- | ---: |
| 정직하게 (학습 구간으로 학습) | **27.2%** |
| 부정행위 (평가 구간으로 학습) | **46.9%** ← 상한 |
| 완전한 정보 (라벨을 그대로) | 100% |

모델을 아무리 잘 만들어도 47.1% 를 못 넘고, 그것도 과적합으로 부풀려진 값이다.

#### 왜 그런지도 나왔다

상위 10 안에서 **맞은 것과 헛짚은 것이 거의 안 갈린다.**

| | n | 승률 | 픽률 | 밴율 | 판수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 맞음 | 68 | 0.489 | 0.103 | 0.181 | 118,017 |
| 헛짚음 | 132 | 0.482 | 0.081 | 0.136 | 96,995 |
| **놓침** | **448** | **0.500** | **0.060** | **0.050** | **60,927** |

놓친 448종은 승률이 정확히 5할이고 픽률·밴율이 낮다. 공개 지표에 아무 흔적이
없는데 조정된 것들이다. 위의 「어떤 규칙에도 안 걸리는 92건」과 같은 무리다.

하이퍼파라미터도 이미 학습 구간 3겹 교차검증으로 골라 뒀다. 여기서 더 짜낼
것이 거의 없다.

#### 그래서 남은 여지는 모델이 아니라 데이터에 있다

| 방향 | 무엇이 열리나 | 막힌 것 |
| --- | --- | --- |
| 다른 모집단(Elite · Average) | 개발사가 보는 판정 기준 넷 중 둘을 채운다 | **우리 구간에 5패치 이하** ([data-sources](../spec/data-sources.md#우리-구간13_14--16_15의-티어-2026-09-01)) |
| 챔피언별 아이템 구매율 | 아이템으로 이뤄진 조정을 라벨에 넣는다 | **소급 수집이 안 된다** ([followups](../followups.md)) |
| 솔랭 듀오 통계 | 조합 너프를 잰다 | 같음 |
| 트랜스포머 임베딩 | R2 검색 품질 | 키 필요 · [하네스는 준비됐다](../../scripts/score-retrieval) |

그래서 「모델이 부족해서」도 「피처가 부족해서」도 아니다. 공개 신호로 「누가 조정될지」는 여기가 한계다.

#### 점수를 확률로 읽으면 안 된다 (2026-08-29)

`class_weight="balanced"` 로 학습해 **양성 쪽이 부풀려져 있다.** 평가 구간
3,263행을 구간별로 세면 이렇다.

| 도구가 낸 점수 | 행 | 실제로 조정된 비율 |
| --- | ---: | ---: |
| 0.2 ~ 0.4 | 1,463 | 11.6% |
| 0.4 ~ 0.5 | 1,149 | 13.2% |
| 0.5 ~ 0.6 | 502 | 19.3% |
| 0.6 ~ 0.7 | 221 | 27.6% |
| 0.7 ~ 0.8 | 63 | 31.7% |
| **0.8 ~ 1.0** | 28 | **50.0%** |

**「0.72」는 72% 가 아니라 32% 쯤이다.** 전체 평균은 15.0% 다.

쓸모는 절대값이 아니라 **순서**에 있다 — 10.7% 에서 57.7% 로 다섯 배 넘게
벌어진다. 눈금을 맞추지 않은 것은 세 과제가 전부 줄 세우기라 필요가 없어서다.
확률로 읽어야 할 자리가 생기면 그때 보정한다.

#### 방향으로만 묻는다 (2026-08-29)

**「조정되나」는 안 낸다.**

모델 쪽이 막힌 뒤(위 다섯 실패) 남은 지렛대는 **무엇을 묻느냐** 하나였다. 방향
좁히기와 컷을 같이 걸어 쟀다.

| 무엇을 보나 | 상위3 | 상위5 | 상위10 | 기준선 |
| --- | ---: | ---: | ---: | ---: |
| 조정 후보 | 38.3% | 38.0% | 34.0% | 15.0% |
| → 배수 | 2.5배 | 2.5배 | 2.3배 | |
| **너프 후보** | **31.7%** | 24.0% | 17.5% | **3.4%** |
| → 배수 | **9.3배** | **7.0배** | 5.1배 | |
| 버프 후보 | 16.7% | 13.0% | 11.5% | 3.6% |
| → 배수 | 4.7배 | 3.7배 | 3.2배 | |

**조정 후보가 정밀도는 제일 높은데 배수는 제일 낮다.** 기준선이 15.0% 라 아무나
찍어도 어느 정도 맞아서다. 도구가 값을 하는 자리는 **찍어서는 거의 안 맞는
질문**이고, 그것이 방향이다.

그래서 `predict` 에서 **「조정 후보」를 뺐다.** 셋을 나란히 내면 제일 안 쓸모
있는 것이 맨 위에 온다.

##### 컷은 5 로 뒀다

    패치당 실제 조정 수   중앙값 22.5 · 범위 11~41

      상위    정밀도   맞는 수   재현율
        3    38.3%     1.1     4.6%
        5    38.0%     1.9     7.9%
       10    34.0%     3.4    14.3%
       20    29.3%     5.9    24.7%
       40    24.3%     9.7    40.0%
      (조정 후보 기준. 방향별 값은 위 표)

**정밀도는 5에서 꼭대기를 찍는다.** 3 이 너프에서는 더 높지만(31.6% · 9.4배)
맞는 수가 1.0 종이라 목록이라기엔 얇다. 넓히면 정밀도가 단조로 내려간다.

**재현율은 숨기지 않는다.** 너프 상위5의 재현율은 한 자리 수다. 조정될 21종 중
대부분을 놓치고, 20 을 뽑아도 23% 다 — 순위를 넓혀서 해결되는 문제가 아니라
위의 천장이 그대로 나타난 것이다.

#### 모델 쪽을 아홉 번 밀어 봤다 (2026-08-29 · 08-31) — **전부 실패**

「천장이 있다」만으로는 정말 끝인지 알 수 없어, 안 해 본 조합을 골라 시험했다.
**고르는 것은 학습 구간 3겹 교차검증으로 하고 평가 구간은 승자 하나만 한 번
봤다** — 평가를 보고 고르면 그것이 누출이다.

| 시도 | 결과 |
| --- | --- |
| `A7hp` — 이력과 프로를 **같이** | CV 0.317 < `A7h` 0.334 ❌ |
| 시드 앙상블 5·15개 | 값이 한 자리도 안 바뀐다 — 부스팅이 결정적이다 ❌ |
| 부스팅 + 회귀 순위평균 | **CV 0.349 ↑ · 평가 0.260 < 0.272** ❌ |
| 확장 학습 (패치마다 재학습) | 조정 +0.007 · 너프 −0.031 · 버프 −0.014 ❌ |
| 목표를 「방향 있는 조정」으로 | 2.1배 vs 지금 1.9배 — 사실상 같다 ❌ |
| **판수로 학습 표본에 가중** | CV 0.3338 ≈ 0.3341 — 변화 없다 ❌ |
| **패치 안에서 피처를 표준화** | CV 0.3121 — 오히려 내려간다 ❌ |
| **R2 이웃 다수결** | 조정 0.9배 · 버프 0.6배 — 기준선 이하 ❌ |
| **R2 를 피처로** | CV 0.3401 ↑ · 평가 0.2708 ≈ 0.2714 ❌ |

**셋째를 남겨 둔다.** 세 겹 전부에서 올라 「됐다」고 볼 만했는데 평가 구간에서
뒤집혔다. **33패치 3겹으로는 0.015 차이를 못 가른다** — 다음에 같은 것을 시도할
사람이 같은 자리에서 속는다.

넷째는 `predict` 가 실제로 하는 방식이다. **조정은 조금 오르고 방향은 내려간다** —
최근 데이터를 더 넣는 것이 방향 예측에는 손해다. 19패치뿐이라 실제인지 잡음인지는
말할 수 없다.

첫째는 [README 가 적은 실수](../../README.md#결과)와 같은 종류를 노린 것이었다.
프로를 부스팅과 안 붙여 본 것이 26.7% → 27.4% 였으므로 이력도 그럴까 봤는데,
**이번에는 아니었다.**

##### 여덟째·아홉째 — **노트 검색(R2)은 왜 점수에 안 쓰이나** (2026-08-31)

R2 는 검색 성적이 제일 좋은데(MRR@10 0.946 · Recall@10 99.2%) **점수를 내는 arm 이
하나도 안 쓴다.** 안 해 본 것인지 안 되는 것인지 몰라 둘 다 해 봤다.

**여덟째 — R1 과 같은 구조로, 거리만 텍스트.** 「노트가 비슷했던 챔피언들은 그 뒤
어떻게 됐나」를 다수결한다.

    학습 23패치      R2 arm    기준선     배수
    조정             18.3%    20.7%    0.9배   ← 기준선 이하
    너프              4.2%     3.6%    1.2배
    버프              3.3%     5.3%    0.6배   ← 기준선 이하

**아홉째 — 이웃이 아니라 피처로.** 노트에 마지막으로 나온 지 몇 패치인지, 최근
5전환에 몇 번 나왔는지, 그때 몇 줄이 바뀌었는지 셋을 `A7h` 에 붙였다.

    A7h              CV 0.3341   평가 0.2714
    A7h + 노트 피처    CV 0.3401   평가 0.2708   ← 또 전이가 안 된다

**왜 안 되는지는 뜻이 통한다.** 노트 텍스트는 **「무엇이 바뀌었나」**를 적지
**「다음에 누가 바뀌나」**를 적지 않는다. 같은 「피해량 너프」 문장을 가진 두
챔피언이 다음 패치에 같은 일을 겪을 이유가 없다.

**검색이 정확한 것과 그 검색이 예측에 쓸모 있는 것은 다르다.** R2 는 앞엣것에서
99.2% 이고 뒤엣것에서 기준선 이하다. 둘을 따로 재 두지 않았으면 「RAG 를 붙였으니
좋아졌겠지」로 넘어갔을 것이다.

**R2 는 그래서 `ask` 와 배포 페이지에만 남는다** — 사람이 읽을 근거로는 값을 하고,
점수로는 안 한다. 에이전트가 생기면 다시 볼 자리이기도 하다.

**에이전트가 생겼고(2026-09-18) R2 는 해설에만 쓰인다.** 평가에서는 익명 조건 때문에
뺐다 — 노트의 스킬 이름이 대상의 정체를 드러낸다. 점수로 쓰일 자리는 여전히 없다.

##### 여섯째·일곱째는 데이터 감사에서 나왔다 (2026-08-31)

「데이터가 이상한 것 아닌가」를 확인하려고 패널을 감사했다. **구조는 멀쩡했다.**

    승률 평균 0.5006 · 표준편차 0.0147 · 5할±5%p 밖 0.5%
    패치별 평균 승률   53패치 전부 0.498~0.502   ← 치우침이 없다
    픽률 합           정확히 10.00              ← 5역할 × 2팀. 파싱이 정확하다
    챔피언 163~173종

**연속 패치 승률 상관이 판수로 완전히 설명된다.**

    14_5  → 14_6    0.243      판수   3,159 →   1,335
    13_16 → 13_17   0.439            8,308 →   1,131
    16_12 → 16_13   0.942           85,094 → 112,546
    15_19 → 15_20   0.948           75,277 →  71,847

즉 **편향이 아니라 잡음이다** — 값이 치우친 게 아니라 흔들린다. 편향이면 패치 평균이
5할에서 벗어나는데 안 벗어난다.

여기서 **학습 구간(2023년 판수 중앙값 3,649)이 평가 구간(2026년 68,869)보다 훨씬
잡음이 많다**는 것이 드러났다. 흐릿한 데이터로 배워 선명한 데이터로 시험보는 셈이라,
① 판수로 학습 표본에 가중을 주고 ② 평가가 패치 안 줄 세우기이므로 피처도 패치 안에서
표준화해 봤다. **둘 다 안 됐다.**

하이퍼파라미터는 **학습 구간 안에서 시간순 3겹 교차검증으로** 골랐다. 평가 구간을 보고 고르면 그것이 곧 누출이다.

**승률 순(A0c)이 무작위보다 나쁘다**(AUC 0.448). 조정되는 쪽이 양 끝이라 단조롭지 않다. 거리로 바꾸면(A0d) 0.569 로 뒤집힌다.

#### 데이터 쪽을 밀어 봤다 — **아홉 갈래 · 93회 측정, 걸린 것 2건 · 채택 0** (2026-09-01)

모델을 아홉 번 민 것이 다 실패했으므로 이번에는 **입력을 늘렸다.** 「무엇을 보고
너프하고 버프하는가」의 근거를 최대한 찾아 피처로 만들고 같은 잣대로 쟀다.

**절차를 하나로 고정했다.** 갈래마다 다르게 재면 비교가 안 된다.

    1. 학습 구간(13_14 ~ 15_12)에서 패치 하나씩 앞으로 밀며 20겹
    2. 짝지은 차이의 평균 ± 표준오차. 2 표준오차를 넘어야 「걸렸다」
    3. 걸린 것만 평가 구간을 한 번 본다

피처를 붙이는 arm 은 `A7p` 다. 기준값은 ① 0.3412 · ①′ 0.2656(둘 다 R-정확도) ·
② 0.9118(AUC) 이다. **이 93회는 저장소와 다른 설정으로 쟀다** — 거르는 쪽이라
`class_weight="balanced"` 를 뺐고, 그래서 여기 값은 공개된 `A7p` 27.4%(평가 구간)와
같은 자리의 숫자가 아니다. 살아남은 후보는 저장소 설정으로 다시 쟀다.

| 갈래 | 넣은 것 | ① 조정 | ①′ 너프 | ② 방향 |

##### 잡음 열을 넣어 봤다 — **①′ 의 양수는 난수와 못 가른다**

위 표는 갈래마다 **열을 전부 넣었을 때**다. 실제로는 갈래를 피처 묶음 31개로
쪼개 3과제씩 93회를 쟀고, **「전부」를 뺀 묶음 22개 중 20개에서 ①′ 너프가
양수다.** 「신호는 있는데 표본이 모자란다」로 읽을 수도 있어, 아무 뜻 없는
난수 열을 같은 수만큼 넣어 봤다.

    난수 열         ① 조정              ①′ 너프             ② 방향
      2개    +0.0011 ±0.0023   +0.0121 ±0.0078   −0.0040 ±0.0029

     12개    −0.0060 ±0.0026   +0.0286 ±0.0120   +0.0094 ±0.0066

**난수만 넣어도 ①′ 가 열 수에 따라 +0.006 ~ +0.029 움직인다.** 위 표의 작은
양수(+0.009 ~ +0.031)는 그 폭 안팎이다 — 제일 큰 아이템 격변 +0.031 ±0.0197 도
자기 표준오차 안에서 난수와 갈리지 않는다. 큰 둘 — 프로 승률·성적 +0.048
±0.0236 과 리그 +0.040 ±0.0211 — 은 난수 평균보다 크지만 **자기 표준오차가
그만큼 커서 난수와 구별되지 않는다.** 「난수 수준이다」가 아니라
**「난수와 못 가른다」**다.

**①′ 는 열을 더하면 움직인다.** 단조롭지 않다 — 12열이 제일 높고 20열이 제일
낮다. 시드 다섯 사이 표준오차도 ±0.008 안팎이라 바닥 자체가 흔들린다. 패치당
실제 너프가 2~11종(중앙값 4.5)이라 R-정확도가 한 종에 0.09~0.5씩 튀는 것이
그 아래에 있다.
반대로 ① 은 열을 더하면 내려간다(난수 20열에 −0.022). **표의 ① 음수도 신호가
나쁘다는 뜻이 아니라 열을 더한 대가다.**

잡음 열을 안 뒀으면 「프로 승률이 너프 예측을 4.8%p 올린다」로 적었을 것이다.

##### 남은 하나 — 직전 패치의 버프 비율

난수 바닥 위에 남은 것은 하나다. **직전 패치에 이뤄진 조정 중 버프가 몇 %였나**
(`buff_ratio_1`)를 ② 방향에 넣으면 **+0.0218 ±0.0084** 다. 20겹 중 11겹에서
오르고 내린 겹은 0, 제일 큰 겹을 빼도 +0.0141 ±0.0037 로 남는다.

(`buff_ratio_3` 을 같이 넣으면 +0.0174 ±0.0061 로 희석된다 — 그 열 단독은
−0.0049 ±0.0107 로 방향조차 없다. **3패치 누적이 아니라 직전 하나가 신호다.**)

**패치 안에서 상수인 값이 어떻게 줄 세우기를 바꾸나.** 트리가 그 값으로 갈라
「직전이 버프 편중이었을 때」와 아닐 때 승률을 다르게 읽는다. 상수 이동이 아니라
조건 분기다.

**그런데 저장소 설정으로 재면 문턱 아래로 내려간다.** 이번 93회는
`class_weight="balanced"` 를 빼고 쟀는데, 저장소의 `_boosting()` 을 그대로 쓰면
+0.0139 ±0.0075 로 **1.9 표준오차**가 되고 오른 겹도 11에서 6으로 준다.

평가 구간은 한 번 봤다 — 저장소 `_boosting()` · `buff_ratio_1` 단독이다.

    ① 조정    0.2739 -> 0.2827   (+0.0088)
    ①′ 너프   0.2287 -> 0.2408   (+0.0121)
    ② 방향    0.8780 -> 0.8866   (+0.0085)

셋 다 오르는 쪽이다. **그래도 채택하지 않는다.** 미리 정한 절차로는 2 표준오차를
넘었지만(2.6) 저장소 설정으로는 1.9 다. 같은 홀드아웃을 이번 93회의 설정으로
재면 ① +0.0064 · ①′ **−0.0004** · ② +0.0043 이라 **①′ 는 오르지도 않는다** —
**설정 하나에 뒤집히는 크기다.**
[셋째 실패](#모델-쪽을-아홉-번-밀어-봤다-2026-08-29--08-31--전부-실패)가 학습
구간 세 겹 전부에서 올랐다가 평가 구간에서 뒤집힌 자리였다.

##### 붙일 arm 을 잘못 고를 뻔했다 — **`A7h` 로 재면 안 나올 것이 나온다**

처음에는 스킨·출시 시점을 `A7h`(이력·역할)에 붙여 쟀고 ① +0.022 · ② +0.036 이
나왔다. 둘 다 2 표준오차를 넘어 「걸렸다」로 볼 뻔했다.

**최고 arm 은 `A7h` 가 아니라 `A7p`(프로 경기) 다.** 붙일 arm 을 옮기니 전부 1 표준오차
안으로 들어갔다. 스킨 줄 수는 픽률과 상관 +0.26 인 인기 대리 지표인데, **프로
픽·밴율이 이미 같은 것을 더 직접 재고 있다.**

**약한 arm 에 붙이면 겹치는 신호가 이득처럼 보인다.** 새 피처는 그 과제의 최고
arm 에 붙여야 한다.

#### 개발사가 공개한 기준 (2026-09-01)

지금 저장소의 규칙 12개는 전부 **데이터에서 뽑은 것**이다. 개발사가 공개한 기준이
따로 있다 — 「/dev: Champion Balance Framework」(2019)와 그 갱신본(2020)이다
(주소는 [data-sources](../spec/data-sources.md#6-공개-밸런스-기준--개발사가-적어-둔-문턱)).
근거의 출처가 달라 따로 대 봤다. **2019·2020년에 공개한 것이고 지금도 이대로인지는
모른다.**

| 모집단 | 세다 | 약하다 |
| --- | --- | --- |
| Average (상위 10% 밖) | 승률 54.5%(밴율 평균 이하) ~ 52.5%(평균의 5배). 2020년에 상단을 0.5%p 조였다 | 승률 49% |

| 프로 (상위 5리그) | 프로 픽·밴율 90%, 또는 연속 패치 80% | 프로 픽·밴율 5% |

역할별 성적(승률+밴율) 1위도 너프를 검토한다」.

**이것은 상관 하나다.** 그 선 위에서 조정이 더 잦았다는 것뿐이고, 개발사가 이

모델이 그 둘을 이미 본다는 설명이 가능하지만 **그것은 해석이고 재지 않았다.**

**문턱보다 중요한 것은 모집단이 넷이라는 점이다** —
[밝혀 두는 한계](#모집단-넷-중-둘만-본다)에 적었다.

**공개된 버프 편중 안전장치가 켜지는지는 우리가 고른 두 값에 달려 있다.**
조건이 「연이은 패치의 조정 중 절반 넘게 버프면」인데 **「연이은」이 몇 패치인지도,
「조정」에 무엇을 넣을지도 안 적혀 있다.**

    분모   `adjust` 652건과 `mixed` 233건을 조정으로 세면 버프가 26.5% 다

**분모를 바꾸면 결론이 뒤집힌다.** 「한 번도 안 켜진다」는 `adjust`(버그 수정·
효과음·스킨 포함)와 `mixed` 를 조정으로 셀 때만 참이다. 개발사가 무엇을 세는지
우리는 모르므로 **어느 쪽이라고 말하지 않는다.**

`B5` 는 「RAG」가 아니라 그 검색부다. RAG 는 검색해서 **생성**한다는 뜻인데
`B5` 는 이웃 `k` 개를 찾아 **라벨을 다수결**한다 — 생성 단계가 없다. 그 위에
판단을 올린 것이 `B6` 이고, 용어는 [glossary](../glossary.md#rag--판단을-올려-봤고-이긴다고-말할-수-없다)에 있다.

대화 산출물 둘 다 통계를 못 이겼다.

| `B4` 규칙 | 0.837 | 로지스틱 회귀(`B2h` 0.841)에 **살짝 진다** |

이것이 [CLAUDE.md](../../CLAUDE.md) 가 요구하는 비교다 — **통계 베이스라인 없이
LLM 성능을 주장하지 않는다.** 이기지는 못했고, 못 이겼다고 적는다.

최고는 프로를 쓴 사례 검색(`B5p` 0.900)이다. 승률 한 줄(`B0b` 0.796)보다
+0.104, 다수 클래스로 찍기(0.510)보다 훨씬 위다. 솔랭만으로는 `B5` 0.856 이고,
**그 차이 +0.044 가 프로 경기가 더 보는 것**이다.

### 검색 위의 판단(B6)과 다수결을 왜 나란히 못 읽나

대화 안에서 0~100 점을 매기고 근거를 적었다. 평가 239건 중 **229건**이다 —
핫픽스 라벨 44종을 붙이며 평가 구간이 늘었고 그 행들에는 판단이 없다. 표본이
다르면 짝지어 비교가 안 되므로 `B5` 도 같은 229종으로 잘라 `B5s` 로 함께 실었다.

판단을 새로 만들지 않는 이유는 오염이다. 빠진 10종 중 9종은 **핫픽스 라벨을
붙이는 바로 그 자리에서** 방향을 정한 것들이다. 지금 판단을 적으면 판단이 아니라
답을 옮겨 적는 것이 된다. 익명화가 막는 것은 「예전에 붙인 라벨을 기억하는가」이지
(상한 검정 AUC 0.505), 「방금 붙인 것을 아는가」가 아니다.

빠진 것이 무작위가 아니라는 점은 따로 봐야 한다. 같은 `B5` 로 두 집단을 재면
이렇다.

```
전체 239종      AUC 0.856
판단 있는 229종  AUC 0.850    ← B6 이 실제로 겨루는 구간
빠진 10종       AUC 1.000     n=10, 크기가 못 믿을 값이다
```

빠진 쪽이 쉬운 쪽이다. 그래서 `B6` 0.830 을 239종에서 잰 `B5` 0.856 과 나란히
놓으면 **`B6` 을 실제보다 나쁘게 본다.** `B5s`(0.850)가 옳은 상대다.

```
B5s 다수결        AUC 0.850   정확도 76.0%   점수 25종
B6  검색 + 판단    AUC 0.830   정확도 77.7%   점수 50종
```

차이 −0.020, 95% [−0.045, +0.004]. 짝지어 부트스트랩 2만 회에서 **구간이 0 을
포함한다** — `B6` 이 더 높을 확률 5.1%. **한때는 0 을 안 넘었는데**(−0.031,
[−0.057, −0.005]) 표본이 234 → 229 종으로 바뀌며 경계로 왔다.

#### 되돌린 판단 — **둘이 같은 이웃을 본 것이 아니었다** (2026-09-01)

이 절은 오래 **「`B5` 와 같은 이웃 25종을 놓고 판단했다」**로 적혀 있었고,
`ragjudge.py` 의 주석도 「같은 검색 결과 위에서 판단해야 「다수결 대신 판단하면
나아지는가」를 재는 것이 된다」고 의도를 밝혀 두었다. **`k` 는 같았는데 검색 풀이
달랐다.**

    맥락 블록   `make-rag-context` 가 패널 전체를 넘긴다      8,767행
    `B5`    `direction_arms` 가 방향 붙은 행만 쓴다        710행

`k=25` 로 같아도 뽑히는 것이 다르다. 실측하면 이렇다.

    맥락 블록 이웃 25종 중 방향이 붙은 것   중앙값 2 · 평균 2.4 · 아예 0인 대상 41/239
    `B5`  이웃 25종 중 방향이 붙은 것   중앙값 25 · 평균 25.0

**판단자는 쓸 수 있는 사례를 중앙값 2개 보고 다수결은 25개를 봤다.** 반대로
판단자는 대상 자신의 지표(승률·픽률·밴율·추세)를 봤고 다수결은 그것을 안 쓴다
(`ragjudge.render`). **양쪽 입력이 서로 다른 방향으로 어긋나 있어, −0.020 을
「판단 대 다수결」의 차이로 읽을 수 없다.**

이 절이 이미 「이웃이 하나도 없는 대상(약 20%)」이라고 적어 두고도 같은 문단에서
「같은 이웃을 보므로」라고 쓰고 있었다. **한 절 안에서 어긋나 있었고 오래 안 걸렸다.**

#### 판단은 지표 여섯 항의 선형 읽기와 구별되지 않는다 (2026-09-01)

판단자가 맥락 위에 무엇을 얹었는지 직접 쟀다. 판단 점수를 **대상 자신의 지표
여섯 항**(승률·픽률·밴율·격차·승률 변화·픽률 변화)으로 되맞춰 본다.
**패치 단위 leave-one-out** 이라 같은 패치가 학습과 평가에 같이 들어가지 않는다.

    지표 6항으로 재구성        R² 0.867 · 상관 0.932
    AUC   원본 판단 0.8301     재구성 0.8630     ← 재구성이 더 낫다
    판단 − 재구성(잔차)만으로    AUC 0.5081  [0.431, 0.585]   ← 찍기와 못 가른다

**판단자가 선형 읽기 위에 얹은 것은 찍기와 구별되지 않고, 그 얹음이 AUC 를
0.03 깎는다.**

**「이웃을 안 봤다」는 뜻은 아니다.** 여섯 항에 이웃 다수결을 더하면 같은
leave-one-out 에서 R² 가 **0.867 → 0.942** 로 오르고, 잔차와 이웃 다수결의
상관이 **+0.53** 이다 — 판단자가 이웃을 보고 점수를 움직인 것은 맞다.

    지표 6항              R² 0.867   재구성 AUC 0.8630
    지표 6항 + 이웃 다수결   R² 0.942   재구성 AUC 0.8423   ← 오히려 나빠진다

**움직이기는 했는데 그 움직임이 방향을 못 맞힌다.** 이웃 성분을 넣은 재구성이
오히려 더 나쁘다. 여기서 잰 것은 거기까지다.

「판단이 검색에 닻을 내린다」로 적어 두었던 설명은 이것으로 바뀐다 — **닻은
내렸는데 그 닻이 방향을 안 가리켰다.**

**공정하게 다시 재려면 판단을 새로 만들어야 한다.** 맥락 블록이 `direction_rows` 를
쓰도록 고치고 239건을 다시 판단하는 것인데, **지금 그 판단을 할 수 있는 사람이
없다** — 이 대화에서 데이터를 깊이 봤으므로 오염 상한을 다시 못 세운다.
[followups 21](../followups.md)에 적어 둔다.

해상도는 병목이 아니었다. 점수 종류가 25 → 50 으로 두 배가 됐는데 AUC 는
내려갔다. `B4` 에서 해상도를 고쳐 0.807 → 0.837 이 된 것과 다르다.

#### 같은 이웃으로 다시 쟀다 — 에이전트 `B8` (2026-09-18)

바로 위가 「공정하게 다시 재려면 판단을 새로 만들어야 한다」로 끝났다. **에이전트로
그것을 했다.** 판단자가 로컬 모델이라 「데이터를 깊이 본 사람」의 오염이 없고,
키도 필요 없다([ADR 0009](../adr/0009-agent-framework-and-local-model.md)).

변형 `r1` 은 `B5` 와 **같은 이웃 25종**(조정된 사례만, 경계는 분할점 `15_13` 에
고정)과 대상 자신의 지표(`B6` 이 받은 칸과 같다)를 주고 판단만 맡긴다. 대상은 익명
키로만 부른다. 이웃 다수결을 같은 루프에 태운 규칙 에이전트가 `B5s` 를 **행 단위로**
재현한다(평가 0.850 · 개발 0.899) — 도구·경계·표본·채점이 맞다는 확인이다.

**고치고 고르는 것은 개발 표본에서 했다**(분할점 `14_13`, 학습 구간 안 114건).
평가 표본은 세 번 봤다.

그런데도 이웃을 세는 것보다 나빴다.

다수결을 따르라고 지시하면 숫자는 오를 것이다. **그것은 LLM 을 `B5` 로 만드는
것이라 하지 않았다.**

**이 결론의 범위.** 판단자는 작은 로컬 모델(`qwen3.5` 2b · 9b)이다. 「판단이
다수결을 못 이긴다」를 큰 모델로 넓히지 않는다 — `B6` 의 판단자(대화 속 Claude)는
입력이 달라 같은 비교가 안 된다([followups 21](../followups.md)). 이름만 주는
조건의 오염 상한은 재지 않았는데, 오염이 있었다면 판단을 부풀리는 쪽이라
「졌다」는 안 뒤집힌다.

**출처를 지어낸다.** 부르지 않은 도구를 근거의 출처로 적은 건이 `v1` 에서
**110/229** 였다. 코드가 대조해 기록에 남긴다(`unverified_sources`) — 최종 설정은 8/229.

**① 대상에는 돌리지 않았다.** 자동 호출이라 3,433행을 다 판단할 수는 있다(로컬
9b 로 약 18시간, 키를 받아 gpt-4o-mini 로 돌리면 약 $1.9 로 추정). 그래도 돌리지
않았다 — 결과가 두 갈래뿐이고 둘 다 새로 알려 주는 것이 없다.

| 조건 | 무엇이 나오나 |
| --- | --- |
| 익명 | R2(노트)를 빼야 한다 — 스킬 이름이 정체를 드러낸다. LLM 이 가진 정보가 통계 모델보다 **적다.** ② 에서 같은 증거로도 졌다 |
| 이름 | 노트를 쓸 수 있지만 모델이 그 패치의 결과를 **학습했을 수 있다.** 좋은 숫자가 나와도 판단인지 기억인지 못 가린다 |

다시 볼 조건은 ② 에서 판단이 다수결을 이기는 설정이 개발 표본에서 나오는 것이다.

그래서 화면(`scripts/app`)은 판단이 아니라 **해설**을 맡긴다 — [agent](../agent.md).
위 수치는 `./scripts/score-agent` 가 [판단 기록](../../ground_truth/agent/README.md)을
읽어 모델 없이 다시 낸다.

#### 판단자의 오염은 재서 배제했다

방향 라벨 1,599종을 대화 안의 Claude 가 붙였고 그것이 곧 채점 정답이다.
「기억 안 난다」는 검증할 수 없으므로 열쇠를 없애고 상한을 쟀다.

| 조건 | 주는 것 | n | AUC |
| --- | --- | ---: | ---: |
| `anon` | **이름 없이** 수치 · 이웃 · 노트 | 234 | 0.834 |
| `named` | **이름과 패치만.** 수치도 사례도 없다 | 80 | **0.505** |
| `named` — 이 대화에서 정답을 본 6건 제외 | | 74 | **0.421** |

찍기와 구별이 안 된다. 「일부러 50 점으로 채운 것 아니냐」에 대한 답도
데이터에 있다 — 아는 6건에는 20·25·65·70·80 점을 매겼다.

설계와 되돌린 판단은 [ADR 0006](../adr/0006-rag-generation-and-contamination-control.md)에 있다.

표본을 늘리니 순위가 뒤집혔다. 이것이 이번에 얻은 가장 중요한 것이다.

| | 전 | 후 |
| --- | ---: | ---: |
| 승률 한 줄 (B0b) | **0.836** | 0.803 |
| 로지스틱 회귀 (B1) | 0.759 | **0.813** |

전에는 **「승률 한 줄이 피처 열한 개짜리 회귀를 이긴다」**고 적었다. **그것이 표본
편향이었다.** 옛 표본은 Data Dragon 이 보는 것 — 기본 스탯·쿨다운 조정 — 에
쏠려 있었고, 그 부분집합에서는 승률이 유난히 잘 먹혔다. **피해량만 바뀐
챔피언을 넣자 승률 한 줄이 무너지고 회귀가 올라섰다.**

「단순한 것이 이긴다」는 결론은 **그 표본에서만 참이었다.**

**정교한 arm 들은 조금씩 내려갔다**(B4 −0.032 · B5 −0.009 · B7 −0.009). 새로
들어온 222종이 더 어렵다는 뜻이다.

**B4 의 규칙을 다시 제안해 봤는데 안 올랐다**(0.809 → 0.811). 새 규칙 셋이
개별로는 평가에서 80~96% 인데 **기존 규칙과 100% 가까이 겹쳐** 172건 중 1건만
새로 덮는다. 남은 28건은 승률이 정확히 5할이라 **공개 지표가 어느 쪽으로도
기울지 않는다.** 자세한 것은 [balance-rules](balance-rules.md).

**B5(사례 검색)가 가장 덜 흔들렸다**(−0.009).

### 손 라벨을 전량으로 늘렸다 — **커버리지 100%**

242 → 424 → 618 → 1,555 → **1,599** (11 → 17 → 23 → **52패치**). 1,606종 중 1,599종이고
빠진 7종은 그 패치에 처음 나온 챔피언이다. **충돌은 끝까지 0 이다**(채점 대상 407종).

`◆` 는 프로 경기를 쓰는 arm 이다.

| arm | 242 | 424 | 618 | **1,555** |
| --- | ---: | ---: | ---: | ---: |
| ◆ B2p 수준+추세+프로 | — | — | 0.860 | **0.885** |
| ◆ B1p 수준 + 프로 | 0.856 | 0.863 | 0.877 | 0.880 |
| **B5 사례 검색** | 0.854 | 0.851 | 0.857 | **0.856** |
| B7 부스팅 | 0.828 | 0.838 | 0.836 | 0.850 |
| B1 회귀 — 수준 | 0.813 | 0.814 | 0.826 | 0.834 |
| B4 규칙 | 0.811 | 0.800 | 0.798 | 0.837 |

마지막 열은 **2026-08-27 재측정**이다(핫픽스 절·이름 어긋남 수정 뒤). `B4` 만
앞 열들과 결이 다른데, 그 사이에 **점수 해상도를 고친 것**이 겹쳐서다 —
0.807 → 0.837 의 경위는 아래 「규칙은 0.807 이었다」에 있다.

라벨을 늘릴 때마다 거의 모든 arm 이 올랐다. 첫 확장에서 결론 둘이 뒤집힌
뒤로는 순위가 흔들리지 않고 값만 올라갔다 — **표본이 부족해서 낮게 나오고 있었다.**

`B4` 규칙만 0.807 로 뒤처지는데, 규칙이 덮지 못하는 자리 — 승률이 정확히 5할인
챔피언들 — 은 라벨이 늘어도 그대로이기 때문이다.

## 프로 경기가 무엇을 더 보나

한때 본 분석 밖에 뒀다. 질문을 「**지금 솔랭 지표로** 예측할 수 있는가」로
잡았기 때문인데, **도구는 이미 프로를 쓰고 있어 문서만 어긋나 있었다**
([ADR 0008](../adr/0008-pro-play-in-the-main-analysis.md)). 지금은 본 분석에
들어가고, 이 절은 **프로가 무엇을 더 보는지**를 남긴다.

Oracle's Elixir 프로 경기 픽·밴(**29,977경기 · 72패치** — 2026-08-26 내려받기 기준. 2026-09-20 갱신본은 29,984 이고 패널은 그대로다). 패널 커버리지 98.1%,
**평가 구간은 100%** 라 비교 자체는 공정하다 — 결측 때문에 뺀 것이 아니다.

| arm | 방법 | AUC | 정확도 | 솔랭만 대비 |
| --- | --- | ---: | ---: | ---: |
| B1p | 로지스틱 회귀 — 수준 + 프로 | 0.880 | 80.8% | B1 **+0.046** |
| B2p | 로지스틱 회귀 — 수준 + 추세 + 프로 | 0.885 | **80.8%** | B2 **+0.046** |
| **B5p** | **사례 검색 — + 프로 · 거리가중** | **0.900** | 74.9% | B5 **+0.044** |
| A2p | **① 대상** — 로지스틱 회귀 + 프로 | 0.595 | — | A2 **+0.003** |

② 에서는 듣고 ① 에서는 안 듣는다. 프로 팀이 밴으로 「이게 세다」를 표시하지만
라이엇이 **누구를 건드릴지**는 그것으로 안 갈린다. `A2p` 를 ① 본 분석 표에 남겨 둔
이유가 이것이다 — **「겹치지 않는 신호를 더해도 안 오른다」가 ① 의 결론(데이터
한계)을 강화한다.**

### 어디서 갈리는가 — **승률 50% 미만인데 너프당한 69종**

솔랭만 보면 전부 「약하니 버프」로 읽어야 하는 구간이다.

| | n | 프로 픽·밴율 평균 |
| --- | ---: | ---: |
| 그런데 **너프당했다** | 69 | **0.361** |
| 버프받았다 | 295 | 0.077 |

**4.7배다.** 이 구간에서는 프로 픽·밴율이 승률보다 잘 가른다(AUC 0.754 vs 0.672).

```
Ryze   16_2   승률 0.483  솔랭밴 3.4%  프로밴 23.6%  프로픽 33.3%  → 너프
Jayce  16_13  승률 0.487  솔랭밴 6.9%  프로밴 42.2%               → 너프
Jinx   15_18  승률 0.509  솔랭밴 1.6%  프로밴  1.1%               → 버프
```

승률과 상관이 0.06~0.10 밖에 안 된다. 프로 밴율 단독 AUC 는 0.661 로 승률
(0.796)보다 **약한데도** 보태면 오르는 이유가 이것이다 — **더 센 신호가 아니라
다른 신호다.**

### 원인은 확정하지 못했다

후보 셋 중 둘을 지웠고 하나가 안 풀렸다. **「라이엇이 프로 경기를 본다」로는 적지
않는다** — 이 데이터로 알 수 있는 것이 아니다. 검정 내역과 되돌린 판단은
[followups 10번](../followups.md)에 있다.

### 두 지표가 어긋난다

솔랭 승률과 프로 픽·밴율은 상관이 0.06~0.10 밖에 안 된다. 서로 다른 것을 재고
있고, **조정 한 번이 양쪽에 닿는데 챔피언마다 배분이 다르다.**

용어는 [glossary](../glossary.md)에 있다. 여기서만 쓰는 것은 둘이다.

| | |
| --- | --- |
| **자주 나오는 챔피언** | 통산 프로 픽·밴율 **상위 25%**(0.182 이상)인 챔피언 42종 |
| **높은 쪽 / 낮은 쪽 너프** | 조정 직전 프로 픽·밴율이 **중앙값 위 / 아래**인 너프 |

픽·밴율 변화는 %p 가 아니라 자기 값 대비 비율이다. 챔피언마다 자릿수가 달라
(0.55 와 0.04) %p 로는 비교가 안 된다. 솔랭 승률만 %p 다.

버프 — 솔랭에는 똑같이, 프로 경기에는 다르게 닿는다.

| | n | 솔랭 승률 | **프로 픽·밴율** |
| --- | ---: | ---: | ---: |
| 자주 나오는 챔피언 | 85 | +0.73%p | **+35.0%** |
| 그 외 | 214 | +0.75%p | **+0.0%** |

![버프의 비대칭](../img/buff-asymmetry.svg)

**이 값은 [`run-effect`](../../scripts/run-effect)가 낸다** (2026-08-31). 그림은
[`make-effect-svg`](../../scripts/make-effect-svg)가 같은 함수를 불러 그리므로
**표와 그림이 갈릴 수 없다.** 한때
`87 / +37.1%` · `244 / +0.0%` 로 적혀 있었는데, 그것은 대화 중에 계산하고 스크립트로
남기지 않은 값이었다. 스크립트로 만들어 다시 재니 표본과 값이 조금 달라졌다.
**결론은 같다 — 자주 나오는 챔피언만 뛴다.**

솔랭 지표만 보면 이 차이가 안 보인다. 같은 크기로 올려 줬는데 한쪽만 프로 경기에서 뛴다.

#### 너프 쪽은 재현되지 않는다 — **열어 둔다** (2026-08-31)

    적혀 있던 값 (2026-08-27 재측정)   자주 나오는 61 −18.0%   그 외 160 −17.5%
    스크립트가 내는 값                  자주 나오는 62 −14.6%   그 외 152 −19.4%
    그전에 적었다가 철회한 값            자주 나오는    −14.6%   그 외     −23.1%

**스크립트가 내는 값이 철회된 옛 값과 거의 같다.** 재측정의 근거가 「핫픽스 라벨
44종을 붙이고 다시 쟀다」인데 그 라벨은 지금 패널에 다 들어가 있고(커버리지 100%),
그런데도 재측정 값이 안 나온다.

셋 중 무엇인지 **아직 모른다.**

| | |
| --- | --- |
| 가 | 재측정이 여기와 다른 필터를 썼다 |
| 나 | 재측정이 틀렸고 철회가 잘못이었다 |
| 다 | 이 스크립트가 재측정과 다른 것을 재고 있다 |

**어느 쪽인지 정할 근거가 없어 덮어쓰지 않는다.** 스크립트 값을 그대로 쓰면 철회된
주장을 근거 없이 되살리는 것이 된다. [followups 19](../followups.md) 로 연다.

**버프 쪽 결론은 이것과 무관하게 선다** — 도구가 띄우는 경고는 버프 경고다.

그래서 절대값이 아니라 비율로 적는다. 처음에 「너프도 자주 나오는 챔피언이 5배 빠진다」고
적었는데 **착시였다** — 자주 나오는 챔피언은 조정 전 픽·밴율이 0.522 로 높아 절대 변화가 클
수밖에 없다.

```
                        조정 전 픽·밴율   절대 변화   상대 변화
버프 자주 나오는 챔피언        0.127      +0.0450    +35.0%   ← 버프 쪽은 상대로도 유지된다
버프 그 외                  0.013      +0.0000     +0.0%
너프 자주 나오는 챔피언        0.522      −0.0777    −14.6%   ← 결론을 걸지 않는다
너프 그 외                  0.038      −0.0047    −19.4%
```

**전부 중앙값이고 네 줄 세 열이 다 `run-effect` 가 내는 값이다.** 여기 있던 옛 표는
조정 전과 절대 변화를 평균으로, 상대 변화를 중앙값으로 적어 **한 행에 두 통계가
섞여 있었다**(조정 전 0.190 은 평균 · 중앙값 0.127).

**너프 두 줄은 값만 싣고 결론을 붙이지 않는다.** 이대로 읽으면 「자주 나오는 쪽이
덜 빠진다」가 되는데 그 주장은 [followups 19](../followups.md)에서 철회돼 있고
어느 쪽이 맞는지 아직 못 정했다.

반대로 프로 경기 지표만 보면 솔랭이 상한다.

| 너프 후 | 높은 쪽 | 낮은 쪽 |
| --- | ---: | ---: |
| 승률 48% 미만 | **16%** | 4% |
| 승률 49% 미만 | **39%** | 13% |
| 이미 50% 아래인데 너프했다 | **34%** | 18% |

50% 를 정확히 맞추는 것은 가능한 작업이 아니다. 그러므로 50% 아래로 내려간 것
자체를 실패로 적지 않는다. **적는 것은 두 지표가 어긋나는 방향과 크기다.**

#### 이것은 일부에서만 일어난다

패치 30개 이상 나온 167종을 넷으로 가르면 이렇다.

| | 자주 나오는 챔피언 | 비자주 나오는 챔피언 | 계 |
| --- | ---: | ---: | ---: |
| **승률 낮음** (통산 평균 <49.5%) | **18** | **20** | 38 |
| 승률 보통 이상 | 24 | 105 | 129 |

승률 낮은 38종의 절반은 프로 경기와 무관하게 약하다.

```
프로 제약형 18종   Azir 0.42   K'Sante 0.43   Varus 0.52   Vi 0.44   Ezreal 0.30
그냥 약함  20종   Yuumi 0.01  Shyvana 0.01   Zed 0.02     Yasuo 0.03  Smolder 0.09
```

어렵다고 자주 나오는 챔피언인 것도 아니다 — Yasuo·Zed 는 어렵기로 유명한데 프로 픽·밴율이
0.03·0.02 다. **반대쪽도 있다** — 자주 나오는 챔피언 42종 중 24종은 승률이 보통 이상이다.

전체의 11%(18/167)에서만 두 조건이 겹친다. 그리고 겹치는 챔피언이라도
[고정 목록으로는 안 갈린다](#원인은-확정하지-못했다) — 챔피언 고유분 AUC 0.548 ·
패치 변동분 0.764. **챔피언이 아니라 상황이고, 그 상황이 자주 오지도 않는다.**

### 되돌린 판단 — **거리가중의 기여는 0 이었다**

처음에 「프로 피처 + 거리가중으로 0.866 → 0.901」이라고 적었다(그때 값이다). 쪼개 보니
거리가중은 아무것도 안 했다.

```
솔랭4 · k=25 · 다수결   0.856   ← 본 분석
솔랭4 · k=50 · 거리가중  0.860   거리가중만 켜면 오히려 내려간다
프로+ · k=25 · 다수결   0.900   프로 피처만으로 거의 전부
```

점수 종류가 25 → 206 으로 는 것은 사실이지만 **그것이 AUC 를 올린 게 아니다.**
규칙(B4)에서 해상도 진단이 통한 것을 보고 RAG 도 같은 원인이라 단정했다.

피처·이웃 수·가중 방식은 **학습 구간 3겹 시간순 교차검증으로** 골랐다. 솔랭
지표만으로 다시 고르면 `기본4 · k=50 · 거리가중`(CV 0.891)이 뽑히는데, 평가
구간에서는 0.860 으로 본 분석 `B5`(0.856)와 사실상 같다.

### 그때 알 수 있었던 경기만으로 다시 쟀다 — **머리 숫자가 유지된다** (2026-09-18)

프로 픽·밴율은 **패치 t 로 치른 경기 전부**로 센다. 그런데 그 절반(49.5%)이 t+1
출시 **뒤**에 열렸다 — t → t+1 을 예측하는 날에는 아직 없던 경기다
([data-sources](../spec/data-sources.md#경기-날짜--패치로만-묶으면-절반이-다음-패치-출시-뒤다-2026-09-18)).
머리 숫자 셋이 전부 프로를 쓰므로(① `A7p` · ①′ `A7nerfp` · ② `B5p`) 그 경기를
빼고 다시 쟀다. 다른 칸은 그대로 두고 **프로 두 칸만** 갈아 끼웠다.

| 집계 | 무엇으로 세나 | 프로가 비는 행 (학습 · 평가) |
| --- | --- | ---: |
| 현재 | 패치 t 경기 전부 | 3.1% · 0.0% |
| 출시일 경계 | 그중 t+1 출시일 전에 열린 경기만 | 6.2% · 5.0% |
| 7일 전 | 경계를 7일 앞당긴다 | **37.2%** · 15.0% |
| 최근 14일 | 출시일 경계 직전 14일의 경기, 패치 무관 | 0% · 0% |
| 최근 14일 · 7일 전 | 위를 7일 앞당긴다 | 0% · 0% |

| arm | 현재 | 출시일 경계 | 7일 전 | 최근 14일 | 최근 14일 · 7일 전 |
| --- | ---: | ---: | ---: | ---: | ---: |
| ① `A7p` R-정확도 | 27.4% | 27.4% | 27.1% | 28.7% | 27.9% |
| ①′ `A7nerfp` R-정확도 | 22.9% | **27.0%** | 25.4% | 24.1% | 24.5% |
| ② `B5p` AUC | 0.900 | 0.893 | **0.868** | 0.909 | 0.910 |
| ② `B1p` AUC | 0.880 | 0.870 | 0.871 | 0.866 | 0.863 |
| ② `B2p` AUC | 0.885 | 0.875 | 0.872 | 0.876 | 0.875 |

프로를 안 쓰는 줄(`A7` 26.7% · `A7nerf` 22.3% · `B5` 0.856 · `B1` 0.834 · `B2`
0.839)은 다섯 모두 같다.

머리 숫자를 「현재」와 짝지어 비교했다 — 부트스트랩 2만 회, ① 은 패치 20개를,
② 는 행을 다시 뽑는다.

```
                     ① A7p                  ①′ A7nerfp               ② B5p
출시일 경계     +0.000 [−0.017, +0.018]   +0.041 [+0.013, +0.076]   −0.007 [−0.016, +0.001]
7일 전          −0.003 [−0.020, +0.015]   +0.025 [−0.011, +0.064]   −0.032 [−0.056, −0.011]
최근 14일       +0.013 [−0.005, +0.031]   +0.012 [−0.008, +0.034]   +0.009 [−0.005, +0.025]
최근 14일·7일 전 +0.006 [−0.010, +0.022]  +0.017 [−0.018, +0.051]   +0.010 [−0.005, +0.027]
```

**머리 숫자는 미래 경기 덕이 아니었다.** ① `A7p` 는 그대로이고 ② `B5p` 는 구간
안에서 움직인다. 그날 실제로 보이던 값(최근 14일)으로 세면 오히려 조금 높다.

**「7일 전」에서 ② 가 떨어진 것은 결측 때문이다.** 경계 전 경기가 없는 패치가 많아
학습 행의 37% 가 프로 없이 남는다. 같은 경계를 창으로 세면(최근 14일 · 7일 전) 비는
행이 없고 0.910 이다.

**①′ 너프 대상은 늦은 경기를 빼면 오른다**(22.9% → 27.0%). 늦은 경기가 신호를
흐렸을 수 있는데 원인은 확정하지 않는다.

주의할 것 셋.

- **비교가 열두 개다**(조건 넷 × 머리 숫자 셋). 95% 구간이면 우연히 하나쯤 걸린다 —
  ①′ 의 +0.041 을 그 무게로 읽는다
- **「최근 14일 · 7일 전」은 첫 결과를 보고 더했다** — 「7일 전」의 결측을 가르려고.
  나머지 넷은 돌리기 전에 정했다
- **정의를 바꾸지 않는다.** 여기서 낫게 나온 집계로 바꾸면 평가 구간을 보고 고른
  셈이다. 바꾸려면 학습 구간 안에서 고르고 ADR 을 쓴다([followups 26](../followups.md))

프로 두 칸 말고도 `B1p` · `B2p` 가 0.01 안팎 내려갔다. 머리 숫자가 아니라 구간은
재지 않았다. `./scripts/run-pro-timing` 으로 다시 잰다(약 1분).

대조군이 50.5% 인 것에 주의한다. 아무것도 안 해도 절반은 50% 에 가까워진다

### 핫픽스는 이 방식으로 못 잰다 (2026-08-27)

핫픽스 라벨 44종을 붙이자 ③ 이 84.6% → 79.5% 로 내려갔다. **쪼개 보면 원인이
하나다.**

| 조정이 실린 곳 | 방향 | n | 의도대로 |
| --- | --- | ---: | ---: |
| 본절 | 너프 | 208 | **85.1%** |
| 본절 | 버프 | 326 | **75.8%** |
| **핫픽스** | 너프 | 21 | **23.8%** |
| **핫픽스** | 버프 | 24 | **41.7%** |

핫픽스 너프는 23.8% 로 찍기보다 나쁘다 — 승률이 오히려 반대로 간다.

측정 창이 조정을 못 감싸기 때문이다. ③ 은 패치 P−1 과 P 의 승률을 비교하는데,
핫픽스는 **P 한가운데**서 나간다. 그래서 P 의 승률에는 셋이 섞인다.

```
P 의 패치 변경        핫픽스가 아닌 것들
급등                 핫픽스를 부른 바로 그 일
핫픽스 보정           재려던 것
```

핫픽스는 그 패치 안에서 벌어진 급등에 대한 대응이다. P−1 → P 비교는 보정보다
급등을 더 크게 담고, 그래서 「너프했는데 승률이 올랐다」로 읽힌다.

45건(7.8%)이 이렇다. 라벨을 빼지 않는다 — 조정은 실제로 있었고 ① 과 ② 는
그것으로 좋아졌다. **③ 에서만 창이 안 맞는다는 것을 적어 둔다.**

갈리는 이유는 출발점이다. 조정 크기는 사실상 같다.

```
너프   50.85% 에서 시작   50% 까지 1.38%p 남았는데  1.44%p 움직인다  → 지나친다
버프   48.96% 에서 시작   50% 까지 1.65%p 남았는데  1.44%p 움직인다  → 못 미친다
```

「50% 에 가까워짐」을 성패로 읽지 않는다. 50% 를 정확히 맞추는 것은 가능한
작업이 아니다. 이 열이 재는 것은 **[두 지표가 어긋나는 크기](#두-지표가-어긋난다)**다.

**표본이 361 → 463 으로 늘었는데 값이 거의 안 움직였다**(너프 82.2% → 83.2%,
버프 79.1% → 78.5%). ②와 달리 ③은 **안정됐다** — 측정이지 예측이 아니라서
표본이 늘어도 흔들리지 않는다.

다섯 건 중 하나는 의도한 방향으로 안 간다.

## 직접 모은 경기로 솔랭 지표를 재현해 봤다 (2026-09-20)

u.gg 아카이브가 `16_15` 에서 끊겼다. 그래서 Riot API 로 같은 패치를 직접 모아
**우리 숫자가 u.gg 를 재현하는지** 먼저 쟀다. 판정 기준은
[ADR 0010](../adr/0010-riot-api-direct-aggregation.md) 에 **재기 전에** 적었다 —
챔피언마다 차이를 표준오차로 나눈 z 가 평균 0 · 표준편차 1 근처인가.

**견준 것**: 패치마다 u.gg 스냅샷 전 4,500판(`kr` · `euw1` · `na1` 각 1,500판)에서 셀 수
없는 경기(다른 플랫폼에서 치른 것 · 이긴 쪽이 다섯이 아닌 것)를 뺀 것. `16_15` 는 그
뒤로 3,000판을 더 모았지만 스냅샷 뒤 경기라 여기서는 안 센다. 지금 에메랄드
이상인 이용자를 단계별 인원에 비례해 뽑아 그 경기를 받았다. 두 패치 모두 u.gg 의
스냅샷 시각 전 경기만 센다.

| 패치 | 직접 집계 | u.gg | 창 |
| --- | ---: | ---: | --- |
| `16_15` | 4,487판 · 이용자 804명 (모은 것은 7,468판 · 1,078명) | 334,500판 | 출시 ~ 07-31 14:05Z |
| `16_13` | 4,479판 · 이용자 395명 | 2,254,893판 | 출시 ~ 07-06 18:34Z |

### 승률은 구분되지 않고, 픽률·밴율은 계통 차이가 남는다

| 패치 | 비율 | r | 평균 차이 | z 평균 | z 표준편차 | 계통 차이 | 판정 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| `16_15` | 승률 | 0.399 | +0.01%p | −0.01 | 1.03 | 1.01%p | **잡음 안** |
| `16_15` | 픽률 | 0.984 | 0.00%p | −0.03 | 1.50 | 0.49%p | 잡음 밖 |
| `16_15` | 밴율 | 0.990 | +0.08%p | +0.07 | 1.94 | 0.92%p | 잡음 밖 |
| `16_13` | 승률 | 0.307 | −0.15%p | −0.02 | 1.06 | 1.49%p | **잡음 안** |
| `16_13` | 픽률 | 0.983 | 0.00%p | −0.10 | 1.50 | 0.51%p | 잡음 밖 |
| `16_13` | 밴율 | 0.984 | +0.09%p | −0.08 | 2.26 | 1.29%p | 잡음 밖 |

**두 패치가 같은 말을 한다.** 승률은 둘 다 잡음 안, 픽률·밴율은 둘 다 잡음 밖이다.

**승률의 상관이 낮은 것(0.3~0.4)은 값이 어긋나서가 아니라 우리 표본이 작아서다.**
4,500판이면 챔피언당 판수가 적어 승률의 표준오차가 3%p 근처다. 챔피언 사이의 실제
승률 폭이 그만큼이라 상관이 희석된다. z 로 보면 평균 −0.02~−0.01 · 표준편차
1.03~1.06 으로, **잡음으로 설명되지 않는 차이가 안 보인다.** 다만 이것은 「같다」가
아니라 **「이 표본에서 1%p 남짓 아래는 구분 못 한다」**는 뜻이다.

**픽률·밴율은 상관이 0.98 을 넘는데도 기준을 못 넘는다.** 분모가 전체 경기라
표준오차가 작고, 그래서 작은 차이도 잡음 밖으로 나온다. 크기는 0.5~1.3%p 다.

#### 원인은 지역을 섞는 비율로 보인다

플랫폼 하나만으로 견주면 **더 나빠진다**(`16_15`).

| 무엇으로 견줬나 | 픽률 z 표준편차 | 밴율 z 표준편차 |
| --- | ---: | ---: |
| 세 지역을 같은 판수로 | **1.50** | **1.94** |
| `euw1` 만 | 1.72 | 2.61 |
| `na1` 만 | 1.97 | 3.00 |
| `kr` 만 | 2.91 | 4.61 |

지역마다 챔피언 인기가 다르고, 섞은 값이 u.gg 의 `world` 에 가장 가깝다. **u.gg 가
어떤 비율로 섞는지 모르므로 그 차이를 맞출 방법이 없다.**

### 밴을 세는 방식이 달랐다 — 견줘 보고 알았다

처음에는 밴을 **칸마다** 셌다. 그러자 밴율만 계통으로 높게 나왔다(z 평균 +0.42 ·
계통 차이 1.49%p). 세어 보니 원인이 나왔다.

```
우리 · 밴 칸 그대로        9.635개/판
우리 · 같은 챔피언 한 번    9.083종/판     ← 경기의 45.3% 에서 중복 밴이 있다
u.gg                      8.939/판
```

u.gg 는 한 경기에서 두 팀이 같은 챔피언을 밴해도 **한 번으로 센다.** 정의를 맞추니
`16_15` 밴율이 z 평균 +0.42 → **+0.07**, 계통 차이 1.49%p → **0.92%p** 로 줄었다(앞
값은 그때의 4,500판에서 잰 것).
**재고 나서 정의를 고친 것이므로 여기 적는다** — 판정 기준(z 문턱)은 안 바꿨다.

### 그래서 잇지 않는다

픽률·밴율에 계통 차이가 남으므로 **직접 집계를 솔랭 지표 뒤에 이어 붙이지
않는다**([출처를 섞지 않는다](../../CLAUDE.md#출처를-섞지-않는다)). 별도 계열로
쌓고, 예측에 쓸 때는 그 사실을 밝힌다([followups](../followups.md) 27).

### 직접 집계로 다음 패치를 예측하고 채점해 봤다 (2026-09-20)

[ADR 0012](../adr/0012-predicting-with-direct-aggregation.md) 대로 **학습은 u.gg,
대상 패치만 직접 집계**로 바꿔 돌렸다. 새 패치의 방향 라벨은 노트를 읽어 붙였다
(`16_17` 19종 · `16_18` 12종 · `save-labels` 의 자동 판정 대조로 일치 10 · 확장 2 · 충돌 0, `score-labels` 는 직전 패치 노트의 챔피언을 빼서 일치 9 — 처음 붙인 넷이 라벨 기준에 어긋나 감사 뒤 고쳤다, [ADR 0012](../adr/0012-predicting-with-direct-aggregation.md)).

| 기준 → 정답 | 대상 종수 | 그 패치 조정률 | 너프 상위 5 중 조정 | 그중 방향까지 |
| --- | ---: | ---: | ---: | ---: |
| `16_16` → `16_17` | 51종 | 19.6% | **2종** (기준선 1.0) | 1종 (Nasus) |
| `16_17` → `16_18` | 51종 | 11.8% | 0종 (기준선 0.6) | 0종 |

**이 숫자로는 아무 말도 못 한다.** 평가 지점이 둘이고, 상위 5 안의 적중이 2종과
0종이다. 기준선(1.0 · 0.6)에서 잡음만큼 떨어져 있다.

**이 표는 표본에 흔들린다.** `16_15` 표본을 늘리거나 셀 수 없는 경기를 거를 때마다
`16_16` 행의 추세 피처가 움직여 너프 상위 5 의 다섯째 자리가 바뀐다(Yasuo ↔ Lee Sin)
— **1종과 2종 사이를 오간다.** 채점 하나가 챔피언 하나에 달린 크기다.

**위 표는 셀 수 없는 경기를 거른 `16_15` 7,468판 기준이다.** 다섯째와 여섯째의
점수 차가 0.07 이라, 어느 자료로 돌렸는지를 적지 않으면 같은 표가 재현되지 않는다.
`16_15`·`16_16` 은 끝난 패치라 매일 수집이 건드리지 않는다 — 이 행은 이제 움직이지
않는다.

### 검색과 LLM 은 후보 점수에 관여하지 않는다 (2026-09-21)

코드로 확인했다. **① 대상과 ② 방향의 점수를 내는 `rank_candidates` 는 표 형식
피처 위의 부스팅 트리 하나다** — 검색기를 부르지 않는다.

| 무엇 | 어디에 쓰이나 | 후보 점수에 |
| --- | --- | --- |
| `CaseSearch` (R1 · k-NN) | arm `A5`·`A5b` · 에이전트 도구 | **안 쓴다** |
| `NoteSearch` (R2 · BM25) | 에이전트 도구 | **안 쓴다** |
| `StatLookup` (R3 · 조회) | 에이전트 도구 | **안 쓴다** |
| `rank_candidates` (부스팅 트리) | `predict` · `ask` · `run-live-predict` | 이것 하나 |

그래서 **모델을 바꾸거나 검색을 고치는 것으로는 ① 적중률이 안 움직인다.** 둘은
다른 코드 경로다. 검색은 「무엇을 근거로 보여 줄까」와 에이전트 판단에 쓰인다.

**검색 실패는 확인되지 않았다.** 2026-09-18 에 로컬 임베딩 둘을 BM25 와 견줬고
[BM25 가 크게 이겼다](../glossary.md#벡터화는-하고-있다--벡터-db-를-안-쓸-뿐이다-2026-08-28-측정); 섞어도
나빠졌다. 벡터 DB 는 문서 3,843개에 전수 비교가 빠르므로 안 만든다. **검색 방식을
더 바꿀 근거가 지금은 없다.**

### 우리 자료로 예측하면 성적이 얼마나 떨어지나 (2026-09-21 밤)

**머리 수치는 u.gg 로 만든 대상 행에서 나왔다.** 실제로 예측할 때는 직접 집계로
만든 행을 쓴다. 표본이 훨씬 작으니 성적도 달라야 하는데, 그 폭을 잰 적이 없었다.

| 대상 행의 출처 | 챔피언당 경기 | 승률 표준오차 |
| --- | ---: | ---: |
| u.gg 패널 | 중앙 50,020 | **0.22%p** |
| 직접 집계 2,979판 | 중앙 177 | 3.76%p |
| 직접 집계 9,900판 | 중앙 487 | **2.27%p** |

**열 배 넘게 차이 난다.** 그래서 u.gg 대상 행의 승률·픽률·밴율을 그 표본 크기의
이항 오차만큼 흔들고 같은 채점을 다시 돌렸다(흔들기 5회 평균 · 정답은 그대로).

| 대상 행의 표본 | ① 조정 적중 | 기준선 | 배수 | ①′ 너프 적중 | 기준선 | 배수 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| u.gg 원본 | 27.4% | 15.0% | 1.82배 | 22.9% | 3.4% | **6.71배** |
| 9,900판 수준 | 22.0% | 15.1% | 1.46배 | 15.2% | 3.4% | 4.47배 |
| 3,900판 수준 | 21.7% | 15.1% | 1.44배 | 15.6% | 3.4% | 4.58배 |
| 3,000판 수준 | 22.2% | 15.1% | 1.47배 | 15.5% | 3.4% | 4.56배 |

**두 가지가 나온다.**

첫째, **우리 예측의 기대 성적은 6.7배가 아니라 4.5배다.** 머리 수치를 직접 집계
예측에 그대로 갖다 쓰면 안 된다. 여전히 기준선의 네 배가 넘지만 다른 숫자다.

둘째, **3,000판이든 9,900판이든 성적이 같다.** 15.2 · 15.6 · 15.5%로 차이가 없다.
승률 오차가 3.8 → 2.3%p 로 줄어도 u.gg 수준(0.22%p)에는 한참 못 미친다. 거기
가려면 패치당 수십만 판이 필요하고, 하루 900판으로는 몇 년이 걸린다.

**수집을 늘려 얻는 것은 성적이 아니라 커버리지다.**

| | 3,900판 | 9,900판 |
| --- | ---: | ---: |
| 200판 넘는 챔피언 | 80종 | **167종** |
| ①′ 너프 적중 | 15.6% | 15.2% |

`16_18` 을 3,900 → 9,900판으로 늘리자 카시오페아(93 → 235판)처럼 못 보던 챔피언이
후보에 들어왔다. 맞히는 비율은 그대로여도 **놓치던 정답을 볼 수 있게 된다.**

#### 한 번 돌린 목록은 절반이 우연이다

같은 `16_18` 9,900판을 무작위로 반씩 갈라 각각 줄 세웠다. **같은 패치 · 같은 기간 ·
같은 코드**인데 순위가 이만큼 다르다.

```
Yasuo     A 반쪽 1위  →  B 반쪽 31위
Irelia    A 반쪽 4위  →  B 반쪽 49위
Talon     A 반쪽 5위  →  B 반쪽  4위
```

165종 전체의 순위 상관이 ① 조정 **+0.588** · ①′ 너프 **+0.419** 다. 앞뒤로 가른
것(0.550 · 0.366)과 거의 같으므로 **시점 차이가 아니라 잡음이다.**

그래서 자료를 3,000 → 9,900판으로 늘렸을 때 상위 5 가 바뀐 것도 잡음으로 설명된다
(`16_19` 노트가 나와야 어느 쪽이 맞는지 알 수 있다 — 세 벌을 다 굳혀 두었다).

**한 번 돌린 상위 5 를 그대로 믿으면 안 된다.** 여러 번 갈라 돌려 공통으로 올라오는
챔피언을 봐야 한다.

### 예측이 왜 안 맞나 — 절반은 평가 대상에 있지도 않다 (2026-09-21)

`diagnose-predict` 로 틀린 것을 넷으로 갈랐다. 고정 묶음 `eval-2026-09-21`
(경기 21,811 · [ADR 0013](../adr/0013-frozen-evaluation-snapshots.md))로 읽었다.

| 기준 → 정답 | 실제 조정 | 그중 평가 대상 안 | 커버리지 | 상위 5 적중 | 재현율 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `16_16` → `16_17` | 19종 | 10종 | **53%** | 2 | 2/10 |
| `16_17` → `16_18` | 12종 | 6종 | **50%** | 1 | 1/6 |

**조정된 챔피언의 절반이 200판 문턱 아래라 아예 안 보인다.** `16_17` 에서 빠진 9종은
LeBlanc 139판 · Vladimir 151 · Cho'Gath 89 · Irelia 168 · Trundle 64 · Mordekaiser 159 ·
Diana 171 · Aurelion Sol 70 · Qiyana 144 다. 맞히고 못 맞히고 이전에 **재현율의
천장이 절반**이라는 뜻이다.

#### 문턱을 올려도 상위 5 는 그대로다

| 문턱 | `16_16` 대상 | 커버리지 | 상위 5 적중 | 기준선 | 배수 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0판 | 173종 | 100% | 2 | 0.55 | **3.6배** |
| 100판 | 129종 | 84% | 2 | 0.62 | 3.2배 |
| 200판 | 51종 | 53% | 2 | 0.98 | 2.0배 |
| 300판 | 19종 | 32% | 2 | 1.58 | 1.3배 |

**적중 수가 안 움직인다.** 문턱은 후보를 걸러 내는 것이 아니라 **정답을 분모에서
빼는 일만** 한다. 기준선이 같이 올라가므로 배수는 오히려 나빠진다.

**두 지점만 보고 정하면 누출이다.** 그래서 u.gg 20패치 · 조정 516건에서 같은 것을
다시 봤다. 픽률 문턱을 0 → 12% 로 올리면 커버리지가 100% → 12% 로 떨어지는데
**상위 5 적중은 39 → 39 로 그대로**이고 배수는 2.59 → 1.56 으로 내려간다.
낮은 픽률 챔피언이 줄 세우기 어려운 것이 아니라, **문턱이 정답을 가릴 뿐이다.**

`16_16`·`16_17` 두 평가 지점은 이 진단에서 **여러 번 봤다.** 문턱을 실제로 바꾸려면
개발 구간에서 정하고 여기서 한 번만 확인해야 한다 — 이 표는 그 확인이 아니다.

#### 자료가 늘면 추세 피처 없는 챔피언이 상위로 올라온다

`16_18` 이 3,000판에서 3,900판이 되며 대상이 48 → 80 종이 됐다. **새로 들어온
32종 중 27종은 추세 피처(앞 패치 대비 승률 변화)가 비어 있다** — 앞 패치에서
문턱 아래라 견줄 행이 없어서다.

```
너프 상위 5   다섯 다 원래 있던 종 · 추세 피처 있음   → 목록이 거의 안 바뀜
버프 상위 5   Kayn · Lissandra 가 새로 들어와 1·5위   → 둘 다 추세 피처 없음
```

**신호가 약한 버프 쪽에서 피처가 빈 챔피언이 위로 뜬다.** 매일 수집이 목록을 흔든
것은 모델이 바뀌어서가 아니라 **대상이 바뀌어서**다.

`16_15` 는 더 심하다 — **145종 전부 추세 피처가 없다.** u.gg 패널이 `16_13` 에서
끝나고 직접 집계는 `16_15` 부터라 **`16_14` 가 통째로 구멍**이고, 그 구멍 위에서는
앞 패치 대비를 낼 수 없다.

#### 원인을 나눠 적는다

| 원인 | 판정 | 근거 |
| --- | --- | --- |
| 표본 문턱이 정답의 절반을 가린다 | **확인됨** | 위 두 표 · 개발 구간 20패치에서 재현 |
| 자료가 늘어 추세 피처 빈 챔피언이 상위로 온다 | **확인됨** | 새로 들어온 32종 중 27종이 빈 피처 · 버프 1·5위 |
| `16_14` 구멍으로 `16_15` 추세가 통째로 없다 | **확인됨** | 145종 중 0종 |
| 이력 사슬에 출처가 섞인다(u.gg → 직접 집계) | **정황 있음** | `16_15`~`16_17` 이 직접 집계 행이다. 효과를 따로 재지 않았다 |
| 평가 지점이 둘뿐이라 성적을 말할 수 없다 | **확인됨** | [위 표](#직접-집계로-다음-패치를-예측하고-채점해-봤다-2026-09-20) |
| 라벨 오류 | **확인 불가** | `score-labels` 충돌 0. 오류가 없다는 뜻은 아니다 |
| 개발사가 무엇을 보고 조정하는지 | **확인 불가** | 예측이 틀린 것만으로는 아무 말도 못 한다 |

**검색이나 LLM 은 여기 없다.** 후보 점수(`rank_candidates`)는 표 형식 피처 위의
부스팅 트리 하나이고 검색기를 부르지 않는다 — 아래 절에 코드로 적었다.

#### 대상이 51종뿐인 것이 지금 가장 큰 제약이다

패널은 그 패치에서 **200판 이상** 나온 챔피언만 본다. 패치당 3,000판을 모으면
챔피언당 평균 173판이라 절반 넘게 문턱 아래로 떨어진다. 매일 수집이 쌓여 패치당
1만 판을 넘으면 150종 근처가 된다.

#### `16_19` 예측은 미리 적어 둔다

현재 패치(`16_18`)로 다음 패치를 예측했다. **정답이 아직 없다.**

```
너프 후보  Yasuo · Lucian · Talon · Jayce · Sylas
버프 후보  Cho'Gath · Xerath · Qiyana · Blitzcrank · Camille
```

**이것은 2026-09-19 0시(UTC) 까지의 `16_18` 3,000판으로 낸 예측이다.** 채점도 그
자료로 한다.

```
./scripts/run-live-predict 16_18 --until 2026-09-19 --score
```

과거를 되짚는 백테스트와 달리 **정답을 본 적이 없는 예측**이다. 앞으로 패치마다
이렇게 쌓아 전향 평가로 간다.

#### 자르지 않으면 채점할 수 없다 (2026-09-21)

매일 수집이 현재 패치를 계속 불린다. `16_18` 이 3,000판에서 3,900판이 되자 같은
명령이 다른 목록을 냈다.

| | 미리 적은 것 (3,000판) | 그냥 다시 돌린 것 (3,900판) |
| --- | --- | --- |
| 대상 | 48종 | 80종 |
| 너프 상위 5 | Yasuo · **Lucian** · Talon · Jayce · Sylas | Yasuo · Jayce · **Yone** · Talon · Sylas |
| 버프 상위 5 | **Cho'Gath · Xerath · Qiyana · Blitzcrank · Camille** | **Kayn** · Cho'Gath · Qiyana · **Malphite · Lissandra** |

버프 다섯 중 셋이 바뀐다. **`--until` 없이 채점하면 아무도 미리 적지 않은 목록을
채점하게 된다** — 미리 적어 둔다는 말이 뜻을 잃는다. 그래서 자르는 기능을
`run-live-predict` 에 넣고, 미리 적는 예측에는 **자른 날짜와 판수를 같이 적는다.**
`16_16`·`16_17` 기준 채점은 끝난 패치라 자르든 안 자르든 같다.

#### 그래서 예측을 두 벌 적는다 (2026-09-21)

**미리 적은 것을 고치지 않는다.** 대신 오늘 자료로 낸 것을 **따로** 적는다. 둘 다
채점하면 「자료가 늘면 나아지는가」를 처음으로 잴 수 있다.

| | 미리 적은 것 | 낮 갱신 | 밤 갱신 |
| --- | --- | --- | --- |
| 자료 | 3,000판 | 3,900판 | **9,900판** |
| 대상 | 48종 | 80종 | **167종** |
| 너프 상위 5 | Yasuo · Lucian · Talon · Jayce · Sylas | Yasuo · Jayce · Yone · Talon · Sylas | Lee Sin · Jinx · Sylas · Yone · Lucian |
| 버프 상위 5 | Cho'Gath · Xerath · Qiyana · Blitzcrank · Camille | Kayn · Cho'Gath · Qiyana · Malphite · Lissandra | Lux · Warwick · Ornn · Diana · Alistar |
| 채점 | `--until 2026-09-19` | `--snapshot eval-2026-09-21` | `--snapshot eval-2026-09-21-night` |

밤 갱신은 `16_18` 에 6,000판을 더 받은 것이다. **기간이 뒤로 쏠렸다** — 09-18 이후가
70% 다(앞 일주일은 하루 345~480판, 뒤 나흘은 1,876~2,569판). `16_15` 가 앞으로
쏠린 것의 거울상이라 그대로 적어 둔다.

**어느 쪽이 맞을지 지금은 모른다.** 새로 들어온 32종 중 27종이 추세 피처 없이
들어왔고(위 절), 그중 둘이 버프 상위 5 에 있다. 표본이 늘어 좋아진 것인지 피처가
빈 챔피언이 떠오른 것인지는 **`16_19` 노트가 나와야 갈린다.**

### 주요 아이템이 바뀐 챔피언의 승률은 움직였나 — **이 표본으로는 못 본다** (2026-09-20)

[ADR 0011](../adr/0011-champion-item-usage.md) 의 경고가 값을 하는지 보려고,
앞 패치의 주요 아이템이 이번 패치에 바뀐 챔피언과 그 외의 **승률 변화**를 견줬다
(`run-item-effect`). 두 패치 다 100판 넘는 챔피언만이고, 챔피언을 재표본하는
부트스트랩 20,000회로 구간을 냈다.

#### 첫 판은 −1%p 였고, 검토가 그것을 무너뜨렸다

첫 판은 「바뀐 챔피언 20종 −1.37%p · 그 외 110종 −0.36%p · 차이 −1.01%p
[−3.28, +1.24]」였다. 독립 재계산 둘이 숫자를 그대로 재현했다. 그런데 같은
검토가 설계에서 넷을 잡았고, 전부 결과를 바꾸는 것이었다.

| 걸린 것 | 크기 |
| --- | --- |
| **`16_15` 표본이 처음 2.5일에 60% 몰려 있다** (u.gg 비교 창을 먼저 채웠다). 아이템 변경이 없는 **같은 패치 안**에서 앞 반 → 뒤 반을 견주니 차이가 **−1.09%p** — 첫 판 방식이 지금 자료에서 내는 −1.06%p 와 같은 크기다 | 첫 판의 차이 전부 |
| 「바뀌었다」에 방향이 없었다 — 20종 중 **17종은 아이템이 세진** 쪽이었다 | 무리 평균이 뜻을 잃는다 |
| 그 패치에 **직접 조정된** 챔피언이 섞여 있었다 — Smolder(−10.2%p) 하나가 무리 평균의 1/3 | 4/20 · 28/109 |
| 챔피언당 100~500판이라 승률 변화의 표준오차가 4~5%p 다 | 3~5%p 아래는 못 가른다 |

#### 고친 측정

날짜마다 같은 무게를 주고(**날짜 균등**), 그 패치에 직접 조정된 챔피언을 빼고,
아이템이 세진 쪽과 약해진 쪽을 따로 낸다. 옆에 **가를 수 있는 최소 차이**(80%
검정력 · 양측 5%)를 적는다.

| 구간 | 무리 | 승률 변화 | 그 외 | 차이 · 95% | 가를 수 있는 최소 차이 |
| --- | --- | ---: | ---: | --- | ---: |
| `16_15` → `16_16` | 아이템이 세진 13종 | −0.10%p | −0.07%p (81종) | −0.03 [−3.08, +3.17] | 4.4%p |
| `16_15` → `16_16` | 아이템이 약해진 3종 | −7.03%p | −0.07%p | −6.97 [−14.69, +0.54] | 10.3%p |
| `16_16` → `16_17` | 아이템이 약해진 9종 | +0.74%p | +0.57%p (94종) | +0.17 [−3.16, +3.36] | 5.3%p |
| `16_17` → `16_18` | 아이템 값 변경 없음 | — | — | — | — |

**고친 방식은 위약을 통과한다 (2026-09-21).** 아이템이 안 바뀐 같은 패치 안에서 앞
반 → 뒤 반을 같은 방식으로 견주면 `16_15` 에서 **−0.02%p** 다. 첫 판 방식으로 같은
것을 재면 −1.09%p 가 나온다. **날짜 균등과 직접 조정 제외가 그 가짜 −1%p 를
없앤다**는 뜻이고, 이제 스크립트가 두 위약을 나란히 낸다.

**구간보다 오른쪽 칸을 봐야 한다.** 무리가 열 종 안팎이면 챔피언을 재표본하는
부트스트랩이 **우연히 모인 몇 값의 퍼짐**을 재게 돼 구간이 좁게 나온다. `16_16` →
`16_17` 의 9종이 그렇다 — 부트스트랩 구간은 ±3.3%p 인데 판수에서 나오는 이항
표준오차로 내면 ±3.7%p 다. 그래서 **결론은 좁은 쪽이 아니라 「가를 수 있는 최소
차이」로 낸다.** 챔피언마다 판수가 다른데 무리 평균은 똑같이 세는 것도 같은 이유로
적어 둔다(104판짜리와 1,000판짜리가 한 표씩이다). **무리가 15종 미만이면 스크립트가
해석적 구간을 같이 내고, 부트스트랩 쪽이 더 좁으면 그렇다고 적는다.**

**아무것도 못 본다.** 세진 13종은 차이가 0 이고, 약해진 3종은 −7%p 로 보이지만 **세
종으로 낸 구간은 0 을 지나고 믿을 것도 못 된다**(가를 수 있는 최소 차이 10.3%p 가
관측 7.0%p 보다 크다). 아이템 하나가 낼 법한 차이(1%p 아래)는 이 표본이 가를 수 있는
것(4~5%p)보다 훨씬 작다 — **「구분 안 된다」는 가설과 무관하게
나오는 결과다.**

#### 다음 패치에 조정됐나

| 구간 | 아이템 바뀐 쪽 | 그 외 | 무작위라면 바뀐 쪽이 0 이하일 확률 |
| --- | ---: | ---: | ---: |
| `16_16` → `16_17` 조정 | 0/20 | 16/109 | 0.056 |
| `16_17` → `16_18` 조정 | 0/9 | 9/110 | 0.480 |

방향은 「경고가 조정을 예고한다」의 **반대**이고, 유의하지도 않다. 두 구간의 9종은
겹치므로 합치지 않는다.

#### 그래서

아이템 사용률은 **경고와 설명**으로만 쓴다. 예측을 낫게 한다는 증거는 없고, 이
표본으로는 그 질문에 답할 수 없다. 답하려면 패치당 표본이 열 배는 필요하고,
수집을 **패치 전 기간에 고르게** 해야 한다 — `16_15` 처럼 한쪽에 몰린 표본은 그
자체가 결과를 만든다. 매일 수집이 그 조건을 만든다.

수집의 다른 한계도 여기 적는다. 한 패치는 **이용자 256~509명**에서 왔고(이용자당 최대
20판), 그래서 **한 챔피언의 경기가 몇 사람에게 쏠린다** — `16_16` 의 Ornn 은 123판
중 20판이 한 이용자다(최대 16%). 구간은 챔피언을 재표본할 뿐 이용자를 재표본하지 않는다.
**이용자를 군집으로 놓고 다시 재 봤다** — 세진 13종 행의 가를 수 있는 최소 차이가
4.4 → **3.6%p** 로, 커지지 않는다. 같은 사람의 경기라고 해서 승패가 특별히 같이
가지는 않는다는 뜻이고, 이 쏠림은 결론을 바꾸지 않는다. `16_18` 은 출시일(2026-09-10)을 빼고 쌓인다. **이 절의 수치는 2026-09-20
기준이고 `16_18` 이 3,000판이던 때의 것이다** — 매일 수집이 그 뒤로 900판을 더해
3,900판 · 10일이 됐다. 아이템 값이 안 바뀐 패치라 위 표의 결론에는 영향이 없다.

## 어디까지 되고 어디부터 안 되나

증명 대상 4번 — **이것이 가장 정직한 결과다.**

| 단계 | 질문 | 성적 | 판정 |
| --- | --- | --- | --- |
| 1 · 대상 | 누가 | 기준선의 **1.8배** (너프로 좁히면 **6.5배**) | **약하다.** 좁히면 나아진다 |
| 2 · 방향 | 너프냐 버프냐 | AUC 0.856 (기준선 0.796) | **된다** |
| 3 · 항목 | 무엇을 | — | **아직 안 함** |
| 4 · 폭 | 얼마나 | — | **아직 안 함** |

그리고 방향 안에서도 갈린다.

```
nerf · buff 만              정확도 69.6%   (기준선 50.0%)
+ mixed                          49.4%          33.3%
+ mixed + adjust                 37.2%          25.0%
```

`mixed` 는 24건 중 1건만 맞힌다 — 현재 통계로 사실상 예측되지 않는다. 조정된 챔피언의 15%가 여기 속한다.

### 모집단 넷 중 둘만 본다

[개발사가 공개한 기준](#개발사가-공개한-기준-2026-09-01)에서 문턱보다 중요한 것은
**모집단이 넷**이라는 점이다.

| 개발사가 보는 것 | 우리가 가진 것 |
| --- | --- |
| Average (상위 10% 밖) | **시계열이 안 된다** — `gold` 5패치뿐 |
| Skilled (상위 10%) | u.gg `emerald_plus` — 대략 여기 |
| Elite (상위 0.5%) | **시계열이 안 된다** — `master_plus` 5패치뿐 |
| 프로 (상위 5리그) | Oracle's Elixir 프로 픽·밴 |

**그 둘도 정확히 겹치지는 않는다.** `emerald_plus` 는 Skilled(상위 10%)의
근사이고, 우리 프로 경기는 「상위 5리그」가 아니라 리그 정규시즌이 대부분이다.

「어느 한 모집단에서라도 넘으면 세다」가 [공개 밸런스 기준](../glossary.md)의
판정 방식이므로, **우리가 못 보는 두 모집단에서 넘어 조정된 챔피언은 우리 입력에
근거가 아예 없다.**

Elite 는 승률조차 안 쓰고 밴율 45% 로 판정한다. `emerald_plus` 에서 그 선을 넘는
15행은 **갓 나온 챔피언의 밴 물결이 많다**(Naafiri `15_6` 62.5% · Mel `15_4`
60.9% · Ambessa `14_23` 57.5% · Briar · Smolder). **전부는 아니다** —
Karthus `14_11` · Draven `14_8` · Blitzcrank `13_21` 처럼 오래된 챔피언도 섞여
있다. **같은 숫자를 다른 모집단에서 재면 다른 것을 가리킨다.**

**아카이브에 다른 모집단이 있기는 하다.** 다만 우리 74패치 구간에는
`emerald_plus` 53패치를 빼면 전부 5패치 이하다
([티어 실측](../spec/data-sources.md#우리-구간13_14--16_15의-티어-2026-09-01)).
[중국 솔랭](../spec/data-sources.md#중국-솔랭은-제외한다--그리고-결과에-명시한다)과
같은 종류의 한계이고 같은 방식으로 다룬다 — 못 채우므로 적어서 낸다.

**그럴듯한 설명이 하나 생겼다. 재지는 않았다.** 모집단이 빠진 것과
[천장 47.1%](#천장을-쟀다-2026-08-28--274-에서-471-사이가-남은-전부다) 사이의
간격이 이어지는지는 확인할 방법이 없다 — 다른 모집단 자료가 5패치 이하이고,
실제로 받아 보려다 [봇 차단](../spec/data-sources.md#7-막힌-것과-이유)에 걸렸다.
문턱 자체도 2020년 문서이고 지금도 그대로인지 모른다.

### 아이템으로 이뤄진 조정을 놓친다

Lucian–Nami 가 그랬다.

방향 라벨은 [`champion_changes`](../../src/lol_balance/patchnotes.py)가 노트의
`data-champion` 속성으로 뽑은 **챔피언 블록**에서 나온다. 노트에는 그 밖에
`Items` · `Runes` · `Summoner Spells` · `Monsters` 절이 있고 **어느 것도 안 읽는다.**

실제로 놓친 사례가 있다. 프로 경기의 Lucian–Nami 조합 출전 비율이다.

```
14_8   19.2%
14_9   24.0%   ← 정점 (70경기)
14_10   6.0%   ← 4분의 1로 무너졌다
14_11   3.9%
```

그런데 `14_10` 노트에 Lucian 도 Nami 도 없다. 우리 라벨은 두 챔피언 모두
「조정 안 됨」이다. 무너뜨린 것은 `Items` 절에 있었다.

```
B. F. Sword — Now builds into Essence Reaver and The Collector.
              No longer builds into Navori Quickblades and Terminus.
```

Navori Quickblades 와 Essence Reaver 는 Lucian 의 핵심 아이템이다.
빌드 경로가 갈아엎혔고 조합이 무너졌는데, 정답지에는 아무 일도 없다.

Corki–Nami 도 같은 모양이다 — `16_6` 에 16.9% 로 정점을 찍고 내려온다.

#### 절반은 이제 본다 (2026-08-27)

아이템이 언제 어떻게 바뀌었는지는 Data Dragon `item.json` 으로 잡힌다.
챔피언과 같은 CDN 이라 새 출처가 아니고 키도 필요 없다. 협곡에서 살 수 있는
아이템만 세면 완성템 변경이 이렇다.

```
중앙값  1종        90% 분위  8종  ← 경고 문턱
14_19  75종      14_1  65종      14_10  30종
```

`14_10` 이 73패치 중 3위다. `Essence Reaver` 의 골드가 2900 에서 3200 으로 오른
것이 그 안에 있다.

경고는 패치 단위로 붙인다. 챔피언마다 띄우면 그 패치의 후보 목록 전체에
붙어 「항상 뜨는 경고」가 된다. `predict` 는 머리말에 한 번 내고, `run-effect` 는
**③ 의 16% 가 그런 패치에서 왔다**고 같이 적는다.

**예측 피처로도 대 봤고 안 올랐다** — [데이터 쪽을 밀어 봤다](#데이터-쪽을-밀어-봤다--아홉-갈래--93회-측정-걸린-것-2건--채택-0-2026-09-01)의
「아이템 격변」. 이 신호는 경고로만 값을 한다.

#### 나머지 절반은 왜 안 넣는가

「Navori 너프」가 누구의 너프인지는 규칙으로 안 잡힌다. 그 아이템을 누가
쓰는지를 알아야 정해지고, 그러려면 **챔피언별 아이템 빌드 데이터**가 필요하다.

u.gg 에 `overview` 엔드포인트가 있고 아카이브에도 남아 있지만 **커버리지가
13.3% 이고 52패치 중 50% 를 넘는 것이 2개뿐**이다. 조사 내역은
[followups 13](../followups.md#챔피언별-구매율--조사했고-못-쓴다).

#### 나머지 절반도 `16_15` 뒤로는 본다 (2026-09-21)

직접 집계가 챔피언별 아이템 사용률을 세므로([ADR 0011](../adr/0011-champion-item-usage.md))
「Navori 너프가 누구의 너프인지」는 `16_15` 뒤 패치에서 답이 나온다 — 경고가 챔피언
단위가 됐다. **그래도 라벨에는 안 넣는다.** 주요 아이템이 바뀐 챔피언의 승률이
움직였는지 재 봤더니 [이 표본으로는 못 본다](#주요-아이템이-바뀐-챔피언의-승률은-움직였나--이-표본으로는-못-본다-2026-09-20).
소급은 여전히 안 된다 — 위의 u.gg 이야기는 `16_15` 까지 그대로다.

#### 무엇을 못 재게 되나

「조합이 세면 그 조합을 겨냥해 너프한다」를 확인할 수 없다. 조합을 깨는 실제
수단이 아이템인 경우가 많은데 그것이 라벨 밖이라, 「조합 → 너프」의 연결이
애초에 안 보인다.

프로 경기로 조합을 뽑아 재 보면 이렇다.

| 신호 | AUC |
| --- | ---: |
| 개인 프로 픽·밴율 | **0.796** |
| 최다 조합 출전 비율 | 0.740 |
| 회귀에 조합을 더하면 | 0.893 → **0.888** |

**조합 출전 비율 상위 20 중 17건이 너프**이고 `14_14` 의 Ezreal–Leona 는 둘 다
너프됐다. **현상은 보이는데 개인 프로 픽·밴율(상관 0.729)과 갈라내지 못한다.**
표본도 얇다 — 바텀 + 방향 라벨이 171행, 평가 구간은 73행이다.

### 「LLM arm」이 무슨 뜻인가 — 오해하기 쉽다

`A4` · `B4` 가 「LLM」으로 표시돼 있지만 **실행할 때 API 를 부르지 않는다.**

| | |
| --- | --- |
| 규칙 12개 | **대화 중 Claude 가 학습 구간을 읽고 제안**했고 `rules/proposed.jsonl` 에 텍스트로 있다 |
| 방향 라벨 1,630종 (52패치 1,599 + `16_17`·`16_18` 31) | **대화 중 Claude 가 패치 노트를 읽고** 붙였다 |
| 실행 시점 | 그 텍스트를 읽어 **채점만** 한다 |

`ANTHROPIC_API_KEY` 를 쓴 적이 한 번도 없다. 그런데 **그것이 결함이 아니다.**

세 과제에 들어가는 산출물은 **둘 다 완성됐다** — 방향 라벨 100%, 규칙 12개.
둘 다 대화 안에서 만들어 저장소에 텍스트로 두었고, 실행할 때는 그 텍스트를

한때 「수치 기록 6,092건을 API 로 뽑아야 한다」고 적어 뒀다. 필요 없다.
그 기록은 세 과제 어디에도 안 들어간다 — `arms.py` 는 `panel` · `baseline` ·
`retrieval` · `rules` 만 읽는다. 근거는 [ground_truth/README](../../ground_truth/README.md).

한때 「정말로 API 키가 있어야 하는 것은 하나뿐이다 — 에이전트다」라고 적었다.
**틀렸다 (2026-09-18).** 조회→검색→판단 루프에 자동 호출은 필요했지만 키는 필요
없었다 — 로컬 모델(Ollama)로 돌았다([ADR 0009](../adr/0009-agent-framework-and-local-model.md)).
에이전트(`B8`)는 실행할 때 로컬 모델을 부르는 **유일한 arm** 이고, 그 판단도
텍스트로 저장해 채점은 모델 없이 한다(`score-agent`).

증명 5번의 LLM·RAG 부분은 답이 나왔다 — `B4` 규칙은 회귀와 동률이고 `B6`
판단은 다수결을 못 넘는다. 한때 **그래서 루프까지 가지 않고 여기서 끊었다.**
루프도 만들었고, 같은 이웃을 주고도 다수결에 졌다([`B8`](#같은-이웃으로-다시-쟀다--에이전트-b8-2026-09-18)).

검색기 셋(R1·R2·R3)이 다 쓰인다 — [`retrieval.py`](../../src/lol_balance/retrieval.py).
`R3`(수치 조회)는 오래 호출하는 arm 이 없었다. **에이전트가 조회하려고 만든
도구**라 단발 판단 구조에는 자리가 없었고, 에이전트가 생기고서야 불렸다.

## 이 문서가 말하지 않는 것

- ❌ 우리가 라이엇보다 밸런스를 잘 잡는다
- ❌ 예측이 정확하다 — **정확도는 측정 대상이지 전제가 아니다**
- ❌ 라이엇의 내부 프로세스가 이렇다 — **관측된 패턴**일 뿐이다
- ❌ 조정이 옳았다·틀렸다 — 효과를 **측정**하는 것이지 판정이 아니다
