# 지금까지 보인 것

**공개 데이터만으로 라이엇의 밸런스 조정을 얼마나 설명할 수 있는가.** 2026-08-25 기준 결과다.

숫자는 전부 [`run-report`](../../scripts/run-report)가 낸 것이고 `runs/` 에 남는다. 시드 `20260824` · 시간순 분할 `15_13` 앞뒤.

## 한 줄

**「어느 쪽으로 조정할까」는 잘 맞고, 「누구를 조정할까」는 잘 안 맞는다.**

```
② 방향  너프냐 버프냐    AUC 0.866 (기준선 0.799)      ← 규칙으로 잡힌다
① 대상  누가 조정되나    R-정확도 25.8% (기준선 14.5%)  ← 잘 안 잡힌다
③ 효과  조정이 먹혔나    의도대로 84.6% · 균형 접근 54.8% (대조군 50.4%)
```

**본선은 솔랭 지표만 쓴다.** 이 프로젝트의 질문이 **「패치가 솔랭 지표에 어떤
영향을 주는가, 그리고 지금 승률로 다음 패치를 예측할 수 있는가」**여서다. 프로
경기 데이터를 쓰는 arm 은 [확장](#확장--솔랭-지표가-못-보는-것)에 따로 뒀다.

### 세 번 밀어 봤고 세 번 다 안 움직였다

**모델을 바꿔도, 겹치지 않는 새 신호를 넣어도 25% 대에서 안 움직인다.**

| 시도 | 전 | 후 |
| --- | ---: | ---: |
| **부스팅 트리** (표 데이터의 표준 강자) | 25.6% | **25.8%** |
| **이력·역할 피처** (최근 조정 횟수 등) | 25.8% | **25.6%** |
| **프로 경기 피처** (② 에서는 +0.046) | 25.5% | **24.7%** |

**세 번째가 특히 말해 준다.** 프로 경기 피처는 ② 방향에서 회귀를 +0.046 올린
신호다. 승률과 상관이 0.06 밖에 안 되는 **진짜 새 정보**인데, ① 에서는
**AUC 0.596 → 0.597** 로 그대로다.

이력 피처는 **신호가 분명히 있었다** — 최근 5패치 조정 횟수가 늘수록 다음 패치 조정률이 16.4% → 33.3% 로 단조 증가하고, 기존 피처와 상관도 낮다(`pick_rate` +0.149 · `ban_rate` +0.190).

**그런데 패치 안에서는 못 가른다**(AUC 0.530). 「이 챔피언이 자주 손대는 축인가」를 말하지 「이번 패치에 손댈까」를 말하지 않기 때문이다. 순열 중요도로 봐도 부스팅이 쓰는 것은 `ban_rate`(+3.73%)와 `win_rate`(+2.90%)이고 이력·역할 9개 열의 기여는 **−0.93%** 다. 자세한 것은 [prediction-signals](../spec/prediction-signals.md).

**그래서 「모델이 부족해서」도 「피처가 부족해서」도 아니다.** 공개 신호로 「누가 조정될지」는 여기가 한계다.

하이퍼파라미터는 **학습 구간 안에서 시간순 3겹 교차검증으로** 골랐다. 평가 구간을 보고 고르면 그것이 곧 누출이다.

**승률 순(A0c)이 무작위보다 나쁘다**(AUC 0.451). 조정되는 쪽이 양 끝이라 단조롭지 않다. 거리로 바꾸면(A0d) 0.567 로 뒤집힌다.

## 확장 — 솔랭 지표가 못 보는 것

**본선 밖이다.** 이 프로젝트의 질문은 「**지금 솔랭 지표로** 다음 패치를 예측할 수
있는가」이고 프로 경기는 거기 안 들어간다. **그런데 빼고 나면 남는 오차가 어디에
몰려 있는지가 보이고, 그것을 재려고 따로 둔다.**

Oracle's Elixir 프로 경기 픽·밴(**29,977경기 · 72패치**). 패널 커버리지 98.1%,
**평가 구간은 100%** 라 비교 자체는 공정하다 — 결측 때문에 뺀 것이 아니다.

| arm | 방법 | AUC | 정확도 | 본선 대비 |
| --- | --- | ---: | ---: | ---: |
| B1p | 로지스틱 회귀 — 수준 + 프로 | 0.879 | 80.3% | B1 **+0.046** |
| B2p | 로지스틱 회귀 — 수준 + 추세 + 프로 | 0.880 | **82.1%** | B2 **+0.045** |
| **B5p** | **사례 검색 — + 프로 · 거리가중** | **0.901** | 74.4% | B5 **+0.035** |
| A2p | **① 대상** — 로지스틱 회귀 + 프로 | 0.597 | — | A2 **+0.001** |

**② 에서는 듣고 ① 에서는 안 듣는다.** 프로 팀이 밴으로 「이게 세다」를 표시하지만
라이엇이 **누구를 건드릴지**는 그것으로 안 갈린다. `A2p` 를 ① 본선 표에 남겨 둔
이유가 이것이다 — **「겹치지 않는 신호를 더해도 안 오른다」가 ① 의 결론(데이터
한계)을 강화한다.**

### 어디서 갈리는가 — **승률 50% 미만인데 너프당한 65종**

솔랭만 보면 전부 「약하니 버프」로 읽어야 하는 구간이다.

| | n | 프로 존재감 평균 |
| --- | ---: | ---: |
| 그런데 **너프당했다** | 65 | **0.366** |
| 버프받았다 | 292 | 0.080 |

**4.6배다.** 이 구간에서는 프로 존재감이 승률보다 잘 가른다(AUC 0.771 vs 0.675).

```
Ryze   16_2   승률 0.483  솔랭밴 3.4%  프로밴 23.6%  프로픽 33.3%  → 너프
Jayce  16_13  승률 0.487  솔랭밴 6.9%  프로밴 42.2%               → 너프
Jinx   15_18  승률 0.509  솔랭밴 1.6%  프로밴  1.1%               → 버프
```

**승률과 상관이 0.06~0.10 밖에 안 된다.** 프로 밴율 단독 AUC 는 0.698 로 승률
(0.804)보다 **약한데도** 보태면 오르는 이유가 이것이다 — **더 센 신호가 아니라
다른 신호다.**

### 기전은 확정하지 못했다

후보 셋 중 둘을 지웠고 하나가 안 풀렸다. **「라이엇이 대회를 본다」로는 적지
않는다** — 이 데이터로 알 수 있는 것이 아니다. 검정 내역과 되돌린 판단은
[followups 10번](../followups.md)에 있다.

### 계기판이 둘이다

**솔랭 승률과 대회 존재감은 상관이 0.06~0.10 밖에 안 된다.** 서로 다른 것을 재고
있고, **조정 한 번이 양쪽에 닿는데 챔피언마다 배분이 다르다.**

「프로형」은 평생 평균 대회 존재감 상위 25%(0.182 이상)를 말한다.

**버프 — 솔랭에는 똑같이, 대회에는 다르게 닿는다.**

| | n | 솔랭 승률 | **대회 존재감** |
| --- | ---: | ---: | ---: |
| 프로형 | 83 | +0.85%p | **+35.0%** |
| 그 외 | 244 | +0.92%p | **−0.5%** |

**솔랭 계기판만 보면 이 차이가 안 보인다.** 같은 크기로 올려 줬는데 한쪽만 대회에서 뛴다.

**그리고 되돌리기가 비싸다.**

| | n | **대회 존재감** |
| --- | ---: | ---: |
| 프로형을 너프 | 60 | **−14.6%** |
| 그 외를 너프 | 153 | **−23.1%** |

**비율로는 프로형이 덜 빠진다. 들어오기는 쉽고 나가기는 어렵다.**

**평균회귀로는 설명이 안 된다.** 프로형은 존재감이 튄 패치에 너프당하므로 자기
범위 꼭대기에 있고, 평균회귀라면 **더** 떨어져야 한다. 반대로 나왔다.

**절대값으로 보면 방향이 다르다.** 처음에 「너프도 프로형이 5배 빠진다」고 적었는데
**착시였다** — 프로형은 조정 전 존재감이 0.551 로 높아 절대 변화가 클 수밖에 없다.

```
             조정 전 존재감   절대 변화    상대 변화
버프 프로형        0.192      +0.0779    +35.0%   ← 버프 쪽은 상대로도 유지된다
버프 그 외         0.042      +0.0151     −0.5%
너프 프로형        0.551      −0.1062    −14.6%   ← 너프 쪽은 주장을 철회한다
너프 그 외         0.119      −0.0191    −23.1%
```

**반대로 대회 계기판만 보면 솔랭이 상한다.**

| 너프 후 | 프로발 | 솔랭발 |
| --- | ---: | ---: |
| 승률 48% 미만 | **20%** | 4% |
| 승률 49% 미만 | **44%** | 14% |
| 이미 50% 아래인데 너프했다 | **35%** | 16% |

**50% 를 정확히 맞추는 것은 가능한 작업이 아니다.** 그러므로 50% 아래로 내려간 것
자체를 실패로 적지 않는다. **적는 것은 두 계기판이 어긋나는 방향과 크기다.**

#### 이것은 일부에서만 일어난다

패치 30개 이상 나온 167종을 넷으로 가르면 이렇다.

| | 프로형 | 비프로형 | 계 |
| --- | ---: | ---: | ---: |
| **승률 낮음** (평생 평균 <49.5%) | **18** | **20** | 38 |
| 승률 보통 이상 | 24 | 105 | 129 |

**승률 낮은 38종의 절반은 대회와 무관하게 약하다.**

```
프로 제약형 18종   Azir 0.42   K'Sante 0.43   Varus 0.52   Vi 0.44   Ezreal 0.30
그냥 약함  20종   Yuumi 0.01  Shyvana 0.01   Zed 0.02     Yasuo 0.03  Smolder 0.09
```

**어렵다고 프로형인 것도 아니다** — Yasuo·Zed 는 어렵기로 유명한데 대회 존재감이
0.03·0.02 다. **반대쪽도 있다** — 프로형 42종 중 24종은 승률이 보통 이상이다.

**전체의 11%(18/167)에서만 두 조건이 겹친다.** 그리고 겹치는 챔피언이라도
[고정 목록으로는 안 갈린다](#기전은-확정하지-못했다) — 챔피언 고유분 AUC 0.548 ·
패치 변동분 0.764. **챔피언이 아니라 상황이고, 그 상황이 자주 오지도 않는다.**

### 되돌린 판단 — **거리가중의 기여는 0 이었다**

처음에 「프로 피처 + 거리가중으로 0.866 → 0.901」이라고 적었다. 쪼개 보니
**거리가중은 아무것도 안 했다.**

```
솔랭4 · k=25 · 다수결   0.866   ← 본선
솔랭4 · k=50 · 거리가중  0.860   거리가중만 켜면 오히려 내려간다
프로+ · k=25 · 다수결   0.900   프로 피처만으로 거의 전부
```

점수 종류가 25 → 206 으로 는 것은 사실이지만 **그것이 AUC 를 올린 게 아니다.**
규칙(B4)에서 해상도 진단이 통한 것을 보고 RAG 도 같은 원인이라 단정했다.

피처·이웃 수·가중 방식은 **학습 구간 3겹 시간순 교차검증으로** 골랐다. 솔랭
지표만으로 다시 고르면 `기본4 · k=50 · 거리가중`(CV 0.891)이 뽑히는데, 평가
구간에서는 0.860 으로 본선 `B5`(0.866)를 못 넘는다.

## ③ 효과 — 조정이 먹혔나

인접 패치 쌍 42개. 조정 안 된 챔피언을 대조군으로 빼고 잰다.

| | n | 대조군 뺀 뒤 | 의도대로 | **50% 에 가까워짐** |
| --- | ---: | ---: | ---: | ---: |
| 너프 | 221 | −1.136%p | **84.6%** | 54.8% |
| 버프 | 345 | +0.962%p | **75.1%** | **64.3%** |
| 조정 안 함 (대조군) | 5,791 | — | — | 50.4% |

**두 열이 다른 말을 한다.** 「의도대로」로 보면 너프가 낫고(84.6% > 75.1%),
「50% 에 가까워짐」으로 보면 버프가 3배 낫다(대조군 대비 **+14.0%p vs +4.4%p**).

**대조군이 50.4% 인 것에 주의한다.** 아무것도 안 해도 절반은 50% 에 가까워진다
— 이번에 높게 나온 챔피언은 다음에 내려오기 때문이다.

**갈리는 이유는 출발점이다.** 조정 크기는 사실상 같다.

```
너프   50.85% 에서 시작   50% 까지 1.38%p 남았는데  1.43%p 움직인다  → 지나친다
버프   48.96% 에서 시작   50% 까지 1.65%p 남았는데  1.41%p 움직인다  → 못 미친다
```

**「50% 에 가까워짐」을 성패로 읽지 않는다.** 50% 를 정확히 맞추는 것은 가능한
작업이 아니다. 이 열이 재는 것은 **[두 계기판이 어긋나는 크기](#계기판이-둘이다)**다.

**표본이 361 → 463 으로 늘었는데 값이 거의 안 움직였다**(너프 82.2% → 83.2%,
버프 79.1% → 78.5%). ②와 달리 ③은 **안정됐다** — 측정이지 예측이 아니라서
표본이 늘어도 흔들리지 않는다.

**다섯 건 중 하나는 의도한 방향으로 안 간다.**

## 어디까지 되고 어디부터 안 되나

증명 대상 4번 — **이것이 가장 정직한 결과다.**

| 단계 | 질문 | 성적 | 판정 |
| --- | --- | --- | --- |
| 1 · 대상 | 누가 | R-정확도 25.8% (기준선 14.5%) | **약하다 — 한계로 보인다** |
| 2 · 방향 | 너프냐 버프냐 | AUC 0.866 (기준선 0.799) | **된다** |
| 3 · 항목 | 무엇을 | — | **아직 안 함** |
| 4 · 폭 | 얼마나 | — | **아직 안 함** |

그리고 방향 안에서도 갈린다.

```
nerf · buff 만              정확도 69.6%   (기준선 50.0%)
+ mixed                          49.4%          33.3%
+ mixed + adjust                 37.2%          25.0%
```

**`mixed` 는 24건 중 1건만 맞힌다** — 현재 통계로 사실상 예측되지 않는다. 조정된 챔피언의 15%가 여기 속한다.

### 「LLM arm」이 무슨 뜻인가 — 오해하기 쉽다

`A4` · `B4` 가 「LLM」으로 표시돼 있지만 **실행할 때 API 를 부르지 않는다.**

| | |
| --- | --- |
| 규칙 12개 | **대화 중 Claude 가 학습 구간을 읽고 제안**했고 `rules/proposed.jsonl` 에 텍스트로 있다 |
| 방향 라벨 1,555종 | **대화 중 Claude 가 패치 노트를 읽고** 붙였다 |
| 실행 시점 | 그 텍스트를 읽어 **채점만** 한다 |

**`ANTHROPIC_API_KEY` 를 쓴 적이 한 번도 없다.** 그런데 **그것이 결함이 아니다.**

세 과제에 들어가는 산출물은 **둘 다 완성됐다** — 방향 라벨 99.6%, 규칙 12개.
둘 다 대화 안에서 만들어 저장소에 텍스트로 두었고, 실행할 때는 그 텍스트를
읽기만 한다.

**한때 「수치 기록 6,092건을 API 로 뽑아야 한다」고 적어 뒀다. 필요 없다.**
그 기록은 세 과제 어디에도 안 들어간다 — `arms.py` 는 `panel` · `baseline` ·
`retrieval` · `rules` 만 읽는다. 근거는 [ground_truth/README](../../ground_truth/README.md).

**정말로 API 키가 있어야 하는 것은 하나뿐이다 — 에이전트(A5·A6).** 조회→검색→
판단 루프는 자동 호출 없이 만들 수 없다. **증명 5번은 그래서 아직 답이 없다.**

**검색기 셋(R1·R2·R3)은 만들어졌다** — [`retrieval.py`](../../src/lol_balance/retrieval.py). 에이전트가 쥘 도구이고, 검색만이라 API 키가 필요 없다. 다만 **그것을 쥐고 판단하는 루프가 아직 없다.**
