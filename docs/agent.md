# 에이전트 — arm `B8`

조회→검색→판단 루프를 **모델이 스스로 돈다.** 검색기 셋(R1·R2·R3)을 도구로 쥐고,
무엇을 찾아볼지 모델이 고른다.

LangChain 으로 만들고 **로컬 모델(Ollama)로 돌린다 — API 키가 필요 없다.**
왜 이렇게 정했는지는 [ADR 0009](adr/0009-agent-framework-and-local-model.md)에 있다.

**판단은 다수결을 못 이겼다.** `B5` 와 같은 이웃 25종을 주고 판단만 맡겼는데 졌다
([results](results/README.md#같은-이웃으로-다시-쟀다--에이전트-b8-2026-09-18)).
그래서 화면에서는 판단이 아니라 **해설**을 맡긴다.

## 쓰는 법

```bash
ollama pull qwen3.5:9b && ollama serve   # 한 번. 약 6.6 GB
./scripts/app                            # 화면 → http://127.0.0.1:7861
./scripts/ask-agent Senna 16_13          # 한 챔피언을 맡기고 도구 호출을 본다
./scripts/score-agent                    # 저장한 판단 기록을 채점만 한다 (몇 초)
./scripts/run-agent                      # 하네스 검증 — 규칙이 B5s 를 재현해야 한다
./scripts/score-qa                       # 후속 질문의 고정 질문 답을 다시 대조한다 (모델 없이)
```

기본 모델은 `ollama:qwen3.5:9b` 다. `.env` 의 `LOL_BALANCE_AGENT_MODEL` 로 바꾼다.
다른 제공자(`openai:…` · `anthropic:…`)는 그 LangChain 통합 패키지와 키가 따로
있어야 한다 — 저장소는 로컬 쪽만 설치한다.

## 화면에서 누가 무엇을 내나 — 섞지 않는다

| | 누가 | |
| --- | --- | --- |
| 후보 10종 · 베이스라인 점수 | **통계 모델** (`arms.rank_candidates`) | 검증된 값이다 |
| ⚠ 경고 · 근거 | **코드 규칙** (`explain`) | 규칙으로 잡히는 것을 LLM 에 보내지 않는다 |
| 해설 | **LLM** | 사례 해석은 자연어 판단이다 |
| 코드 대조 | **코드** | 모델이 칸에 옮겨 적은 것을 코드가 맞춰 본다 |
| 답 | 패널 라벨 | 누르기 전에는 안 보인다 |

해설은 베이스라인과 경고를 **받아서** 「왜 이 후보인지, 경고와 무엇이
부딪히는지」를 근거로 풀어 쓴다. **확률을 새로 매기지 않는다** — 에이전트의
확률은 평가에서 다수결보다 나빴고, 검증된 점수 옆에 같은 무게로 놓으면 오독된다.

후보 기준의 기본값은 **너프**다. ① 조정의 AUC 는 0.625, 너프로 좁히면 0.794 다 —
같은 10종 목록이라도 너프 쪽 순서가 훨씬 믿을 만하다.

## 첫 해설은 체인, 후속 질문은 에이전트

| 무엇 | 방식 | 조회를 누가 |
| --- | --- | --- |
| **첫 해설** | 체인 | 코드가 R1·R2·R3 를 `RunnableParallel` 로 **한꺼번에** 조회하고, 모델은 해석만 한다 |
| 후속 질문 | 에이전트 | 질문에 맞춰 모델이 무엇을 조회할지 골라 부른다(`create_agent`) |

### 후속 질문이 쥐는 도구

| 도구 | 출처 | 무엇을 주나 |
| --- | --- | --- |
| `find_similar_cases` | R1 | 비슷했던 과거 사례와 그 다음 패치의 결과 |
| `search_patch_notes` | R2 | 패치 노트의 변경 내용. 기준 패치의 노트까지 본다 |
| `lookup_stats` | R3 | 이 챔피언의 과거 지표와 각 패치 다음의 결과 |
| `effect_of` | R3 | **조정 전후** — 조정이 적용된 패치와 직전 패치의 승률 · 픽률 · 밴율 · 판수, 대조군을 뺀 효과 |

`effect_of(챔피언, 패치)` 는 「이 챔피언 너프 후에 뭐가 바뀌었나」에 답하려고 뒀다
(2026-10-01). **숫자는 도구가 계산한다** — `run-effect` 와 정적 API 가 쓰는 계산
(`effect.change_of`)을 그대로 쓰므로 세 곳의 값이 같다.

- **기준 패치 뒤는 보지 않는다.** 기준 패치에 적용된 조정은 잰다 — 직전 패치의 라벨과
  기준 패치의 지표만 쓰고, 기준 패치 행의 라벨(다음에 일어날 일)은 읽지 않는다
- **잴 수 없으면 이유를 말한다** — 조정되지 않았다, 직전 패치 지표가 없다, 직접 집계에서
  판수가 적어 빠졌다. 숫자를 지어내지 않는다
- **표본이 얇으면**(챔피언당 20,000판 미만) **도구가 먼저 말하고**, 전후의 출처가 다르면
  ADR 0012 경고를 붙인다. 「먹혔다 · 안 먹혔다」로 단정하지 않는다
- 평가 도구 묶음에는 넣지 않았다 — 기록한 판단을 재현해야 한다. 익명 조건에서는 켜도
  주지 않는다(패치 이름이 대상의 정체를 드러낸다)

### 후속 답도 코드가 대조한다 (2026-10-01)

답을 `Answer` 로 받는다 — **답 · 답에 쓴 숫자.** 모델이 숫자를 따로 옮겨 적고, 코드가
그것을 도구 출력과 맞춰 본다(`agent/qa.py`). 해설의 `baseline_side` · `tension_quote` 와
같은 방식이다.

**근거로 본 노트 블록은 모델이 적지 않는다 — 코드가 붙인다**
([ADR 0017](adr/0017-note-citations-by-code.md)). 이번 질문에서 노트 검색이 돌려준 블록을
화면이 답 아래에 적는다. 그래서 없는 블록이 나올 수 없다. 처음에는 모델이 인용을 적었는데
[고정 질문으로 재 보니](#고정-질문-27개로-쟀다-2026-10-01) 한 번도 0 이 아니었다.

| 표시 | 뜻 |
| --- | --- |
| ✅ | 답의 숫자가 **출처에 있다.** 몇 개를 확인했는지 같이 적는다 |
| ⚪ | 대조할 것이 없다 — 답에 숫자가 없다. **⚪ 는 「문제없다」가 아니다** — 코드가 확인한 것이 없다는 뜻이다 |
| ⚠ | 도구 결과에 없는 숫자를 썼다. 도구가 낸 주의를 뺐거나 **볼 수 없는 것을 없었다고 말한 것**도 ⚠ 다(아래) |

**출처는 셋이다** — 이 대화에서 도구가 돌려준 글, 코드가 만든 맥락(기준 패치 지표 ·
통계 모델 점수 · 경고), 사람의 질문. **모델이 쓴 글은 출처가 아니다** — 앞선 답에서
지어낸 숫자를 되풀이하면 또 걸린다.

- 숫자는 칸(`numbers`)만 보지 않고 **글도 훑는다** — 칸을 비워 두고 빠져나가지 못한다
- **표시는 확인한 것을 따른다.** 모델이 `Answer` 를 부르지 않고 글로만 답해도 똑같이 본다 —
  숫자를 확인했으면 ✅ 다. 로컬 모델은 칸을 강제할 수 없다
  ([아래](#표시는-확인한-것을-따른다))
- 부호를 적었으면 부호까지, `%` 와 `%p` 는 다른 단위로 본다. `49.4%` 가 있다고 `9.4%` 가
  있는 것은 아니다
- 패치 이름(`14_7` · `14.7`)과 한두 자리 개수는 재지 않는다 — 측정값이 아니다. **「50%」도
  재지 않는다** — 승률의 균형선이라 기준으로 쓰는 말이다(`50.0%` 처럼 소수까지 적으면 잰다)
- **노트 질문에 숫자 없이 답하면 ⚪ 다.** 블록은 코드가 붙였으니 맞고 틀리고가 없고, 답의
  글은 코드가 확인한 것이 없다. 확인한 것이 없으면 통과라고 하지 않는다
- 모델이 인용을 적던 때 받은 답은 **그때의 규칙으로 다시 채점한다** — 도구가 준 적 없는
  블록을 인용했으면 ⚠, 패치를 `[14_7]` 로 적은 것과 다른 도구의 줄을 적은 것은 걸지 않는다
- 대조 결과는 **저장하지 않고 저장된 대화에서 다시 계산한다.** 화면을 껐다 켜도 같은
  표시가 나온다

**✅ 는 「맞는 답」이 아니다.** 숫자의 출처가 있다는 뜻이다. 숫자의 뜻을 틀리게 쓴
것(승률을 픽률이라고 부른 것, 부호 없이 「올랐다」를 「내렸다」로 쓴 것)은 못 잡는다. 글에서
노트 내용을 지어낸 것도 숫자가 아니면 못 잡는다.

#### 도구가 낸 주의는 답이 옮겨야 한다

도구는 다음 셋을 스스로 말한다. **답이 그 말을 빼면 ⚠ 다.**

| 도구가 한 말 | 답에 있어야 하는 것 | 언제 요구하나 |
| --- | --- | --- |
| 「⚠ 표본이 얇다」(챔피언당 20,000판 미만) | 표본이 얇다는 말 | 답이 숫자를 쓸 때 |
| 「⚠ 출처가 …」(u.gg 와 직접 집계가 섞였다) | 출처가 다르다는 말 | 답이 숫자를 쓸 때 |
| 「경계 밖」(기준 패치 뒤라 못 본다) | **볼 수 없다**는 말 | **늘** |

그리고 **화면은 모델이 뭐라고 쓰든 그 주의를 답 아래에 코드로 붙인다** — 사람이 못 보고
지나가지 않게. `lookup_stats` 표에도 표본 주의를 붙였다(후속 질문에서만 — 평가 도구의
출력은 그대로다).

「경계 밖」을 늘 요구하는 이유는 로컬 모델이 실제로 그렇게 틀렸기 때문이다. 기준 패치
`16_13` 에서 「`16_14` 에는 어떻게 됐어?」를 물으니 도구는 「경계 밖」이라고 답했는데 모델은
「**조정되지 않았습니다**」라고 옮겼다 — 실제로는 너프됐다. 못 본 것을 없었다고 말하는
것은 숫자가 없어도 틀린 답이라, 숫자 대조만으로는 못 잡는다.

**「볼 수 없다」고 쓰고도 「없었다」고 단정하면 ⚠ 다.** 고정 질문에서 「15_14 에는 조정이
이루어지지 않았습니다. 15_13 이후 자료를 볼 수 없기 때문입니다」가 통과했다 — 주의하는 말은
있는데 결론이 틀렸다. 그 말 **앞에서 가장 가까운 패치 이름**이 경계 밖 패치일 때만 잡는다
(「15_13 에는 조정되지 않았고 15_14 는 볼 수 없다」는 맞는 답이다). 「기록이 없다 · 보이지
않는다」와 「…았는지는 알 수 없다」는 잡지 않는다 — 일어나지 않았다는 단정이 아니다.

구조화된 답 없이 **글로만 답해도 똑같이 본다.** 없는 숫자나 빠뜨린 주의가 있으면 ⚠ 다.

#### 쓴 돈은 장부에 남는다

유료 모델로 물으면 그 호출이 장부(`data/spend.jsonl`)에 **`qa`** 로 적힌다 — 판단 · 해설에
쓴 돈(`agent`)과 따로 볼 수 있다. 화면은 답마다 「이번 답 · 후속 질문 누적 · 유료 전체 /
상한」을 보인다. 로컬 모델이면 「비용이 없다」고 적는다.

- 답에 든 돈은 **장부에서 잰다**(묻기 전과 뒤의 차). 토큰 수를 따로 세지 않는다
- **상한에 닿았으면 묻기 전에 멈춘다** — 답도 장부도 그대로다(가짜 모델로 시험한다)
- 상한은 용도와 상관없이 **유료 전체**로 잰다

#### 고정 질문 27개로 쟀다 (2026-10-01)

화면에서 몇 번 물어 본 것으로는 「숫자를 지어내지 않는다」고 말할 수 없다. **학습 구간의
끝(`15_13`)에 서서 묻는 질문 27개를 굳혀 두고**, 로컬 모델(`qwen3.5:9b`)의 답을 도구 출력과
함께 적어 둔 뒤 코드로 대조했다([자료](../ground_truth/qa/README.md)).

```bash
./scripts/run-qa dev-v1        # 묻는다 — 로컬 모델 · 비용 0 · 27개에 8~10분
./scripts/score-qa --detail    # 적어 둔 답을 다시 대조한다 — 모델도 data/ 도 필요 없다
```

| 종류 | 수 | 질문 | 바라는 답 |
| --- | ---: | --- | --- |
| `effect` · `mixed` | 10 | 「14_7 패치에서 Volibear 너프 뒤에 뭐가 바뀌었어?」 | 도구가 잰 전후. 표본이 얇은 것을 4개 섞었다 |
| `notes` | 5 | 「14_3 패치 노트에서는 Illaoi 의 뭘 바꿨어?」 | 도구가 준 노트 블록 |
| `stats` · `cases` | 5 | 「Shen 의 최근 승률 흐름은 어때?」 | 도구가 준 표 |
| `unadjusted` · `gap` · `beyond` | **7** | 「15_14 패치에서는 Riven 조정이 어떻게 됐어?」 | **잴 수 없다 · 볼 수 없다** |

**거절해야 하는 질문 7개를 일부러 넣었다.** 잴 수 있는 것만 물으면 「없는 것을 지어내는가」를
못 본다. 질문이 그 경우를 실제로 만드는지는 테스트가 도구에 물어 확인한다.

구간 안이라 누출은 아니고, 고칠 때 본 적이 없는 질문이다(27개 중 2개는 앞선 세트와 겹친다).

**그래도 「숫자는 늘 0 이다」라고 못 박지는 못한다.** 그 전 지시로 물은 처음 보는 질문 한
벌(`dev-v2`)에서는 2개가 나왔다 — 단위를 바꿔 적은 것(`+2.2%p` → `+2.2%`)과 스스로 만든
범위(「49.0%~49.9% 사이」, 표의 최저는 48.9% 다). 나오면 코드가 ⚠ 로 잡는다.

**⚪ 는 「문제없다」가 아니다.** 코드가 확인한 것이 없다는 뜻이다. `dev-v4` 의 한 답은 질문과
상관없이 맥락의 마지막 줄(「… 통계 모델의 판단을 해설해 주세요」)을 그대로 되풀이했는데,
숫자가 없어 ⚪ 였다.

수치는 전부 [`score-qa`](../scripts/score-qa)가 커밋된 답에서 낸 것이고, 같은 값이 나오는지
`tests/test_agent_qa_set.py` 가 본다.

##### 인용을 코드가 붙이게 바꿨다 (ADR 0017)

처음에는 답 형식에 「근거로 쓴 노트 블록」 칸이 있었고 **모델이 채웠다.** 코드는 그 블록을
도구가 실제로 줬는지 맞춰 봤다. 27개씩 다섯 번 받았는데 **한 번도 0 이 아니었다.**

| 절 이름 칸의 설명 | 없는 노트 블록 | 모델이 한 일 |
| --- | --- | --- |
| 진짜 절 이름을 예로 든다 | `dev-v1` 1 | Illaoi 의 노트를 묻는데 **그 예시를 그대로 인용했다.** Senna 를 물었다면 베낀 인용이 대조를 통과했을 것이다 |
| 가짜임이 분명한 예시(`"Q - 스킬 이름"`) | `dev-v1` 2 · **`dev-v2` 5** | 처음 보는 질문에서 **인용 5건 전부** 도구가 준 절 이름 앞에 `Q - ` 를 붙였다(`Thundering Smash` → `Q - Thundering Smash`) |
| 예시 없음 | `dev-v1` 3 · `dev-v3` 2 | 노트 질문은 맞게 인용했다. 인용할 것이 없는 질문에서 `[패치]` 같은 빈말을 적었다 |
| 설명을 길게 고친다 — 「대괄호 안에 준 그대로」 | — | 패치를 `[14_9]` 로 대괄호째 적었다. 9건 받고 멈췄다 |

지어낸 **내용**은 한 건도 없었다. 틀린 것은 모델이 칸을 채우는 방식이고, 그 칸은 화면에
보이지도 않았다 — 틀리면 맞는 답에 ⚠ 가 붙을 뿐이었다. 그리고 어느 블록을 도구가
돌려줬는지는 코드가 이미 안다. **그래서 그 칸을 뺐다.** 화면은 이번 질문에서 노트 검색이
돌려준 블록을 「근거로 본 노트 블록」으로 답 아래에 붙인다.

치른 값도 있다. 모델이 블록을 **골랐다**는 정보가 사라졌고, 노트 질문에 숫자 없이 답하면 전에는
인용이 맞을 때 ✅ 였는데 이제 ⚪ 다. 그때 받은 답 다섯 벌은 지우지 않았고 **그때의 규칙으로
다시 채점한다** — 위 표의 수치가 그대로 나온다.

##### 답 형식의 예시 하나에 답이 바뀐다

위 표가 보인 것이 하나 더 있다. **설명은 모델에게 그대로 가고, 작은 모델은 그 낱말 하나에
답이 바뀐다.** `dev-v1` 만 보고는 가짜 예시를 골랐었는데(없는 블록이 한 개 적었다) 처음 보는
질문에서 틀린 선택으로 드러났다 — 27건에서 한두 개 차이는 우연과 구별되지 않는다.

그래서 **기록마다 모델이 받은 지시의 지문을 적는다** — 프롬프트 · 답 형식 · 도구 설명을
해시한 것이다. 지문이 다른 답은 한 파일에 섞지 않고, 지금 실린 지시가 커밋된 답의 지문과
다르면 테스트가 깨진다. 지시를 고치면 본 질문을 다시 받고, 굳힌 뒤 처음 보는 질문을 새로
만들어 한 번 묻는다.

##### 표시는 확인한 것을 따른다

인용 칸을 빼자 뜻밖의 일이 생겼다. 로컬 모델이 `Answer` 를 부르지 않고 **글로만 답한 것이
27건 중 6 → 16건으로 늘었다.** LangChain 은 답 형식을 `tool_choice="any"` 로 강제하는데
**Ollama 통합은 그 인자를 무시한다**(`ChatOllama.bind_tools` 의 설명에 적혀 있다) — 로컬
모델은 칸을 강제할 수 없다.

그때 규칙은 칸에 넣지 않은 답을 「형식이 맞지 않는다」며 ⚪ 로 뒀다. 그런데 코드는 글의
숫자를 이미 맞춰 본다 — **확인하고도 「대조할 수 없다」고 적는 셈이었다.**

| `dev-v1` · 같은 답 27건 | ✅ · ⚪ · ⚠ |
| --- | ---: |
| 칸에 넣지 않으면 ⚪ | 5 · 19 · 3 |
| **확인한 것을 따른다 (지금)** | **19 · 5 · 3** |

그래서 고쳤다(주인 승인 2026-10-01). **글로 답해도 숫자를 확인했으면 ✅ 고, 지어낸 숫자나
빠뜨린 주의가 있으면 ⚠ 다.** 숫자 칸에 패치 이름이나 스킬 이름을 같이 적은 것도 표시를
가르지 않는다. ⚪ 는 확인한 숫자가 하나도 없을 때뿐이다.

##### 대조 규칙도 이 답들로 고쳤다

`dev-v1` 을 처음 잰 값은 그때 규칙으로 ✅ 13 · ⚪ 8 · ⚠ 6, 없는 숫자 2개 · 없는 노트 블록
2개였다. 걸린 답을 하나씩 읽어 보니 **틀리지 않았는데 걸린 것**과 **틀렸는데 지나간 것**이
섞여 있었다.

| 본 것 | 고친 것 |
| --- | --- |
| 「없는 숫자」 2건이 둘 다 「**50%** 선 근처」였다 | 균형선은 재지 않는다. `50.0%` 는 잰다 |
| 「15_14 에는 조정이 **이루어지지 않았습니다.** 15_13 이후 자료를 볼 수 없기 때문입니다」가 통과했다 | 볼 수 없는 패치를 두고 「없었다」고 단정하면 ⚠ 다 |
| 패치 이름 `14.7` 이 「확인한 숫자」로 세어졌다 | 세지 않는다 |
| 글로만 답하면 숫자가 다 맞아도 ⚪ 였다 | 확인한 것을 따른다(위) |
| (인용을 모델이 적던 때) `effect_of` 의 머리 줄을 노트 칸에 적은 답에 ⚠ 가 붙었다 | 도구가 준 줄이면 걸지 않는다. 어느 도구도 준 적 없는 것만 「없는 블록」이다 |
| (인용을 모델이 적던 때) 패치를 `[14_9]` 로 적은 인용이 「없는 블록」으로 걸렸다 | 대괄호는 봐준다 |

고친 것마다 테스트가 있다(`tests/test_agent_qa.py`). 답과 도구 출력을 적어 뒀으므로 규칙을
고친 뒤 **모델을 다시 부르지 않고** 일곱 벌을 다시 채점했다. 처음 보는 질문(`dev-v2` ·
`dev-v3` · `dev-v4`)의 답을 들여다본 뒤에는 **표시가 달라지는 규칙을 고치지 않았다** —
「확인한 것을 따른다」는 `dev-v4` 의 답을 보기 전에 정했다. 그 뒤에 한 것은 「숫자 칸에 숫자가
아닌 것을 적어도 가르지 않는다」로 규칙을 하나로 정리한 것뿐이고, 일곱 벌 어디에서도 표시가
바뀐 답은 없다.

##### 모델이 아직 틀리는 곳

- **거절을 「없었다」로 옮기거나, 왜 못 보는지를 빼먹는다.** 도구가 「경계 밖」이라고 하면
  「조정되지 않았습니다」나 「기록이 보이지 않습니다」라고만 답한다. 프롬프트에 하지 말라고
  적어도 그런다. **기준 패치 뒤를 묻는 3개는 `dev-v1` 에서 3개, `dev-v4` 에서 2개가 ⚠ 다.**
  화면은 도구가 한 말을 답 아래에 그대로 붙인다
- **숫자를 스스로 만든다 — 드물게.** 지금 지시로는 54건에서 0개다. 그 전 지시로 물은 `dev-v2`
  에서는 2개였다(위)
- **칸에 넣지 않고 글로만 답한다** — 27건 중 16 · 19건. 표시는 가르지 않지만, 숫자 칸에 적어
  주면 글에서 놓칠 수 있는 한두 자리 숫자까지 맞춰 볼 수 있다
- **표의 줄을 잘못 읽는다.** `lookup_stats` 의 「→ 다음 패치」 열을 그 패치의 조정으로 읽었다
  ([followups 35](followups.md#35-lookup_stats-의--다음-패치-열을-모델이-그-패치의-조정으로-읽는다-2026-10-01)).
  숫자는 맞아서 대조가 못 잡는다
- **질문과 상관없는 답** — 숫자가 없으면 ⚪ 로 지나간다(위)

유료 모델로는 재지 않았다([followups 37](followups.md#37-고정-질문을-유료-모델로도-잴-것인가-2026-10-01)).

#### 프롬프트에서 배운 것

해설의 규칙 묶음(`judge.RULES`)을 후속 질문 프롬프트 끝에 그대로 붙여 두었는데, 거기에는
답 형식에 없는 칸(`tension` · `tension_quote`)이 나온다. 주의 규칙을 더하면서 「답하는
방법」이 그 앞으로 밀리자 로컬 모델이 **`Answer` 를 부르지 않고 글로만 답했다**(3건 중
3건). 규칙을 Q&A 용으로 짧게 다시 쓰고 답하는 방법을 맨 끝에 두니 4건 중 3건이 칸을
채웠다. 도구 설명에 「조정 뒤에 뭐가 바뀌었나는 이것으로 확인한다」를 적기 전에는 모델이
`effect_of` 대신 다른 도구를 부르고 얼버무렸다(코드가 ⚠ 로 잡았다). **건수가 적어 성적으로
읽지 않는다** — 고정 질문 세트로 따로 잰다.

로컬 모델(`qwen3.5:9b`)에게 실제로 물어 봤다. 조정 전후 질문은 숫자 6개가 모두 도구
결과에 있어 ✅ 였고, 패치 노트 질문은 도구가 `Absolution` 으로 준 절을 `Q - Absolution`
으로 바꿔 인용해 ⚠ 가 붙었다 — 답 형식 설명의 예시(`Q - …`)를 따라 한 것이었다. 그 뒤
[고정 질문 27개로 쟀다](#고정-질문-27개로-쟀다-2026-10-01).

첫 해설도 처음에는 에이전트였다. 로컬 2B 에게 베이스라인·경고를 다 주니 **도구를
하나도 안 부르고** 받은 것을 되풀어 썼다(Azir·Senna 두 건 모두). 해설에 필요한
근거는 매번 같으므로 무엇을 볼지 모델이 고를 일이 아니다. 그래서 체인을 기본으로
바꿨다.

**그 뒤 화면에서 에이전트 방식을 고르는 칸도 뺐다 (2026-09-22).** 두 방식의 해설이
같은 기록(`runs/explain-demo.jsonl`)에 섞이면 첫 해설끼리 견줄 수 없다 — 에이전트
기록에는 방식 표시(`mode`)도 없었다. 그 전 기록을 셀 때는 `mode` 가 「체인」인 것만
센다. 에이전트 해설(`judge.build_explainer`)은 비교 실험용으로 남긴다.

체인을 고른 근거는 적중이 아니다 — 해설의 입장은 예측이 아니고, 두 방식의 입장을
결과와 맞춰 본 적은 소수 건뿐이라 못 가른다. 근거는 **같은 입력이면 매번 같은 양의
근거를 본다**는 것이다. 에이전트는 사례 검색의 `k` 를 스스로 정해 5~10건만 보는 일이
잦았다(체인은 두 풀 25건씩).

## 코드 대조 — 글에서 값을 뽑지 않는다

로컬 2B 의 Azir 16_15 해설은 베이스라인(버프 0.74 · 너프 0.19)을 「**너프로
보았지만**」으로 거꾸로 읽고, 「버프 주의」 경고를 「**너프 주의**」로 옮겼다.
글에서 값을 뽑는 파서는 만들지 않는다([ADR 0007](adr/0007-answer-schema.md) 선택지 B
기각). 대신 **모델이 칸에 옮겨 적게 하고** 코드가 대조한다.

| 대조 | 잡는 것 |
| --- | --- |
| `misread_baseline` | 옮겨 적은 방향(`baseline_side`)이 실제 점수와 다르다 |
| `misquoted_warning` | 인용한 경고(`tension_quote`)가 코드가 낸 경고에 없다. **띄어쓰기는 안 본다** — 9b 가 원문을 옮기며 공백만 바꾼 것을 한때 잡았다 |
| `invented_tension` | 경고가 없는데 부딪히는 지점을 적었다 |
| `unverified` | 부르지 않은 도구를 출처로 적었다 |

하나라도 걸리면 화면이 「**이 해설은 믿지 않는다**」를 붙인다.

## 해설에 대해 더 묻기

해설 아래에서 이어 묻는다. `thread_id`(브라우저·패치·챔피언)로 대화를 잇고,
`SqliteSaver` 가 `runs/followup.sqlite` 에 남기므로 새로고침해도, 화면을 껐다 켜도
된다 — 같은 브라우저에서 같은 챔피언을 다시 고르면 이전 대화가 되살아난다.

**브라우저 열쇠는 브라우저에 둔다**(`gr.BrowserState`). 한때 Gradio 의 세션 값을
썼는데 그것은 새로고침할 때마다 바뀌어서, 대화는 파일에 남는데 화면이 못 찾았다.

**후속 답은 코드 대조를 거치지 않는다.** 자유 서술이라 대조할 칸이 없다. 화면에
그렇게 적는다.

## 정답 누출을 도구 안에서 막는다

「16_13 을 보고 16_14 를 예측하라」를 받고 16_14 이후를 읽으면 정답을 본 것이다.
**프롬프트 지시로 막지 않는다.** `make_tools(corpus, as_of)` 가 검색기를 **만들 때**
경계를 박고, 도구 인자에는 경계가 없다. 대상 행의 라벨(`adjusted_next` ·
`direction_next`)은 어느 도구도 내보내지 않는다. 테스트가 확인한다.

평가에서는 여기에 **익명 조건**을 더한다([ADR 0006](adr/0006-rag-generation-and-contamination-control.md)).
대상은 키로만 불리고, 이웃은 이름·패치 없이 수치와 결과만 보이며, 노트 검색(R2)은
스킬 이름이 정체를 드러내므로 뺀다.

## 안전장치는 두 겹이다

| 막는 것 | 방법 | 알게 된 경위 |
| --- | --- | --- |
| **호출 횟수** — 도구를 끝없이 부른다 | 모델 호출 8회 · 도구 호출 12회 | 끝없이 도구만 부르는 가짜 모델로 확인 |
| **응답 한 번의 길이** — 한 응답이 끝없이 길어진다 | 출력 600토큰 | `qwen3.5:2b` 가 같은 문단을 2,400토큰 되풀이했다 — 한 건 54초, 답 없이 끝남 |

**첫 번째만 있으면 두 번째를 못 막는다.** 호출은 한 번인데 그 한 번이 길다.
둘 다 한도에 닿으면 구조화된 답이 없으므로 **기권으로 센다.**

## 구조화 출력은 도구 방식으로 고정한다

제공자의 JSON 강제(`ProviderStrategy`)를 로컬 모델에 걸었더니 형식 제약이 도구
호출을 막아 **도구를 하나도 안 부르고** 답했다 — 그러면서 출처에 R1·R3 를 적었다.
겉보기엔 구조화되고 출처까지 달린 답이라 더 위험하다. 도구 방식(`ToolStrategy`)은
제공자와 무관하게 같게 돈다.

## 변형

같은 `B8` 안에서 도구 구성만 다르다.

| 변형 | 도구 | 무엇을 재나 |
| --- | --- | --- |
| `v1` | R1(인자를 모델이 정함) + R3(경계를 분할점에 고정) | 첫 설정 — R3 가 낡은 기록을 준다 |
| `r1` | R1 만, 조정된 사례 25건 고정 | **`B5` 와 같은 증거** 위의 판단 |
| `r1r3` | `r1` + R3(경계를 대상 직전까지) | `B5`·`B6` 이 못 본 정보까지. **돌리지 않았다** |

## 과정 과제와의 대응

이 에이전트는 「생성형 AI 서비스 개발의 이해·활용 (LangChain)」 과정 과제로
만들었다. 교재 장과 코드의 대응이다.

| 장 | 여기서 |
| --- | --- |
| 2 Model | `init_chat_model` — 제공자를 문자열 하나로 바꾼다(`ollama:` · `openai:` · `anthropic:`) |
| 3 Prompt · Structured Output | `PromptTemplate` · `ChatPromptTemplate` / 판단·해설을 Pydantic 스키마로 받는다 |
| 3 Streaming · Memory | `scripts/ask-agent` 에서 도구를 부를 때마다 갱신 / 후속 대화 |
| 4 LCEL · Runnable | 해설 체인 — `RunnableParallel` 로 조회 넷을 동시에 → 프롬프트 → 모델 |
| 5 Agent · Tool | R1·R2·R3 를 `@tool` 로, `create_agent` 가 루프를 돈다 |
| 6 검색 → 생성 | R1 = 표준화 피처 k-NN, R2 = BM25 → 모델이 해설을 생성한다. 임베딩(`OllamaEmbeddings`)은 R2 와 견줘 보고 안 썼다 — `score-retrieval --embed` |
| 7 Middleware · Checkpointer · Backend | 호출 8회·도구 12회 제한 / `thread_id` / `SqliteSaver` |
| 8·9 Gradio | 후보 표 → 챔피언 → 경고·베이스라인·해설·대조·후속 대화·답 |
