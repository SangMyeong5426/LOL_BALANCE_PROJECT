# ADR 0007: 판단을 어떤 형식으로 적는가

- 상태: Accepted
- 날짜: 2026-08-27

## 배경

[ADR 0006](0006-rag-generation-and-contamination-control.md)이 판단 저장 형식을
정했다. **최소한이다.**

```jsonl
{"key": "834b7a", "condition": "anon", "nerf_prob": 78, "reason": "…"}
```

`B6` 을 채점하기에는 이것으로 충분했다. 그런데 세 자리에서 모자란다.

### 하나. 경고가 저장되지 않는다

[README](../../README.md)와 [CLAUDE.md](../../CLAUDE.md)가 이 도구의 값을
「순위」가 아니라 **「놓치면 사고가 나는 것」**에 둔다.

| 경고 | 근거 |
| --- | --- |
| 버프하면 대회 출전이 크게 오른다 | 자주 나오는 챔피언을 버프하면 대회 출전 **+35%** |
| 지나치게 내려갈 수 있다 | 높은 쪽 너프의 **20%** 가 승률 48% 아래로 |

`explain.py` 가 이것을 만들지만 **`predict` 화면에만 찍히고 사라진다.** 그래서
「경고를 낸 건이 실제로 사고가 났나」를 되짚을 수 없다.

### 둘. 어느 검색기가 값을 했는지 모른다

`B6` 은 R1·R2·R3 를 한 덩어리로 받아 점수 하나를 낸다. **맞은 건과 틀린 건에서
어느 검색기를 근거로 삼았는지가 안 남는다.**

실제로 `NoteSearch` 는 챔피언 이름만으로 질의하면 **스킨 버그 수정**을 최상위로
올린다. 그 약점이 판단에 얼마나 번지는지 지금은 못 잰다.

### 셋. 「모른다」를 말할 자리가 없다

`nerf_prob` 은 0~100 이라 **확신 없는 판단도 반드시 숫자 하나로 들어간다.**
실제 판단 314건에 「이웃 0종이라 검색이 아무 말도 못 한다」가 여러 번 나오는데,
그것이 50 으로 적혀 「반반이다」와 구별이 안 된다.

## 검토한 선택지

### A. 지금 형식을 유지한다

`B6` 채점에는 충분하고, 안 쓰는 칸을 만들지 않는다는 미덕이 있다
(`StatLookup` 을 그렇게 처리했다).

**그런데 에이전트가 낼 답의 형식을 안 정하고 루프를 붙이면**, 답이 자유 서술로
나오고 그때 가서 파서를 짜게 된다. **형식을 나중에 바꾸면 그 전에 만든 판단을
전부 다시 만들어야 한다** — `B6` 이 여덟 묶음 걸렸다.

### B. 자유 서술 + 파서

에이전트가 사람이 읽을 글로 답하고, 코드가 거기서 점수를 뽑는다.

**안 된다.** 이 저장소가 이미 겪었다 — 패치 노트 방향을 정규식으로 판정하려다
151건을 오탐으로 냈고, [labeling-guide](../spec/labeling-guide.md)에 「방향을
규칙으로 못 정한다」로 적혀 있다. **자연어에서 값을 뽑는 파서를 또 만들지
않는다.**

### C. 심지 + 몸통 — 채점되는 칸은 고정하고, 나머지를 선택 칸으로 더한다 ← **선택**

기계가 읽는 심지(`nerf_prob`)는 그대로 두고, **전부 선택인 칸**을 더한다.
기존 314건은 손대지 않아도 계속 유효하다.

### D. 완전 구조화 — 근거까지 스키마로

`evidence` 를 `{field, before, after, direction}` 처럼 완전히 구조화한다.

**과하다.** 근거의 절반은 「이웃 25종 중 너프 24」처럼 수치 변경이 아니고, 억지로
칸에 맞추면 담기지 않는 것이 생긴다. **그리고 그 구조화는 수치 추출 과제인데,
[CLAUDE.md](../../CLAUDE.md)가 확인한 대로 그것은 세 과제 어디에도 안 들어간다.**

## 결정

**C 를 택한다.** 새 칸은 **전부 선택**이다.

```jsonl
{"key": "834b7a", "condition": "anon", "nerf_prob": 78, "reason": "…",
 "as_of": "16_13", "abstain": false,
 "evidence": [{"source": "R1", "text": "비슷했던 사례 25종 중 너프 24"}],
 "warnings": [{"kind": "missing_data", "text": "이 패치에 프로 픽·밴이 없다"}]}
```

| 칸 | 필수 | 무엇 |
| --- | :---: | --- |
| `key` · `condition` · `nerf_prob` · `reason` | **예** | ADR 0006 그대로. 바꾸지 않는다 |
| `as_of` | 아니오 | 검색 경계. 나중에 그 답을 의심할 때 되짚는다 |
| `abstain` | 아니오 | 참이면 **커버리지에서 빼고 센다** |
| `evidence[]` | 아니오 | `source` 는 `R1`·`R2`·`R3`·`규칙`·`수치` 중 하나 |
| `warnings[]` | 아니오 | `kind` 는 자유 문자열, `text` 는 필수 |

### `adjust_prob` 은 넣되 **벤치마크용이 아니라고 적는다**

① 대상은 **패치 안 줄 세우기**라 한 패치를 통째로 판단해야 한다. 평가 구간이
**20패치 · 3,433행 · 패치당 171종**이라, `B6` 이 229건에 여덟 묶음 걸린 것을
생각하면 **손으로는 R-정확도를 못 낸다.**

그래서 `adjust_prob` 은 **에이전트가 한 건씩 답할 때 쓰는 칸**이고, arm 을
만들지 않는다. **안 쓰이는 칸을 쓰이는 것처럼 보이게 두지 않는다.**

### 점수는 전부 0~100 정수다

`B4` 가 겪은 해상도 문제 때문이다. 한쪽 근거만 걸린 행이 `1.0`/`0.0` 으로
뭉개져 점수가 5종뿐이었고 AUC 가 0.807 이었다. 사전확률과 섞어 19종으로 늘리니
0.837 이 됐다. **라벨로 받으면 AUC 가 정확도와 같아진다.**

### 경고는 조건부로만 붙인다

항상 뜨는 경고는 경고가 아니다. 버프 후보에 「이미 5할 아래다」를 띄웠다가
목록 전체에 붙어 눈에서 사라진 적이 있고, `explain.warnings` 가 `considering`
인자로 그것을 막는다. 스키마는 그 규칙을 강제하지 않는다 — **강제할 수 없고,
테스트가 지킨다**(`test_explain.py`).

## 영향

**얻는 것**

- **검색기 기여도를 잴 수 있다.** 맞은 건과 틀린 건에서 `source` 분포가 다른지
- **기권이 세어진다.** 커버리지와 정확도를 따로 본다
- **경고가 산출물이 된다.** 낸 경고를 나중에 대조할 수 있다
- **에이전트를 붙일 때 답 형식을 다시 정하지 않는다**

**치르는 것**

- 판단 한 건을 적는 손이 늘어난다. 그래서 전부 선택으로 뒀다
- 칸이 늘면 검증도 늘어난다 — `read_judgments` 가 그 자리에서 거절해야 한다

**안 바뀌는 것**

```
① 27.4%   ② 0.856   ③ 79.5% / 73.4%      전부 그대로
B6 0.830 · B5s 0.850                     그대로
기존 판단 314건                           그대로 유효
```

형식은 「무엇을 예측하는가」가 아니라 「답을 어떻게 적는가」다. 측정값이
움직이면 그것은 결함이다.

## 재검토 조건

- **`evidence` 가 실제로 안 채워지면 뺀다.** 판단 50건을 새로 만들었는데 절반
  이상이 비어 있으면 그 칸은 값을 못 한 것이다
- **에이전트(A6)가 생겨 답이 자동으로 나오기 시작하면** 다시 본다. 사람이 손으로
  적는 것과 루프가 뱉는 것은 감당 가능한 칸 수가 다르다
- **① 판단 arm 을 만들 길이 생기면** `adjust_prob` 의 위치를 다시 정한다
