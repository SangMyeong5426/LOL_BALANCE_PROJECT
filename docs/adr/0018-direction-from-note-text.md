# ADR 0018: 노트 문장에서 조정 방향을 읽는다 — 재 보고 보류했다

- 상태: Proposed · **보류** (제 재검토 조건에 걸렸다 2026-10-19)
- 날짜: 2026-10-19

## 배경

전향 평가 지점에서 **② 방향을 못 재고 있다.** `16_20` 을 채점할 때 맞힌 다섯 자리가
전부 「방향 라벨 없음」이었다.

방향 라벨은 지금 세 곳에서 온다([assemble.directions_in](../../src/lol_balance/assemble.py)).

| 출처 | 무엇을 보나 |
| --- | --- |
| `hand` | 대화 중 Claude 가 노트를 읽고 붙인 것 — 우리 구간 52패치 전량 |
| `auto` | Data Dragon diff — 스탯 · 쿨다운 · 코스트 · 사거리 |
| `value` | CommunityDragon diff — 피해량 · 계수 (ADR 0005) |

**우리 구간 밖(`16_19` 이후)에는 손 라벨이 없다.** 남은 둘은 수치 diff 라 거기 안 잡히는
조정은 라벨이 안 붙는다. `fetch-cdragon` 으로 `16.19` · `16.20` 을 채우고(2026-10-13)
다시 세어도 이렇다.

    16_19  조정 24종 · 라벨 10종
    16_20  조정 21종 · 라벨  7종
    합     조정 45종 · 라벨 17종 (38%)

### 라벨이 없는 28종을 갈라 보면 둘뿐이다

노트 문장을 센 결과다.

| | 종 | 무엇인가 |
| --- | ---: | --- |
| 방향 낱말이 문장에 있다 | **16** | `increased` · `reduced` 가 적혀 있는데 수치 diff 가 못 봤다 |
| `Bug Fix` 한 줄뿐 | 12 | **라벨이 없는 게 맞다** — 버그 수정은 밸런스 의도가 아니다(ADR 0015) |
| 어느 쪽도 아니다 | **0** | |

16종에는 `16_20` 에서 **우리가 맞힌 Kennen 과 Yunara** 가 들어 있다. Kennen 은 공격 속도가
`40 / 50 / 60 / 70 / 80%` 에서 `50 / 60 / 70 / 80 / 90%` 로 `increased`, Yunara 는 패시브
피해가 `5 / 10 / 15 / 20 / 25` 에서 `3 / 8 / 13 / 18 / 23` 으로 `reduced` 다. **노트가 방향을
적어 두었는데 우리가 안 읽고 있다.**

    지금        17/45 (38%)
    문장까지     33/45 (73%)   ← 나머지 12 는 버그 수정뿐이다

### 낱말만 보면 거꾸로 읽는 자리가 있다

**쿨다운은 줄면 버프다.** 방향 낱말이 있는 줄 29개를 세어 보면 뒤집히는 필드가 2개다.

    16_19 Aphelios   Cooldown reduced to 8 – 5 ... from 9 – 6         → 줄었는데 버프
    16_19 Master Yi  Removed: On-hit cooldown reduction is no longer
                     reduced by ability haste                         → 부정문이라 또 뒤집힌다

둘째는 `Removed:` 와 `no longer` 가 겹쳐 **낱말 규칙으로는 어느 쪽으로도 못 읽는다.**
2/29 는 작지만, 틀린 라벨은 없는 라벨보다 나쁘다 — 채점 기준이 틀리면 성적이 통째로
무의미해진다([ADR 0003 배경](0003-llm-provider-and-calling-convention.md)).

## 검토한 선택지

### A. 노트 문장을 네 번째 출처로 넣는다 — 수치 판정이 빈 챔피언만

`increased`/`reduced` 계열 낱말을 필드 극성(`direction.py` 의 `_BUFF_WHEN_UP` ·
`_BUFF_WHEN_DOWN`)과 함께 읽는다. 양쪽이 다 나오면 `mixed` 다.

- **빈칸만 채운다.** `hand` · `auto` · `value` 가 이미 말한 챔피언은 건드리지 않으므로 기존 라벨이 안 바뀐다.
- 73% 까지 올라가고, 남는 12종은 버그 수정뿐이라 **밸런스 의도가 있는 조정은 사실상 다 덮인다.**
- 키가 필요 없고 노트는 이미 받아 뒀다.
- **거꾸로 읽을 위험이 있다**(위 2건). 뒤집히는 필드와 부정문을 만나면 라벨을 안 붙이는 것으로 막는다 — 덮는 범위가 그만큼 준다.
- 규칙이 늘어난다. 노트 표기는 시대마다 달라서([ddragon-format](../spec/ddragon-format.md)) 과거 패치에 그대로 통한다는 보장이 없다.

### B. 전향 지점마다 손 라벨을 붙인다

- **가장 정확하다.** 우리 구간 52패치를 그렇게 만들었고 충돌이 0 이다.
- 노트 전체를 읽으므로 버그 수정도, 부정문도 가른다.
- **오염된다.** 전향 지점의 라벨은 곧 그 지점의 채점 기준인데, 같은 대화에서 예측도 본다. ADR 0006 이 판단자 오염을 재서 배제한 것과 같은 자리이고, 이쪽은 상한을 다시 세울 방법이 없다.
- 패치마다 사람 손이 든다. 매일 수집은 자동인데 채점만 수동이 된다.

### C. CommunityDragon 비교 항목을 넓힌다

Kennen 의 보너스 공격 속도, Yunara 의 패시브 피해는 `cdragon` 파일 안에 있는데 비교
항목에 없다.

- 수치 diff 라 **문장 해석이 없다.** 거꾸로 읽을 위험이 A 보다 작다.
- `16.19` · `16.20` 파일이 이미 받아져 있어 추가 수집이 없다.
- **얼마나 덮을지 모른다.** 항목 이름이 챔피언마다 달라(`BonusAttackSpeed` · `AttackSpeedMod` …) 어디까지 짝지어지는지 세어 보지 않았다. A 는 16종이라고 세어 뒀다.
- 늘린 항목마다 극성을 정해야 하는데, 스킬 필드는 기본 스탯과 달리 이름만으로 극성이 안 정해진다.

### D. 안 한다 — 전향 지점에서는 ① 만 본다

- 규칙이 안 는다. 정답지가 지금 그대로라 소급 문제가 없다.
- **② 가 이 저장소에서 제일 잘 되는 과제다**(AUC 0.900). 그것을 전향으로 확인할 길이 막힌다.
- `predict` 는 이미 「조정되나」를 빼고 방향으로만 묻는다. 방향을 못 재면 **도구가 내는 것과 재는 것이 어긋난다.**

## 재 봤더니 A 가 제 기준을 못 넘었다 (2026-10-19)

아래 「영향」에 적은 대로 **손 라벨에 먼저 붙여 충돌을 셌다.** 우리 구간 52패치의 손 라벨
1,630종이 기준이다.

| 규칙 | 라벨 낸 것 | 일치 | 확장 | 충돌 | 안 읽고 넘김 | 너프↔버프 정반대 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 느슨 — 아래 결정안 그대로 | 603 | 525 | 22 | **56** | 1,003 (62%) | **3** |
| 엄격 — 버그 수정 · 새 효과 · 섞임까지 넘김 | 426 | 391 | — | **35** | 1,180 (73%) | **2** |

**충돌은 저장소 기준으로 셌다.** 손 라벨이 `mixed` 인데 규칙이 한쪽 방향을 말한 것은
「확장」이라 충돌이 아니다([`groundtruth.compare`](../../src/lol_balance/groundtruth.py)) —
노트에서 반대 방향을 더 찾았다는 뜻이기 때문이다. 처음에 이 22건을 충돌로 세어 78건으로
적었다가 바로잡았다.

**두 조건이 동시에 걸린다.** 아래 「재검토 조건」이 「충돌 1건이라도 나오면 멈춘다」와
「안 읽고 넘기는 비율이 절반을 넘으면 B 를 다시 본다」인데, 느슨은 78건에 62%, 엄격은
35건에 73% 다.

### 어디서 갈리는가

| 노트 판정 | 손 라벨 | 건 | |
| --- | --- | ---: | --- |
| buff | `adjust` | 26 | |
| nerf | `mixed` | 19 | ← 확장이라 충돌이 아니다 |
| nerf | `adjust` | 16 | |
| mixed | nerf | 7 | |
| **nerf** | **buff** | **3** | |

**대부분이 `adjust` 와의 충돌이다**(26 + 16 = 42 / 56). 사람은 블록 전체를 읽고 상쇄를
따지는데 규칙은 낱말 하나를 본다. 「피해량은 올리고 사거리는 줄였다」를 사람은 `mixed`
로, 규칙은 먼저 만난 낱말로 적는다.

**정반대 셋이 더 나쁘다.** `13_16` Caitlyn · `14_1` Jarvan IV · `15_3` Elise 는 노트를
너프로 읽었는데 손 라벨이 버프다. 엄격 규칙으로도 둘이 남는다.

    라벨이 비어 있으면 「못 쟀다」로 적힌다.
    라벨이 틀려 있으면 틀린 성적이 나오고, 그것이 맞는 줄 알게 된다.

**그래서 A 를 이대로 정답지에 넣지 않는다.** 채점 기준이 틀리면 성적이 통째로
무의미해진다는 것이 이 저장소가 [ADR 0003](0003-llm-provider-and-calling-convention.md)
에서부터 지켜 온 선이다.

## 결정

**보류한다 — 주인이 고를 자리다.** 아래 결정안은 **채택하지 않은 안**으로 남긴다.

~~**A 를 택한다.** 다만 범위를 좁힌다.~~

| | |
| --- | --- |
| 쓰는 자리 | `hand` · `auto` · `value` 가 **아무 말도 안 한 챔피언만**. 기존 라벨은 안 건드린다 |
| 출처 이름 | `note` — `direction_source` 에 남겨 어디서 왔는지 보이게 한다 |
| 읽는 것 | 방향 낱말 + 그 줄의 필드. 양쪽이 다 나오면 `mixed` |
| **안 읽는 것** | 쿨다운 · 코스트처럼 **뒤집히는 필드**가 섞인 줄, `Removed:` · `no longer` 같은 **부정문**이 있는 줄. 그 챔피언은 라벨 없이 둔다 |
| 버그 수정 | 그대로 라벨 없음(ADR 0015) |

**B 를 택하지 않은 이유**는 오염이다. 전향 지점의 정답지를 예측도 보는 대화에서 만들면
그 지점의 성적을 믿을 근거가 없어진다. **C 는 버리지 않는다** — A 와 겹치지 않고,
A 가 덮는 16종 중 몇이 C 로도 잡히는지 세어 보면 서로 검산이 된다. 다만 얼마를 덮는지
모르는 채로 먼저 하지는 않는다. **D 를 택하지 않은 이유**는 도구가 내는 것이 방향이기
때문이다.

### 측정 뒤에 남은 길 셋

충돌 78건을 보고 나면 고를 것이 이렇게 바뀐다.

| | 무엇을 하나 | 아는 것 · 모르는 것 |
| --- | --- | --- |
| **C 먼저** | CommunityDragon 비교 항목을 넓힌다 | 문장 해석이 없어 정반대로 읽을 위험이 작다. **얼마나 덮을지 아직 안 쟀다** |
| **A 를 보조로만** | 노트 판정을 정답지에 안 넣고, ② 채점을 「노트 라벨 넣은 값 · 뺀 값」 두 줄로 낸다 | 틀린 기준으로 한 줄짜리 성적을 적는 일이 없다. 대신 읽는 사람이 두 줄을 봐야 한다 |
| **B 로 간다** | 전향 지점마다 손 라벨을 붙인다 | 정확하다. **오염 상한을 다시 세울 방법이 없다**(ADR 0006) |

### 지난 지점은 새 정답지로 다시 채점하고, 전후를 같이 남긴다

정답지가 바뀌면 이미 채점한 `16_19` · `16_20` 도 움직인다. 그래서 규칙을 못박는다.

- **① 대상 성적은 안 움직인다.** 방향을 안 쓰고 「조정됐나」만 쓴다. 적중 수치
  (상위 10 에서 2 · 2 · 1)는 그대로다.
- **② 는 「못 쟀다」가 「쟀다」가 되는 것이다.** 주장이 뒤집히는 게 아니라 빈칸이 찬다.
  틀렸던 라벨을 고치는 것이 아니므로 [extension 5절](../extension.md#5-평가와-기록)이
  막는 「고친 코드로 지난 지점을 다시 뽑아 올랐다고 쓰기」에 해당하지 않는다.
- **그래도 바꾼 사실을 적는다.** 지점마다 정답지가 몇 종이었고 몇 종이 됐는지를
  [results](../results/README.md) 에 표로 남긴다. 적어 둔 예측 목록은 건드리지 않는다.

**예측 쪽은 다르다.** 모델·피처를 고치면 지난 지점을 다시 뽑지 않는다. 이 ADR 이 바꾸는
것은 **정답지뿐**이고, 정답지는 개발사가 실제로 한 일이라 우리가 고르는 값이 아니다.

## 영향

**코드는 바뀌지 않았다.** 보류했으므로 `direction.py` 와 `assemble.directions_in` 은
그대로다. 정답지도 그대로여서 `16_19` · `16_20` 채점을 다시 하지 않았다.

- 전향 지점의 ② 는 **여전히 못 잰다.** `16_20` 은 조정 21종 중 방향 라벨 7종(33%)이고,
  적중한 다섯 자리는 버그 수정 둘(Shyvana · Sylas)과 노트에만 적힌 둘(Kennen · Yunara)이다.
- **측정 절차는 남는다.** 손 라벨 1,630종에 붙여 충돌을 세는 이 방식이 네 번째 출처를
  넣으려는 다음 시도에도 그대로 쓰인다.
- 이 ADR 이 **막은 것**이 결과다. 규칙을 넣었으면 덮는 범위가 38% → 73% 로 올랐겠지만
  그중 9% 가 손 라벨과 어긋나고 셋은 정반대였다.

## 재검토 조건

**아래 둘이 이미 걸려서 보류했다.** 조건을 지운 것이 아니라 걸린 것을 적어 둔다.

- ~~손 라벨과 **충돌이 1건이라도 나오면** → 이 결정을 멈추고 어디서 갈리는지 적는다~~
  → **56건. 멈췄고 위에 적었다**
- ~~안 읽고 넘기는 비율이 **절반을 넘으면** → 규칙을 늘리지 말고 B 를 다시 본다~~
  → **62%(느슨) · 73%(엄격)**

다시 볼 조건은 이렇다.

- **C 를 재 보고 덮는 범위가 A 만큼 나오면** → C 로 간다. 문장 해석이 없어 정반대로 읽을 위험이 작다.
- 전향 지점이 쌓여 ② 를 한 번도 못 잰 채 **다섯 지점을 넘기면** → 오염을 감수하고 B 를 다시 본다. 그때는 오염 상한을 못 세운다는 것을 같이 적는다.
- 노트 표기가 바뀌어 `increased` · `reduced` 외의 말이 쓰이기 시작하면 → 이 측정을 다시 한다. 지금 수치는 `13_15` ~ `16_20` 구간의 것이다.
