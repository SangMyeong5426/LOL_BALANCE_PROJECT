# ADR 0003: LLM 제공자와 호출 방식

- 상태: Accepted
- 날짜: 2026-08-25

## 배경

패치 노트를 구조화된 변경 기록으로 바꾸는 것이 이 프로젝트에서 LLM 이 하는 첫 일이고, 그 산출물이 **정답지**다. 정답지가 오염되면 예측도 평가도 효과 측정도 전부 무의미해진다.

규칙으로 못 하는 이유는 [ddragon-format.md](../spec/ddragon-format.md) 에 있다.

- **표기가 시대마다 다르다** — 2023~2024 는 산문(`reduced to X from Y`), 2026 은 화살표(`A ⇒ B`)
- **방향을 규칙으로 못 정한다** — 쿨다운은 줄면 버프, 체력은 줄면 너프, 사거리는 항목마다 다르다
- **Data Dragon 이 대부분의 스킬 피해량을 안 준다** — 툴팁이 `{{ totaldamage }}` 플레이스홀더이고 `datavalues` 는 스킬 932개 전부 비어 있다

동시에 **LLM 에 넘기지 말아야 할 것**도 분명하다. 어느 챔피언의 어느 스킬인지는 위키가 `data-champion` · `data-ability` 속성에 정확히 넣어 두므로 코드가 확정한다([patchnotes.champion_changes](../../src/lol_balance/patchnotes.py)). [CLAUDE.md](../../CLAUDE.md) 의 「규칙으로 잡히는 것을 LLM 에 보내지 않는다」가 이 자리에 그대로 적용된다.

제공자는 `requirements.txt` 와 [config.py](../../src/lol_balance/config.py) 에서 이미 Anthropic 으로 잡혀 있으나 근거가 문서화된 적이 없다. **호출 방식**은 정해진 바가 없다.

## 검토한 선택지

### A. Anthropic SDK 직접 호출 + `messages.parse` 구조화 출력

- `client.messages.parse(output_format=<pydantic 모델>)` 가 스키마를 모델에서 생성하고 응답을 검증한다. 파싱 실패가 API 층에서 걸린다.
- 도구도 상태도 필요 없다. 노트 한 장 → 기록 목록의 단발 변환이다.
- `pydantic` 이 이미 의존성에 있고 스키마가 그대로 저장 형식이 된다.
- 루프가 필요해지면 그때 B 로 옮겨야 한다.

### B. Anthropic SDK Tool Runner (`client.beta.messages.tool_runner`)

- 도구 호출 루프를 SDK 가 돌린다. 나중에 예측 에이전트(조회 → 검색 → 판단)에는 이것이 맞다.
- **추출에는 도구가 없다.** 노트 텍스트가 전부 프롬프트 안에 있고 조회할 것이 없다.
- 베타 의존이 하나 는다.

### C. Managed Agents (서버 관리 에이전트 + 샌드박스)

- Anthropic 이 루프와 컨테이너를 호스팅한다. 스케줄 실행과 세션 상태를 준다.
- **방향이 반대다.** 우리 데이터는 전부 로컬 `data/` 에 있고 그것을 샌드박스로 올릴 이유가 없다.
- 이 프로젝트에는 장기 세션도 스케줄도 없다.

### D. LangChain / LangGraph 등 오케스트레이션 프레임워크

- 체인·프롬프트 템플릿·파서가 갖춰져 있다.
- **단일 변환 한 번에 프레임워크가 과하다.** [README](../../README.md) 가 이미 「도구 몇 개짜리 단일 루프라 오케스트레이션이 과하다」로 제외했다.
- 의존성이 크게 늘고, 구조화 출력은 SDK 가 이미 API 층에서 강제한다.

### E. 파인튜닝

- [README](../../README.md) 가 이미 제외했다. 데이터가 표에 가깝고, **판단 근거가 안 남아** 기획 산출물이 되지 못하며, 패치마다 재학습해야 한다.

## 결정

**A 를 택한다.** Anthropic SDK 직접 호출 + `messages.parse` 구조화 출력.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 제공자 | **Anthropic** | `config.py` 기존 설정. 구조화 출력을 API 층에서 강제하는 경로가 있다 |
| 호출 | `client.messages.parse(output_format=PatchExtraction)` | 파싱 실패가 조용히 섞이지 않는다 |
| 모델 | `claude-opus-5` (`LOL_BALANCE_LLM_MODEL` 로 교체 가능) | 아래 「모델 등급은 측정으로 정한다」 |
| thinking | `{"type": "adaptive"}` | `budget_tokens` 는 이 모델에서 제거됐다 |
| effort | `medium` (추출), 규칙 추출·예측은 `high` 이상 | 추출은 기계적인 축에 가깝다 |
| 단위 | **패치 한 장 = 요청 한 번** | 같은 챔피언 문장이 한자리에 모여 문맥이 유지된다 |

**B 를 택하지 않은 이유**는 추출에 도구가 없기 때문이다. 다만 **예측 에이전트(arm A6)에는 B 를 쓴다** — 그때 별도 ADR 을 쓰지 않고 이 문서를 갱신한다. C·D·E 는 위에 적은 대로다.

### 프롬프트 캐싱을 지금 쓰지 않는다

시스템 프롬프트가 1,024 토큰에 못 미쳐 **캐시가 아예 걸리지 않는다.** 걸리는 척 코드를 넣으면 `cache_read_input_tokens` 가 계속 0인데 아무도 모른다. 규칙 추출 단계에서 밸런스 기준 문서가 접두사로 들어가면 그때 도입한다.

### Batch API 를 지금 쓰지 않는다

파서가 HTML 43 MB 를 텍스트 543 KB(**1.25%**)로 줄여서 74패치 전체가 **약 15만 토큰**이다. 비용이 **$1 미만**이라 50% 할인이 의미 없고, 폴링 코드만 는다. 규칙 추출 스윕이나 백테스트 여러 arm 처럼 호출이 수백 번으로 늘면 그때 도입한다.

### 모델 등급은 측정으로 정한다

**이 자리는 LLM 출력이 자동으로 채점되는 유일한 곳이다.** 스탯·쿨다운·코스트·사거리 네 종은 Data Dragon 에 완전하므로 추출 결과와 기계적으로 대조된다([crosscheck.py](../../src/lol_balance/crosscheck.py)).

그래서 등급을 추측으로 정하지 않고 파일럿으로 잰다 — [`scripts/pilot-extract`](../../scripts/pilot-extract). 표기 시대를 고르게 덮는 5패치(13.15 · 14.10 · 15.3 · 16.1 · 16.15), 채점 대상 **66건**.

**측정이 끝나면 이 절을 갱신한다.** 등급 간 재현율 차이가 없으면 싼 쪽으로 내린다. 이것은 통계 베이스라인을 먼저 세우는 것과 같은 논리다.

### 채점에서 「대조 불가」를 환각으로 세지 않는다

추출에만 있고 Data Dragon 에 없는 기록은 **대부분 정상**이다 — 스킬 피해량이 Data Dragon 에 아예 없어서 노트에만 있고, 그것을 뽑으라고 LLM 을 쓴다. 재현율 분모는 **Data Dragon 이 확실히 아는 변경**으로만 잡는다. `tooltip` 은 대부분 변수명 정리이고 `effect` 는 932개 중 306개만 값이 살아 있어 둘 다 채점에서 뺀다.

## 영향

- `ANTHROPIC_API_KEY` 없이도 **수집·집계·통계 베이스라인은 전부 돈다.** `config.llm_available` 이 그 경계를 지킨다.
- 스키마(`extract.ChangeRecord`)가 곧 저장 형식이 된다. 스키마를 바꾸면 이미 추출한 결과를 다시 뽑아야 하므로 **모델 ID·프롬프트·스키마 버전을 결과에 함께 기록한다.** 시드로는 안 잡히는 재현성이다.
- `anthropic` 1.x 는 내부적으로 **httpx2** 를 쓴다. 수집 코드의 `httpx` 객체(Timeout·Client·transport)를 Anthropic 클라이언트에 넘기면 안 된다.
- 파일럿 재현율이 낮게 나오면 프롬프트를 고치는 것이 먼저이고, 그래도 안 되면 이 ADR 을 다시 본다.

## 재검토 조건

- 파일럿 재현율이 **90% 를 밑돌면** → 프롬프트를 고치고 재측정한다. 그래도 안 되면 문장 단위 분할이나 2단계 추출(뽑기 → 검증)을 검토한다.
- 호출이 **수백 번 규모**로 늘면 → Batch API 를 도입한다.
- 안정 접두사가 **1,024 토큰을 넘으면** → 프롬프트 캐싱을 도입한다.
- 예측 에이전트(arm A6)를 만들 때 → Tool Runner 를 쓰고 이 문서를 갱신한다.
