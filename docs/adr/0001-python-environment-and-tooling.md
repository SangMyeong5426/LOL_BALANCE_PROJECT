# ADR 0001: Python 환경과 코드 품질 도구

- 상태: Accepted
- 날짜: 2026-08-24

## 배경

데이터 수집부터 예측·평가까지 전부 Python 한 언어로 간다. 이 프로젝트에서 환경이 만족해야 할 조건은 셋이다.

1. **재현성** — 같은 시드와 같은 원자료에서 같은 결과가 나와야 하고, 그러려면 의존성 버전이 고정돼야 한다. 통계 라이브러리 하나가 기본값을 바꾸면 베이스라인 성능이 통째로 흔들린다.
2. **정확성 그물** — 집계가 한 번 틀리면 예측도 평가도 무의미하다. 그리고 **집계 오류는 에러를 내지 않고 조용히 지나간다.** 단위 테스트와 정적 검사가 처음부터 있어야 한다.
3. **설명 가능성** — 포트폴리오로 쓰는 프로젝트다. 도구를 왜 그것으로 골랐는지 답할 수 있어야 한다.

## 검토한 선택지

### A. `venv` + `requirements.txt` (+ 도구 설정은 `pyproject.toml`)

- 표준 라이브러리만으로 성립한다. 추가 설치가 필요 없다.
- SKALA 과정 `데이터 분석을 위한 Python 이해`(백정열 교수)가 제시한 방식이고, `~/workspace/skala_python` 에서 이미 쓰고 있다. 학습 비용이 0이다.
- 잠금 파일이 없다. 전이 의존성 버전이 재설치 시점에 따라 달라질 수 있다.

### B. `uv`

- 설치·해석이 훨씬 빠르고 `uv.lock` 이 전이 의존성까지 고정한다. 재현성 조건을 가장 잘 만족한다.
- 로컬에 설치돼 있지 않고 강의 자료에도 없다. 도구 하나를 더 설명해야 한다.
- 이 프로젝트의 의존성은 열 개 안쪽이다. 설치 속도가 병목이 아니다.

### C. `poetry`

- `pyproject.toml` 하나로 의존성과 패키징을 함께 다루고 잠금 파일도 있다.
- 이 저장소는 배포할 패키지가 아니라 실행하는 분석 파이프라인이다. 패키징 기능이 필요 없다.
- B 보다 느리고 무겁다. B 를 이길 이유가 없다.

## 결정

**A 를 택한다.** `python3.11 -m venv .venv` + `requirements.txt` / `requirements-dev.txt`, 도구 설정은 `pyproject.toml`.

B 의 잠금 파일 이점은 인정한다. 그러나 이 프로젝트에서 재현성의 실제 위험은 전이 의존성이 아니라 **원자료 수집 시점과 집계 방식**에 있다. 같은 패치라도 언제 긁었느냐에 따라 값이 다르고, 출처를 섞으면 그 지점에서 튄다. 거기에 그물을 치는 것이 우선이고, 도구를 하나 더 얹어 얻는 이득은 그다음이다. 강의에서 배운 방식을 쓰면 "왜 이 도구인가"에 답이 하나 더 생긴다는 점도 고려했다.

**`pip freeze` 를 그대로 쓰지 않는다.** `requirements.txt` 에는 **직접 쓰는 패키지만** 적고 `==` 로 고정한다. 전이 의존성까지 쏟아부으면 무엇이 프로젝트의 선택이고 무엇이 딸려 온 것인지 구분되지 않고, 버전을 올릴 때 무엇을 봐야 하는지도 알 수 없다. 각 줄에 어느 Phase 에서 쓰는지 주석을 단다.

코드 품질 도구는 강의가 제시한 구성을 따른다 — `ruff`(린팅·포매팅), `pytest` + `pytest-cov`(테스트), `mypy`(정적 타입), `pre-commit`(커밋 전 자동 실행).

**ruff 규칙에 `B` 를 더했다.** 강의는 `E`·`F`·`I`·`UP` 을 제시했으나, `B`(flake8-bugbear)는 가변 기본 인자나 루프 변수 캡처처럼 "돌긴 도는" 결함을 잡는다. 집계가 조용히 틀리는 것이 이 프로젝트의 최대 위험이라 그 종류를 늘렸다.

**패키지를 설치하지 않는다(`pip install -e` 를 쓰지 않는다).** `pyproject.toml` 에 패키징 메타데이터를 두지 않고, `import` 경로는 pytest 의 `pythonpath = ["src"]` 로 해결한다. 배포하지 않는 저장소에 패키징 설정을 두면 의존성 기준이 `requirements.txt` 와 `pyproject.toml` 두 곳으로 갈린다.

## 영향

- clone 후 3 명령으로 환경이 선다 — `venv` 생성, `pip install -r requirements-dev.txt`, `pre-commit install`.
- 전이 의존성은 고정되지 않는다. **이것이 이 결정이 감수하는 위험이다.** 결과가 재현되지 않는 일이 실제로 생기면 그때 잠금을 도입한다.
- `requirements.txt` 를 손으로 관리해야 한다. 패키지를 추가할 때 버전을 직접 적는다.

## 재검토 조건

- 재설치 후 같은 원자료에서 다른 집계·평가 결과가 나오는 일이 실제로 발생하면 → B(`uv` + `uv.lock`)로 옮긴다.
- 의존성이 15개를 넘어 손으로 관리하기 어려워지면 → 잠금 파일 도입을 다시 본다.
