# ADR 0004: 정리한 결과를 어떤 형식으로 남기는가

- 상태: Accepted
- 날짜: 2026-08-25

## 배경

지금까지 나온 숫자는 전부 **그때그때 계산하고 버렸다.** `data/` 에 원자료 391 MB 가 있고 파서도 있지만, 정리한 표가 하나도 없어 매번 391 MB 를 다시 읽는다.

[CLAUDE.md](../../CLAUDE.md) 가 남길 것을 정해 두었다.

> 원자료를 커밋하지 않는다. **정리한 결과와 「언제 어디서 어떻게 가져왔는지」만** 남긴다.

그런데 「정리한 결과」가 **두 종류인데 성질이 정반대다.**

| | 패널 | 정답지 |
| --- | --- | --- |
| 내용 | 패치 × 챔피언 승률·픽률·밴율 | 무엇이 몇에서 몇으로, 너프/버프 |
| 만드는 법 | 코드가 `data/` 를 읽어 계산 | **LLM 이 문장을 읽고 판단** |
| 다시 만들면 | **항상 같은 값** | 같다는 보장이 없다 |
| 크기 | 약 8,940행 | 약 8,500건 · 1.4 MB |

**이 차이가 형식을 가른다.** 패널은 버려도 30초면 다시 만들지만, 정답지는 다시 만들면 값이 달라질 수 있고 비용도 든다.

## 검토한 선택지

### A. 둘 다 SQLite 한 파일에

- `sqlite3` 가 표준 라이브러리다. 의존성이 안 는다.
- 인덱스와 SQL 이 된다. 4단계 에이전트의 조회 도구(「패치 t 이전 통계만」)가 그대로 얹힌다.
- **바이너리라 git diff 가 안 읽힌다.** 정답지가 언제 어떻게 바뀌었는지 이력에서 안 보인다.
- 커밋하면 매번 파일 전체가 새 blob 으로 들어가 저장소가 부푼다.

### B. 둘 다 Parquet

- 컬럼 지향이라 압축률과 읽기 속도가 가장 좋다. pandas 와 잘 맞는다.
- **`pyarrow` 가 새로 필요하다.** 100 MB 급 의존성이고, [ADR-0001](0001-python-environment-and-tooling.md) 이 「직접 쓰는 것만 고정한다」로 의존성을 열 개 안쪽으로 유지하고 있다.
- 역시 바이너리다. 8,940행에 압축 이점이 의미 없다.

### C. 둘 다 CSV/JSONL 텍스트

- git diff 가 읽힌다. 사람이 열어 볼 수 있다.
- **조회가 안 된다.** 4단계 에이전트가 「patch < t 이고 champion = X」를 물으면 전체를 읽어 필터해야 한다.
- CSV 는 타입이 없다. 숫자가 문자열로 돌아오는 사고가 조용히 난다.

### D. 성질에 따라 나눈다 — 패널은 SQLite, 정답지는 JSONL

- 각자 필요한 것을 준다. 패널은 조회, 정답지는 이력.
- **형식이 둘이라 읽는 코드가 둘이다.**
- 어느 것이 어느 형식인지 매번 판단해야 한다 — 규칙이 하나 더 는다.

## 결정

**D 를 택한다.** 다만 규칙을 판단이 아니라 **한 문장**으로 못박는다.

> **다시 만들면 같은 값이 나오는가.** 나오면 SQLite 로 `data/` 에 두고 커밋하지 않는다. 안 나오면 JSONL 로 저장소에 커밋한다.

| 산출물 | 형식 | 위치 | 커밋 |
| --- | --- | --- | --- |
| **패널** (패치×챔피언) | SQLite | `data/panel.sqlite` | ❌ |
| **정답지** (변경 기록) | JSONL | `ground_truth/` | ✅ |
| 평가 결과 · 지표 | JSONL | `runs/` | ❌ |

**A 를 택하지 않은 이유**는 정답지가 바이너리로 들어가면 「이번에 무엇이 달라졌나」를 이력에서 볼 수 없기 때문이다. 정답지는 이 프로젝트의 채점 기준이라 그 변화가 가장 잘 보여야 한다.

**B 를 택하지 않은 이유**는 8,940행에 `pyarrow` 를 들이는 것이 남는 장사가 아니어서다. 행이 백만 단위로 늘면 다시 본다.

**C 를 택하지 않은 이유**는 에이전트 도구가 조회를 필요로 하기 때문이다. 다만 정답지 쪽은 실제로 C 를 쓴다 — 조회할 일이 없다.

### 정답지에 무엇을 함께 적는가

값만 남기면 나중에 「이 정답지가 어떻게 만들어졌는지」를 알 수 없다. 재현성의 실제 위험이 여기 있다.

```
ground_truth/
  records/13.15.1.jsonl       변경 기록
  manifest.json               모델 · 프롬프트 해시 · 스키마 버전 · 추출 일자 · 채점 결과
```

**시드로는 안 잡히는 재현성이다.** 프롬프트나 스키마를 고치면 이미 뽑은 정답지를 다시 뽑아야 하고, 그 사실이 `manifest.json` 에 남아야 한다.

### 패널을 커밋하지 않는 대신 만드는 법을 고정한다

`scripts/build-panel` 하나로 만들어지고, 같은 원자료에서 항상 같은 결과가 나와야 한다. **정렬 순서까지 고정한다** — 순서가 흔들리면 「같은 값」이 아니다.

## 영향

- 매번 391 MB 를 다시 읽지 않는다. 패널 한 번 만들면 그 뒤 계산이 표 하나를 읽는다.
- 4단계 에이전트의 조회 도구가 SQL 로 바로 얹힌다. **패치 경계 필터(`patch < t`)를 SQL 에서 강제**할 수 있어 정답 누출을 도구 안에서 막기 쉽다.
- 형식이 둘이라 읽기 코드가 둘이다. 그 대가로 정답지 이력이 남는다.
- `.gitignore` 에 `ground_truth/` 는 넣지 않는다. `data/` · `runs/` 는 이미 막혀 있다.

## 재검토 조건

- 패널 행이 **백만 단위**로 늘면 → Parquet(B)를 다시 본다. 지금은 8,940행이다.
- 정답지가 **10 MB 를 넘으면** → 텍스트 커밋을 다시 본다. `check-added-large-files` 가 2 MB 에서 막으므로 그전에 걸린다.
- 에이전트 도구가 **벡터 검색을 필요로 하면** → 저장 형식을 다시 본다. 지금 계획은 TF-IDF 와 k-NN 이라 SQLite 로 충분하다.
