# ADR 0010: u.gg 가 끊긴 뒤를 Riot API 로 직접 센다 — 키가 필요한 선택 경로

- 상태: Accepted
- 날짜: 2026-09-18

**이 결정은 API 키가 필요하다** — Riot 개발자 포털의 **개인 키**다. 안 해도 기존
결과(① · ② · ③)는 그대로 나온다. 이 경로가 만드는 것은 **`16_15` 뒤의 패치**이고,
세 과제의 측정 구간(`13_14` ~ `16_15`)에는 들어가지 않는다.

## 배경

### 도구가 다섯 패치 뒤에 멈춰 있다

솔랭 지표는 u.gg 아카이브에서 온다. 그 아카이브가 `16_15` 에서 끊겼다.

| | 상태 |
| --- | --- |
| 아카이브 마지막 스냅샷 | `16_15` (2026-07-31) — 출시 이틀째 값이라 예측 기준으로도 안 쓴다 |
| `./scripts/predict` 의 출발 패치 | `16_13` |
| 라이브 패치 (2026-09-18) | Data Dragon `16.18.1` · 출시일 2026-09-10 |
| u.gg 라이브 | **403** — Cloudflare 봇 확인 페이지 (2026-09-18 다시 확인) |

「최신 패치까지 보고 다음 패치를 고른다」가 도구의 쓰임인데, 지금은 다섯 패치 전의
값으로 고른다.

### 막혔던 이유 하나가 풀렸다

[followups 13](../followups.md#riot-매치-api-도-막혔다-2026-08-29--키를-받아도-과거는-안-열린다)
에 Riot 매치 API 가 세 군데서 막힌다고 적었다(2026-08-29).

| 벽 | 개인 키로 |
| --- | --- |
| 개발 키가 24시간마다 꺼진다 | **풀린다.** 포털 문서에 개인 키의 만료는 적혀 있지 않다 |
| 속도 — 2분 100회 | 그대로다. **다만 권역마다 따로 걸린다**(포털 문서) |
| 랭킹 API 는 오늘의 랭킹만 준다 | 그대로다. **2023~2024 는 여전히 못 모은다** |

2026-09-18 에 개인 키를 받아 요청 한 번으로 작동을 확인했다(HTTP 200 · 한도
`100:120,20:1`).

## 검토한 선택지

### A. Riot 매치 API 로 직접 센다 ← **선택**

에메랄드 이상 선수를 뽑아 그 경기를 받고, 솔랭 지표와 **같은 식**으로 승률·픽률·밴율을
센다.

- 모집단을 우리가 정한다 — 큐 · 티어 · 지역을 u.gg 에 최대한 맞출 수 있다
- 경기 단위 자료라 followups 13 이 「매치 API 가 있어야 한다」고 적은 것(아이템
  빌드 · 듀오)이 **앞으로는** 열린다
- 키가 필요하다. 재현하려는 사람도 각자 키를 받아야 한다
- 느리다. 패치 하나에 몇 시간 걸린다
- **u.gg 와 똑같이 셀 수는 없다** — u.gg 가 지역을 어떤 비율로 섞는지, 「에메랄드
  이상」을 무엇으로 가르는지 모른다

### B. lol.ps 를 받아 둔다 — 키가 필요 없다

현재 패치가 바로 받아진다(2026-09-18 확인 · 255행 · 당일 갱신).

- **집계 조건을 우리가 못 정한다** — 지역·티어가 lol.ps 의 것이다. 출처가 다르다
- 최근 4패치만 남는다
- 그래서 [data-sources 5장](../spec/data-sources.md#5-lolps--최근-패치-솔랭--확보-범위-좁음)
  대로 **현재 패치 데모**에만 쓸 수 있다. u.gg 를 잇는 후보가 못 된다

### C. `16_15` 에서 멈춘 채 둔다

키가 필요 없다는 전제가 그대로 남는다. **도구가 최신 패치를 못 본다는 것도 그대로
남는다.**

### 후보로 두지 않은 것

- **u.gg 차단을 돌아가는 것** — 브라우저 위장, 확인 절차 대행, 사용자 브라우저 자동
  조작, 아카이브에 저장 요청을 넣어 대신 받게 하는 것. u.gg 가 자동 수집을 막아 둔
  것이므로 하지 않는다
- **Production 키** — 공개 서비스에 나오는 것이라 개인 분석으로는 받지 못한다

## 결정

**A 를 택한다.** B 는 키가 없다는 장점이 있지만 모집단을 못 맞추므로 u.gg 를 잇는
후보가 될 수 없다. C 는 도구의 쓰임을 포기하는 것이다.

### 무엇을 어떻게 세는가

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 큐 | 솔로 랭크(`420`) | u.gg `ranked_solo_5x5` |
| 선수 | **지금** 에메랄드 이상 — `EMERALD` · `DIAMOND` 각 네 단계와 마스터 이상 | u.gg `emerald_plus`. 「지금」이라는 것은 아래 위험 |
| 선수 뽑기 | 단계별 인원에 비례해 무작위 | 한 점수대에 몰리지 않게 |
| 경기 | 그 선수가 창 안에서 치른 경기 중 **최대 20판** 무작위 | 한 선수가 표본을 채우지 않게 |
| 지역 | `kr` · `euw1` · `na1` 을 같은 판수로 | 권역이 달라 요청 한도가 따로 걸린다. u.gg `world` 의 섞는 비율은 모른다 |
| 패치 | 경기의 `gameVersion` 앞 두 자리 | 이름이 아니라 경기 자체가 말하는 것 |
| 뺄 것 | 리메이크(`gameEndedInEarlySurrender`) | 승패가 대칭이 아니다 |
| 승률 · 픽률 · 밴율 | 역할을 합친 승/판 · 판/게임 · 밴/게임 | 패널이 u.gg 를 읽는 식과 같다(`panel.py`) |

### 무엇을 남기는가

원자료는 `data/riot/` 에만 둔다. **커밋하지 않는다.** 경기마다 남기는 칸은 이렇다.

| 묶음 | 칸 | 쓰는 곳 |
| --- | --- | --- |
| 경기 | 경기 ID · 큐 · 버전 · 시작 시각 · 길이 · 밴 | 패치 · 기간 구분, 중복 제거 |
| 선수마다 | 챔피언 · 팀 · 포지션 · 승패 | 승률 · 픽률 · 밴율 |
| 선수마다 | **최종 아이템** 일곱 칸 · 룬 · 소환사 주문 | 챔피언별 아이템 사용 |
| 선수마다 | 골드 · CS · 챔피언에게 준 피해량 · 킬 · 데스 · 어시스트 | 승률 밖의 변화 |
| 출발점 | 뽑은 선수의 티어 · 단계 · 조회 시각 | 「지금 에메랄드 이상에서 출발한 표본」이라는 조건 |

- **선수를 가리키는 칸(`puuid` · 이름)은 받자마자 버린다.** 선수 단위 부트스트랩에
  필요한 것은 「몇 번째로 뽑은 선수인가」라는 일련번호뿐이다. 계정 API 는 쓰지
  않는다 — 랭킹 응답에 필요한 것이 다 있다
- 출발점의 랭크는 **조회한 시각의** 것이다. 그 경기를 치른 때의 랭크가 아니다
- 결과에는 챔피언 단위 숫자만 적는다

#### 처음에는 칸을 좁게 받았다 (2026-09-18)

처음에는 승률 · 픽률 · 밴율에 필요한 칸만 남기고 아이템 · 룬 · 성과를 버렸다.
**같은 응답에 이미 들어 있어서 남기는 데 요청이 하나도 들지 않는다** — 버렸다가
나중에 필요해지면 경기마다 다시 받아야 한다. 챔피언별 아이템 사용을 보자는 계획이
나와 저장 형식을 2 로 넓혔다(한 줄 0.4 KB → 3 KB). 좁게 받은 1,625판은
`data/riot/v1/` 에 따로 두고 섞지 않는다 — 형식 2 는 형식 1 을 읽기를 거절한다.

### 키는

- `.env` 의 `RIOT_API_KEY`. 커밋하지 않는다
- **주소가 아니라 헤더**(`X-Riot-Token`)로 보낸다 — 로그에 남지 않게
- 요청에 이 프로젝트 이름을 밝힌다(`lol-balance-project`). 파이썬 기본 이름은
  Cloudflare 가 거절한다(오류 1010). **브라우저로 위장하지 않는다**
- 개인 키 규정상 **공개 서비스에서 키를 쓰지 않는다.** 앱은 저장된 숫자만 읽는다

### 잇는 것은 이 ADR 이 정하지 않는다

[출처를 섞지 않는다](../../CLAUDE.md#출처를-섞지-않는다). 직접 집계를 솔랭 지표
뒤에 이으려면 **먼저 같은 패치에서 두 값이 같은지 재야 한다.** 그래서 시험 수집을
먼저 하고, 판정 기준을 **재기 전에** 여기 적는다.

### 시험 수집과 판정 기준 — 재기 전에 정한다

| 패치 | 창 | 왜 |
| --- | --- | --- |
| `16_15` | 2026-07-29 ~ u.gg 스냅샷 시각(2026-07-31 14:05Z) | u.gg 가 센 것과 같은 기간 |
| `16_13` | 2026-06-24 ~ u.gg 스냅샷 시각(2026-07-06 18:34Z) | 판수가 많은 성숙한 스냅샷 |
| `16_18` | 2026-09-11 ~ 2026-09-18 08:00Z | 현재 패치. 비교할 u.gg 가 없다 — **받아진다는 것만** 본다 |

창의 시작은 출시일 0시(UTC)다. 지역마다 패치가 나오는 시각이 달라서 넉넉히 잡고,
패치는 `gameVersion` 으로 가른다. **u.gg 가 출시부터 스냅샷 시각까지를 센다고
본 것이다** — 확인한 사실이 아니다.

**처음에는 출시일 전날로 잡았다가 줄였다(2026-09-18).** 받은 경기의 3~5할이 앞
패치라 버려졌다 — 세 플랫폼 모두 `16_15` 가 출시일 낮(UTC)에야 보였다. 지역별 시각은
[data-sources 5b](../spec/data-sources.md#5b-riot-api--직접-집계--키-필요-2026-09-18-추가)
에 있다. 어느 판을 세는지는 `gameVersion` 이 정하므로 창의 시작은 판정에 영향이 없고,
요청만 아낀다.

챔피언마다 차이(직접 집계 − 솔랭 지표)를 표준오차로 나눈 **z** 를 본다. 표준오차는
**뽑은 선수 단위 부트스트랩**(한 선수의 경기끼리 닮았으므로)과 u.gg 쪽 이항 오차를
합친다. **두 값이 같다면** z 의 평균은 0, 표준편차는 1 근처여야 한다.

직접 집계에서 한 번도 안 나온 챔피언은 부트스트랩 표준오차가 0 이 되어 z 가
무한대로 튄다. 그래서 두 출처가 같다고 놓았을 때의 이항 오차(솔랭 지표의 비율 ·
직접 집계의 분모)를 표준오차의 바닥으로 둔다.

| 판정 | 기준 (승률 · 픽률 · 밴율 각각) |
| --- | --- |
| **잡음 안** | \|z 평균\| ≤ 0.2 **이고** z 표준편차 ≤ 1.2 |
| **잡음 밖** | 그 밖 |

승률은 두 쪽 다 30판 이상인 챔피언만 본다. 함께 **계통 차이**를 적는다 — 차이의
분산에서 표준오차² 의 평균을 뺀 것의 제곱근이고, 잡음으로 설명되지 않는 차이의
크기다.

**잡음 안이어도 곧바로 잇지 않는다.** 이 표본 크기에서 구분이 안 된다는 뜻이지
같다는 증명이 아니다. 잇는 것은 새 ADR 로 정한다.

### 재고 나서 고친 것 (2026-09-20)

**밴을 세는 단위를 경기로 맞췄다.** 위 표의 「밴/게임」을 처음에는 밴 칸마다 셌는데,
u.gg 는 한 경기에서 두 팀이 같은 챔피언을 밴해도 한 번으로 센다(경기의 45.2%
에 중복 밴이 있다). 판정 기준(z 문턱)은 그대로다. 견준 결과와 수치는
[results](../results/README.md#밴을-세는-방식이-달랐다--견줘-보고-알았다)에 있다.

**읽는 쪽도 거른다.** 이긴 쪽이 다섯이 아닌 경기와 다른 플랫폼에서 치른 경기(권역
목록에 섞여 온다)를 `slim` 이 버리고, 이미 받아 둔 파일은 `read_games` 가 같은
규칙으로 거른다.

## 영향

**얻는 것**

- `16_15` 뒤의 패치를 받을 길이 생긴다 — 앞으로 패치마다 쌓을 수 있다
- 출처가 제3자 사이트의 보관 기간이나 차단에 매이지 않는다
- 경기 단위 자료가 앞으로 쌓인다

**치르는 것**

- 「키가 있어야 하는 것은 없다」가 **이 경로에서만** 깨진다. 기존 결과는 그대로 키
  없이 나온다
- 수집이 느리다 — 권역마다 2분 100회
- **지금의 랭킹으로 과거 경기를 뽑는다.** `16_13` 은 열 주 전이라 그사이 오르내린
  선수만큼 모집단이 다르다. 비교에서 이것이 차이로 나올 수 있고, 그러면 과거
  복원은 못 하고 **앞으로 쌓는 것만** 쓸 수 있다는 뜻이다

**안 바뀌는 것**

- 패널 · arm · ① ② ③ 의 숫자
- `./scripts/predict` 의 출발 패치(`16_13`)

## 재검토 조건

- 시험 수집이 **잡음 밖**이면 — 잇지 않고 직접 집계를 **별도 계열**로만 쌓는다
- 개인 키 규정이 바뀌거나 키가 거절되면
- u.gg 아카이브에 `16_15` 뒤 스냅샷이 다시 생기면 — 그때는 이 경로 없이 이어진다
- 요청 한도 안에서 패치당 표본이 모자라다는 것이 드러나면

[followups](../followups.md) 27 에 남긴다.
