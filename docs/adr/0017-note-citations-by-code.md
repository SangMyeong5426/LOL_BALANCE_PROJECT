# ADR 0017: 후속 답의 노트 인용은 코드가 붙인다 — 모델이 적지 않는다

- 상태: Accepted (주인 승인 2026-10-01)
- 날짜: 2026-10-01

## 배경

로컬 화면의 후속 질문(Q&A)은 답을 칸으로 받는다 — **답 · 근거로 쓴 노트 블록 · 답에 쓴 숫자**
([extension 3절 2항](../extension.md)). 코드가 그 숫자와 인용을 도구 결과와 맞춰 보고, 2단계의
완료 기준은 「고정 질문에서 도구에 없는 숫자 0개, 없는 노트 블록 0개」다.

고정 질문 27개씩을 로컬 모델(`qwen3.5:9b`)에게 다섯 번 물었다
([agent](../agent.md#고정-질문-27개로-쟀다-2026-10-01)). **숫자는 지금 지시에서 0개인데 노트
블록은 한 번도 0 이 아니었다.**

| 절 이름 칸의 설명 | 없는 노트 블록 | 모델이 한 일 |
| --- | --- | --- |
| 진짜 절 이름을 예로 든다 | 본 질문 1 | 예시를 다른 챔피언의 노트에 그대로 인용했다 |
| 가짜 예시(`Q - 스킬 이름`) | 본 질문 2 · 처음 보는 질문 5 | 도구가 준 절 이름 앞에 `Q - ` 를 붙였다 |
| 예시 없음 | 본 질문 3 · 처음 보는 질문 2 | 인용할 것이 없는 질문에서 `[패치]` 같은 빈말을 적었다 |

세 가지를 알게 됐다.

1. **지어낸 내용은 한 건도 없다.** 틀린 것은 모델이 인용 칸을 채우는 방식이다
2. **문구로는 못 고친다.** 설명의 낱말 하나에 다른 데가 틀어진다
3. **그 칸은 화면에 보이지도 않았다.** 대조 결과 한 줄에 개수로만 나왔다 — 틀리면 맞는 답에
   ⚠ 가 붙을 뿐이다

그리고 어느 블록을 도구가 돌려줬는지는 **코드가 이미 안다.** 이 저장소의 원칙은 규칙으로
되는 일을 LLM 에 보내지 않는 것이다([CLAUDE.md](../../CLAUDE.md)).

## 검토한 선택지

### A. 그대로 둔다 — 모델이 적고, 문구를 더 고친다

- 장점: 답 형식 규칙을 안 고친다. 「도구가 준 블록 중 어느 것을 근거로 썼나」가 남는다
- 단점: 세 번 고쳐 세 번 다 0 이 아니었다. 고칠 때마다 고정 질문을 다시 받아야 하고, 27건에서
  한두 개 차이는 우연과 구별되지 않는다. 완료 기준을 채울 길이 안 보인다

### B. 인용을 코드가 붙인다 ← 택함

모델은 답과 숫자만 적는다. 화면은 **이번 질문에서 `search_patch_notes` 가 돌려준 블록**을 답
아래에 코드로 붙인다.

- 장점: 「없는 노트 블록」이 **구조상 0** 이다. 화면에 근거 블록이 실제로 보인다. 모델이 채울
  칸이 줄어 지시가 짧아진다
- 단점: 답 형식 규칙을 고친다. 모델이 블록을 **골랐다**는 정보가 사라진다 — 도구가 준 블록이
  전부 붙는다. 노트 질문의 답에 숫자가 없으면 코드가 확인한 것이 없어 ✅ 가 아니라 ⚪ 다

### C. 걸리면 한 번 되묻는다

코드 대조가 ⚠ 면 무엇이 걸렸는지 알려 주고 답을 다시 받는다.

- 장점: 인용뿐 아니라 뺀 주의 · 「없었다」고 한 말도 고칠 기회가 생긴다
- 단점: 걸린 답은 두 배 걸린다(로컬 약 15초). 유료면 호출이 한 번 더 든다. 되물은 메시지를
  대화에 어떻게 남기고 출처에서 뺄지를 새로 지켜야 한다. **그래도 0 이 된다는 보장이 없다**

### D. 더 큰 모델에 맡긴다

- 장점: 유료 모델은 답 형식이 강제되고 덜 틀릴 것으로 본다
- 단점: 기본 모델은 로컬이다([ADR 0009](0009-agent-framework-and-local-model.md)). 크레딧은 반
  전체가 나눠 쓴다. 모델이 바뀌어도 「칸을 잘못 채울 수 있다」는 구조는 그대로다

## 결정

**B 를 택한다.**

- 답 형식(`Answer`)은 **답 · 답에 쓴 숫자**다. 노트 블록 칸을 뺀다
- 화면은 이번 질문에서 노트 도구가 돌려준 블록을 **「근거로 본 노트 블록」**으로 답 아래에
  붙인다. 앞 질문에서 본 블록을 뒤 질문의 답에 붙이지 않는다
- 코드 대조는 숫자 · 도구가 낸 주의 · 「없었다」고 한 말을 본다. 인용은 대조할 것이 없다 —
  코드가 붙인 것이라 틀릴 수 없다
- **옛 형식으로 받아 커밋한 답 다섯 벌은 그때의 규칙으로 다시 채점할 수 있게 둔다.** 기록을
  지우지 않고, 문서에 적은 수치(1 · 3 · 2 · 5 · 2)가 계속 재현돼야 한다

A 를 택하지 않은 까닭은 재 본 결과가 그렇기 때문이다. C 는 0 을 보장하지 못하면서 대화
저장과 출처 규칙을 복잡하게 만든다 — 인용 말고 다른 실수를 줄이는 길로 따로 남긴다. D 는
기본 모델을 바꾸는 일이라 이 결정의 범위가 아니다.

## 영향

- [extension 3절](../extension.md) 2 · 3항을 고친다. [ADR 0016](0016-static-api-and-local-qa.md)의
  「근거는 노트 블록으로 가리키고」는 이제 「코드가 붙인다」로 읽는다
- **잃는 것** — 모델이 어느 블록을 근거로 골랐는지. 그리고 노트 질문에 숫자 없이 답하면 전에는
  인용이 맞을 때 ✅ 였는데 이제 ⚪ 다. 확인한 것이 없으면 통과라고 하지 않는다
- **그대로 못 잡는 것** — 글에서 노트 내용을 지어내는 것. 숫자면 잡고 숫자가 아니면 못 잡는다.
  전에도 인용 목록만 봤지 글의 주장을 블록과 맞춰 보지는 않았다
- 모델이 받는 지시가 바뀐다. 고정 질문을 다시 받아 수치를 새로 적는다

## 재검토 조건

- 사람이 「어느 블록이 이 답의 근거인가」를 알아야 하게 된다 — 그때는 블록에 번호를 매겨
  모델이 번호만 고르게 하는 것을 먼저 본다(자유 글자를 적게 하지 않는다)
- 인용 말고 다른 실수(뺀 주의 · 「없었다」고 한 말)를 줄여야 한다 — C 를 다시 본다
