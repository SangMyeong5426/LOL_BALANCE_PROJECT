# ADR 0006: 검색 위에 판단을 올리고, 판단자의 오염을 어떻게 다루는가

- 상태: Accepted
- 날짜: 2026-08-27

## 배경

**이 저장소의 「RAG」에는 검색부만 있다.** `A5`·`B5` 는 이웃 사례를 찾아
**라벨을 다수결**할 뿐 생성 단계가 없다. 코드가 스스로 그렇게 적어 뒀다.

```python
def _retrieved(...):
    """사례 검색만으로 두 과제를 예측한다. 모델이 없다 — 이웃의 다수결이다."""
```

검색기 셋 중 **`NoteSearch`(R2)와 `StatLookup`(R3)은 만들고 테스트했으나 어떤
arm 도 부르지 않는다.** 「에이전트가 쥘 도구」로 만들어 두고 에이전트를 안
만들어서다. 자세한 것은 [glossary](../glossary.md#rag--검색부만-있다).

그래서 이 프로젝트가 답하려는 **증명 5번 — 「LLM·RAG·Agent 가 값을 하는가」**
가 절반만 답해져 있다. 규칙(`B4` 0.836)은 쟀지만 **검색 맥락 위의 판단은 재
본 적이 없다.**

### 그런데 판단자가 오염돼 있다

키 없이 만든다는 전제([CLAUDE.md](../../CLAUDE.md))대로라면 판단은 **대화 안의
Claude** 가 한다. 라벨 1,555종과 규칙 12개를 만든 그 방식이다.

**문제는 그 Claude 가 정답을 이미 봤다는 것이다.**

| 오염 경로 | 내용 |
| --- | --- |
| **라벨을 직접 붙였다** | 방향 라벨 1,555종 전량이 대화 산출물이다. 채점 정답과 같은 것이다 |
| **평가 구간 결과를 봤다** | 대화 중 `Ryze 16_2 → 너프` · `Jinx 15_18 → 버프` 같은 개별 정답을 직접 적었다 |

**「안 봤다」고 주장해도 저장소가 검증할 수 없다.** 검증 불가능한 무오염 주장은
근거가 아니다. 이 저장소는 `check-leakage` 로 라벨을 섞어 성능이 무너지는지
확인하는 곳이고, 같은 기준을 판단자에게도 적용해야 한다.

## 검토한 선택지

### A. 대화 판단 + 대상 익명화 + 오염 상한 검정

- 검색기가 뽑은 맥락을 대화에 붙이고 판단을 받아 텍스트로 저장한다. **API 호출 0회** —
  라벨·규칙과 같은 방식이라 새 전제가 안 생긴다.
- **대상을 익명으로 준다.** 챔피언 이름과 패치를 가리고 수치와 이웃 사례만 준다.
  「내가 Ryze 16_2 를 너프로 라벨했지」가 발동할 **열쇠를 없앤다** — 구조적 방어다.
- **오염 상한을 따로 잰다.** 이름과 패치만 주고 수치도 사례도 안 준 조건에서
  찍기(0.5)를 넘는지 본다. 넘으면 기억이 살아 있다는 뜻이다.
- 약점: **상한 검정이 완벽하지 않다.** 부분 기억(예: AUC 0.60)은 표본이 작으면 못 잡는다.
  그리고 조건 사이에 시간이 지나면 기억 상태가 달라질 수 있다.

### B. API 키로 새 세션에서 판단

- 판단자가 이 대화를 안 본다. **오염이 구조적으로 없다.**
- 프롬프트·모델·시드를 고정해 재현이 된다. 234건을 스크립트로 돌린다.
- **키 없이 만든다는 전제를 깬다.** 사용자가 비용 때문에 정했고 여러 번 확인된 결정이다.
- 그리고 **라벨을 만든 것도 Claude 다.** 세션이 달라도 같은 모델이 같은 노트를 읽으면
  비슷한 판단을 낸다 — 오염이 0 이 아니라 **다른 종류**가 된다.

### C. 로컬 모델(Qwen3-8B 등)로 판단

- 키가 필요 없고 판단자가 라벨을 만든 적이 없다. **오염 경로가 둘 다 끊긴다.**
- 이미 한 번 시도했고 **남기지 않기로 결정했다** — 8B 로는 방향 정확도가 66.9~81.2%
  구간에서 흔들렸고 프롬프트에 과민했다.
- 의존성(`mlx-lm`, 4~8 GB 모델)이 늘고, [README](../../README.md) 가 걷어낸 것을
  되돌리게 된다.

### D. 하지 않는다 — 검색부만 있다고 적고 끝낸다

- 비용 0. **이미 그렇게 적었다**(이 ADR 의 배경).
- 증명 5번이 절반으로 남는다. 「RAG 가 값을 하는가」에 답이 없다.
- 그리고 **R2·R3 가 영원히 죽은 코드로 남는다.**

## 결정

**A 를 택한다.** 대화 판단 + 대상 익명화 + 오염 상한 검정.

**B 를 택하지 않은 이유는 전제다.** 키 없이 만드는 것이 이 프로젝트의 축이고,
그 전제로 이미 라벨 1,555종과 규칙 12개를 만들어 결과를 냈다. 판단 하나를 위해
전제를 깨면 **다른 산출물의 위치도 흔들린다.** 게다가 B 도 오염이 0 이 아니다 —
같은 모델이 같은 패치 노트를 읽고 라벨을 만들었다.

**C 를 택하지 않은 이유는 이미 재 봤기 때문이다.** 8B 판단은 프롬프트 문구 하나에
81.2% → 66.9% 로 흔들렸다. 그 변동이 「검색이 도움이 되는가」를 덮는다.

**D 를 택하지 않은 이유는 R2·R3 다.** 검색기 셋을 만들어 두고 하나만 쓰는 상태를
「완성」이라고 부를 수 없다.

### 조건 둘을 돌린다

| 조건 | 주는 것 | 재는 것 | n |
| --- | --- | --- | ---: |
| **① 익명 + 검색** | 이름 없이 수치 · 이웃 사례 `k` 개 · 관련 패치 노트 | **본 성적** | **234 (전량)** |
| **② 이름만** | 챔피언 이름과 패치. **수치도 사례도 없다** | **오염 상한** | **80** |

**① 을 평가 구간 전량으로 하는 것이 핵심이다.** `B5`(0.866)와 **같은 행**에서
재야 비교가 성립한다. 표본을 줄이면 짝지어 비교할 수 없다.

```
n=234   AUC 0.85 근처에서 95% 폭 ±0.050
        같은 행이라 상관이 높아 차이의 오차는 ±0.032
n=100   ±0.077 — 0.79 와 0.94 가 같은 값이 된다
```

**② 를 80건으로 잡은 것도 계산이다.**

```
n=40   찍기와 다르다고 말하려면 AUC 0.681 이상이어야 한다  ← 못 잡는 검사다
n=80                                        0.627
n=120                                       0.604
```

**40건은 검정이 아니다.** 실제로 0.65 만큼 오염돼도 「깨끗하다」로 통과한다.

### 셋째 조건(수치만, 검색 없음)은 넣지 않는다

「LLM 이 회귀보다 나은가」를 재는 자리인데, **`B1`(같은 4피처 로지스틱 회귀
0.833)과 `B0b`(승률 한 줄 0.799)가 이미 그 자리에 있다.** 2차 질문이므로 ② 에
표본을 몰아준다. 필요해지면 나중에 붙인다.

### 저장 형식

[ADR 0004](0004-processed-data-storage-format.md)의 JSONL 결정을 그대로 따른다.
`ground_truth/directions/*.jsonl` 과 같은 모양이다.

```jsonl
{"id": "16_2/0417", "condition": "anon", "nerf_prob": 78, "reason": "…", "patch": "16_2"}
```

- `nerf_prob` 는 **0~100 정수**다. AUC 는 줄 세우기 점수라 라벨이 아니라 **점수**가 필요하다.
- `reason` 을 반드시 남긴다. **판단 근거가 남는 것**이 [README](../../README.md) 가
  파인튜닝을 안 하기로 한 이유이기도 하다.
- `id` 는 익명 키다. 챔피언 이름을 안 담는다 — 판단 파일만 봐서는 대상을 알 수 없다.

## 영향

**얻는 것**

- 증명 5번의 나머지 절반에 답이 생긴다 — 「검색 위의 판단이 다수결을 이기는가」.
- **`NoteSearch`(R2)가 처음으로 실제로 쓰인다.**
- 오염을 「믿어 달라」가 아니라 **숫자로 상한을 제시**한다.

**비용**

- 판단 314건. 건마다 검색 맥락을 읽어야 해 라벨링보다 턴당 처리량이 적다. 대략 15~20턴.
- 새 코드 ~300줄 + 테스트.

**위험**

- **② 가 찍기를 넘으면 ① 을 못 쓴다.** 그때는 결과를 버리고 「오염돼 측정 실패」로 적는다.
  이것을 미리 정해 둔다 — 결과를 보고 기준을 바꾸면 그것이 곧 p-해킹이다.
- 부분 기억은 ② 로도 못 잡을 수 있다. **한계로 명시한다.**
- 판단이 여러 턴에 걸쳐 이뤄져 **기준이 흔들릴 수 있다.**
  [labeling-guide](../spec/labeling-guide.md)가 라벨에서 겪은 문제와 같다.

**후속**

- 30건 예비를 먼저 돌려 **맥락 형식이 판단할 만한지** 확인하고 나머지를 진행한다.
  형식이 나쁘면 314건을 통째로 버리게 된다.
- `B6` 를 `run-report` 에 합류시키고 `check-leakage` 대상에 넣는다.

## 재검토 조건

- **② 가 찍기를 뚜렷이 넘으면** — 익명화가 안 통한 것이다. B(별도 세션)를 다시 본다.
- **키를 쓰기로 정하면** — B 가 더 나은 설계이므로 이 ADR 을 대체한다.
- **에이전트(A6)를 만들면** — 판단이 단발이 아니라 조회→검색→판단 루프가 된다.
  그때 [ADR 0003](0003-llm-provider-and-calling-convention.md)과 함께 다시 본다.
