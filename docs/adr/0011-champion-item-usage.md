# ADR 0011: 챔피언별 아이템 사용을 최종 아이템으로 센다

- 상태: Accepted
- 날짜: 2026-09-18

**이 결정은 API 키가 필요하다** — [직접 집계](0010-riot-api-direct-aggregation.md)의
경기에서 센다. ① 대상 · ② 방향 · ③ 효과의 숫자에는 들어가지 않는다. **경고와
설명을 늘리는 것**이고, 추천을 낫게 하는지는 앞으로 쌓아 따로 잰다(아래).

## 배경

### 아이템 경고가 패치 단위에 머물러 있다

아이템으로 이뤄진 조정은 정답지에 없다. Lucian–Nami 가 `14_9` 24.0% 에서 `14_10`
6.0% 로 무너졌을 때 두 챔피언 모두 「조정 안 됨」이었고, 무너뜨린 것은
`Essence Reaver` 의 골드가 2900 에서 3200 으로 오른 것이었다(`items.py`).

그래서 도구는 「이 패치는 아이템이 크게 바뀌었다」를 경고로 낸다. 그런데 **어느
챔피언이 그 아이템을 사는지 몰라서** 경고가 패치 단위다. 챔피언별 구매율은 u.gg
`overview` 에 있었지만 아카이브 커버리지가 13.3% 라 막혔다(followups 13).

패치 단위 변동량을 예측 피처로 넣어 본 적도 있다. **안 올랐다** — 패치 안에서
상수라 챔피언을 못 가른다(`items.py`).

### 이제 경기마다 최종 아이템이 있다

직접 집계가 저장 형식 2 부터 이용자마다 최종 아이템 일곱 칸을 남긴다(ADR 0010).
**챔피언 단위로 셀 수 있게 됐다.** 다만 경기가 있는 패치만이다 — `16_13` 과
`16_15` 뒤, 그리고 앞으로 받는 패치.

## 검토한 선택지

### A. 최종 아이템으로 센다 ← **선택**

이미 받고 있는 경기 응답에 들어 있다. **요청이 늘지 않는다.**

- 구매 이력이 아니다 — 판 것 · 다 쓴 것 · 바꿔 산 것은 안 보인다
- 경기가 끝났을 때의 모습이라 짧은 경기는 완성템이 적다

### B. 타임라인으로 구매 이력을 센다

`/lol/match/v5/matches/{matchId}/timeline`. 구매 · 판매 · 되돌리기와 시각이 다 있다.

- 구매 순서와 초반 성과까지 볼 수 있다
- **경기마다 요청이 하나 더 들고 응답이 수백 KB 다** — 권역당 2분 100회에서 받는
  판수가 절반이 된다
- 그래서 **2단계로 미룬다.** 붙일 때는 관심 챔피언을 결과를 보기 전에 정한다

### C. 통계 사이트의 챔피언별 빌드를 받는다

u.gg `overview` 는 아카이브 커버리지 13.3%, 라이브는 Cloudflare 가 막는다. lol.ps 는
엔드포인트를 못 찾았다(followups 13). **막혔다.**

아이템 태그(마법사용 · 원거리용)로 챔피언과 아이템을 짝짓는 것은 후보로 두지
않았다 — 맞는지 확인할 방법이 없다.

## 결정

**A 를 택한다.** 요청이 안 늘고 지금 바로 된다. B 는 A 로 부족함이 드러나면 붙인다.

### 무엇을 어떻게 세는가 — 데이터를 보기 전에 정한다

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 완성템 | 협곡에서 살 수 있고 총 골드 2,000 이상 — **그 패치의** Data Dragon `item.json` 기준 | 패치 단위 경고(`items.FINISHED_GOLD`)와 같은 경계. 신발은 이 아래라 빠진다 |
| 썼다 | 최종 아이템 여섯 칸(장신구 칸 제외)에 그 완성템이 있다 | 구매 이력이 아니다 |
| 진화형 | Muramana · Seraph's Embrace · Fimbulwinter 처럼 게임 중에 바뀐 아이템은 **원래 아이템**(Manamune …)을 쓴 것으로 센다 | 진화형은 살 수 없어 완성템 표에 없고, 경기 끝 인벤토리에는 진화형만 남는다 |
| 아이템 사용률 | 그 패치에서 그 챔피언 판 중 그 완성템을 쓴 판의 비율 | |
| 주요 아이템 | 사용률 상위 셋 중 **20% 이상**인 것 | 한 판에 완성템이 서너 개라 셋이면 빌드의 뼈대가 잡힌다 |
| 표본 기준 | 그 패치에서 **100판 이상**인 챔피언만 주요 아이템을 말한다. 아래는 「표본 부족」 | 사용률 20% 근처에서 95% 구간이 ±8%p 안쪽이 되는 크기 |

### 경고 — 앞 패치의 주요 아이템이 이번 패치에 바뀌었다

기준 패치 `t` 의 후보 옆에, **`t−1` 의 주요 아이템**이 `t−1` → `t` 사이에 바뀌었으면
「주요 아이템 ○○ 가 이번 패치에 바뀌었다」를 붙인다.

- `t` 의 주요 아이템이 아니라 `t−1` 의 것을 쓴다. 바뀐 뒤에는 그 아이템을 덜 사서
  주요 아이템에서 빠질 수 있다 — **흔들린 챔피언일수록 경고가 사라진다**
- Lucian–Nami 사례가 이 모양이다 — `14_10` 에 바뀐 `Essence Reaver` 로 `14_10` 에
  무너졌다. **다만 그 패치의 경기가 없어 우리 기준으로 주요 아이템이었는지는
  확인하지 못한다**
- 바뀐 것은 `items.diff_items` 가 잡는 값(골드와 스탯)이다. **효과 문구만 바뀐
  조정은 안 잡힌다** — 패치 단위 경고와 같은 한계다

### 시간 경계 — 예측하는 날 없던 것을 쓰지 않는다

기준 패치 `t` 로 다음 패치를 예측할 때는 **`t` 까지의 경기와 `t` 까지의 아이템
변경**만 본다. 경기는 `t+1` 출시일 전에 시작한 것만 센다 — 프로 경기에 쓰는
출시일 경계와 같은 원칙이다. 에이전트 도구로 붙일 때도 기존 도구처럼 `as_of` 를
지킨다.

### 말하지 않는 것

- **사용률이 높은 아이템의 승률이 높다고 그 아이템이 이기게 했다고 말하지 않는다**
- 최종 아이템을 구매 순서나 「코어 빌드」로 부르지 않는다
- 표본은 「지금 에메랄드 이상인 이용자에서 출발해 모은 경기」다(ADR 0010). 그 경기의
  열 명 모두가 그때 에메랄드 이상이었다고 말하지 않는다

### 예측 피처로는 아직 안 넣는다

넣으려면 **같은 데이터 · 같은 평가 구간**에서 지금 arm 과 비교해야 한다. 그런데
학습 구간(`13_14` ~ `15_13`)의 경기가 API 에 없다 — 2024-09 이전 창은 조회한 6명
모두 0건이었다(2026-09-18). 되돌려 모을 수 없으므로 **앞으로 패치마다 쌓으면서,
패치 전에 예측하고 패치 뒤에 채점하는 방식**으로만 잰다. 그 비교를 설계할 때 새
ADR 을 쓴다.

### 재고 나서 고친 것 (2026-09-20)

**진화형을 놓치고 있었다.** `16_15` 에서 Ezreal 의 Manamune 사용률이 3% 로 나왔는데
실제로는 83% 가 Muramana 를 들고 있었다(둘을 합치면 86%, `16_16` 에서는 90%). `16_15` 에서 13 챔피언·아이템 쌍이 이것 때문에
20% 문턱 아래였다. Data Dragon 의 `specialRecipe` 로 원래 아이템에 되돌린다
(`builds.evolved_forms`). 정의 표에 넣었다.

**아이템 id 가 바뀌면 못 본다.** `16_17` 에서 Stormrazor 가 3097 에서 3095 로
옮겨 가며 공격 속도가 20% → 25% 로 올랐는데, `items.diff_items` 는 양쪽에 다 있는
id 만 견주므로 이 변경이 안 잡힌다. `16_16` 의 주요 아이템에 Stormrazor 가 없어 이번
숫자에는 영향이 없다. 이름으로 잇는 것은 「이름으로 잇지 않는다」 규칙에 걸리므로
한계로 적는다([followups 28](../followups.md)).

## 영향

**얻는 것**

- 경고가 챔피언 단위가 된다 — 「직접 조정은 없었지만 주요 아이템이 바뀌었다」
- 정답지가 못 보는 조정(아이템)을 후보 옆에 근거로 적을 수 있다

**치르는 것**

- 직접 집계 위에 서므로 **키가 필요하다**
- `16_13` 앞 패치에는 없다 — 백테스트 구간에서는 이 경고를 못 잰다
- 패치당 표본이 작으면 드문 챔피언은 「표본 부족」으로 남는다. 픽률 1% 챔피언이
  100판을 채우려면 패치당 1만 판이 든다

**안 바뀌는 것**

- 패널 · arm · ① ② ③ 의 숫자
- 패치 단위 아이템 경고(`items.churn`)

## 재검토 조건

- 타임라인(B)을 붙이면 「썼다」를 구매 이력으로 바꿀지 다시 본다
- 직접 집계가 **10패치 이상** 쌓이면 추천을 낫게 하는지 잰다 — 새 ADR
- 효과 문구 변경을 잡을 출처를 붙이면 경고 범위를 넓힌다
- 신발 변경이 경고에서 빠지는 것이 문제로 드러나면 완성템 경계를 다시 본다
