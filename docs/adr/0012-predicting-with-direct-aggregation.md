# ADR 0012: 직접 집계로 다음 패치를 예측한다 — 학습은 u.gg, 대상만 우리 집계

- 상태: Accepted
- 날짜: 2026-09-20

**이 결정은 API 키가 필요하다** — 대상 패치의 지표를 [직접 집계](0010-riot-api-direct-aggregation.md)에서
가져온다. ① 대상 · ② 방향 · ③ 효과의 **기존 숫자는 바뀌지 않는다.** 여기서 나오는
성적은 `16_15` 뒤 패치의 것이고, u.gg 구간 성적과 **나란히 놓지 않는다.**

## 배경

u.gg 아카이브가 `16_15` 에서 끊겨 도구가 `16_13` 에서 출발한다. 직접 집계로 그
뒤를 모았고, 같은 패치에서 u.gg 와 견줬다
([results](../results/README.md#직접-모은-경기로-솔랭-지표를-재현해-봤다-2026-09-20)).

| | |
| --- | --- |
| 승률 | 두 패치 모두 **표본 잡음 안** — 이 표본에서 구분되지 않는다 |
| 픽률 · 밴율 | **잡음 밖** — 0.5~1.3%p 가 남는다. 지역을 섞는 비율로 보인다 |

그래서 [followups 27](../followups.md) 에서 **두 계열을 잇지 않기로** 했다. 그런데
잇지 않으면 최신 패치를 아예 못 본다. 이 ADR 은 그 사이의 좁은 길을 정한다.

## 검토한 선택지

### A. 대상 패치의 지표만 직접 집계로 바꾼다 ← **선택**

학습은 u.gg 구간 그대로 두고, 예측할 패치의 행만 우리 집계로 만든다.

- 최신 패치를 본다. 모델·피처·코드는 그대로다
- **입력의 출처가 학습과 다르다.** 픽률·밴율이 0.5~1.3%p 어긋난 채로 들어간다
- 성적을 u.gg 구간과 견줄 수 없다 — 다른 것을 재는 셈이다

### B. 직접 집계로 학습까지 한다

출처가 하나로 맞는다. **그런데 지금 가진 것이 다섯 패치뿐**이고, 학습에 쓰는
구간은 52패치다. 2024년 9월 이전 경기는 API 가 주지 않으므로 채울 수도 없다.

### C. `16_13` 에서 멈춘 채 둔다

출처가 섞이지 않는다. **도구가 두 달 전 값으로 후보를 고른다**는 것도 그대로다.

### D. 한 계열로 이어 붙인다

[followups 27](../followups.md) 에서 안 하기로 했다. 픽률·밴율에 계통 차이가 남아
있고, 이어 붙이면 그 지점에서 값이 튀는 것이 실제 변화처럼 보인다.

## 결정

**A 를 택한다.** 다음을 함께 정한다.

| 항목 | 정한 것 |
| --- | --- |
| 학습 | u.gg 패널에서 대상 패치 **앞** 행만 |
| 대상 | 직접 집계로 만든 그 패치의 행 |
| 표본 문턱 | 패널과 같은 **200판**. 모자라면 대상 종수가 줄어드는 것을 그대로 적는다 |
| 이력 | 앞선 행에서 가져온다 — u.gg 구간과 직접 집계가 **섞인다** |
| 출력 | 「학습은 u.gg, 대상은 직접 집계」를 매번 머리말에 적는다 |
| 채점 | 다음 패치 노트가 있을 때만. ① 조정 여부와 ② 방향을 **따로** 적는다 |

### 방향 라벨은 노트를 읽어 붙인다

새 패치에는 손 라벨이 없다. 기계 판정(Data Dragon · CommunityDragon)은 `16_17`
19종 중 6종만 잡는다 — 기본 스탯이 안 바뀐 조정은 diff 에 안 걸리기 때문이다.

그래서 **대화에서 노트를 읽고 붙였다.** 이 저장소가 1,599건을 만든 방식과 같다
(`scripts/label-material` → `scripts/save-labels`). `16_17` 19종 · `16_18` 12종을
붙였다.

**처음 붙인 것 중 넷이 [라벨 기준](../spec/labeling-guide.md)에 어긋났다** — 같은 날
독립 감사가 잡았다. 버그 수정 한 줄뿐인 Akali · Diana · Vladimir(`16_17`)를 위력
방향으로 붙였는데 기준은 「버그 수정은 `adjust`」이고, LeBlanc 은 공격 속도 성장이
실제로 **줄었는데**(2.35% → 1.5%, 위키 문장은 「increased」로 잘못 적혀 있다)
`buff` 로 붙여 기계 판정과 충돌했다 — `13_22` 의 같은 변경이 `mixed` 였다. 넷을
고쳐 다시 저장했고, `save-labels` 의 Data Dragon 대조로는 **일치 10 · 확장 2 · 충돌 0**
이다(위의 「6종」은 CommunityDragon 까지 넣은 `directions_in` 기준이라 셈이 다르다).
`scripts/score-labels` 전체도 충돌 0 이다.

**교훈**: 라벨을 붙이기 전에 기준 문서를 읽었어야 했다. 기준이 흔들리면 그 자체가
오염원이라고 그 문서 첫 줄에 적혀 있다.

### 이 숫자로 말하지 않는 것

- **「직접 집계로 예측해도 성적이 유지된다」고 말하지 않는다.** 평가 지점이 둘
  뿐이고 대상도 51종뿐이다
- u.gg 구간의 ① 27.4% · ② 0.900 과 같은 표에 넣지 않는다

## 영향

**얻는 것**

- `16_16` · `16_17` 을 기준으로 다음 패치를 예측하고 **노트로 채점**할 수 있다
- 현재 패치(`16_18`)로 다음 패치(`16_19`) 예측을 **미리 공개**할 수 있다. 정답을
  본 적 없는 예측이라 백테스트보다 셈이 깨끗하다

**치르는 것**

- 키가 필요하다
- 대상 종수가 작다 — 패치당 3,000판이면 200판을 넘는 챔피언이 48~51종이다.
  매일 수집이 쌓이면 패치당 1만 판을 넘어 150종 근처가 된다
- 이력 피처에 두 출처가 섞인다

## 재검토 조건

- 패치가 열 개쯤 쌓이면 — 전향 평가(미리 예측하고 패치 뒤 채점)를 설계한다. 새 ADR
- 표본이 커져 대상 종수가 150종을 넘으면 — 지금 성적과 다시 견준다
- u.gg 아카이브가 다시 열리면 — 이 경로 없이 원래대로 돌아간다
