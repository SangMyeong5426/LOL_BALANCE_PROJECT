# ADR 0013: 평가는 고정 묶음을 읽는다

- 상태: Accepted
- 날짜: 2026-09-21

## 배경

[ADR 0010](0010-riot-api-direct-aggregation.md) 의 매일 수집이 현재 패치를 계속
불린다. 하루에 플랫폼마다 300판, 모두 900판이다.

그래서 **같은 명령이 날마다 다른 답을 낸다.** 2026-09-21 에 그것이 실제로 드러났다.
`16_18` 이 3,000판에서 3,900판이 되자 `16_19` 예측의 버프 후보 다섯 중 셋이 바뀌었고
대상 종수가 48 에서 80 으로 늘었다.

「현황 화면」은 최신을 읽어야 맞다. 그러나 **코드나 모델을 견주는 자리에서 자료까지
같이 움직이면 무엇이 숫자를 바꿨는지 못 가른다.** 우리는 이미 그 함정에 한 번
빠졌다 — 문서에 적힌 채점값이 재현되지 않아, 코드가 틀린 것인지 자료가 늘어난
것인지를 따로 재서야 갈랐다([results](../results/README.md)).

## 검토한 선택지

### A. 날짜로 자른다 — `--until`

- 이미 있다. `run-live-predict --until 2026-09-19` 가 미리 적어 둔 예측을 되살린다.
- **경기 ID 를 굳히지 않는다.** 같은 날짜로 잘라도 그 사이에 `fetch-riot` 를 더
  돌렸으면 같은 창에 경기가 더 들어 있다. 되살아나는 것이 **우연히** 같을 뿐이다.
- 읽는 쪽 규칙(`riot.invalid`)이 바뀌면 같은 창에서 다른 경기 수가 나온다.

### B. 집계값을 굳힌다 — 승률·픽률 표를 저장한다

- 가장 작다.
- **코드를 견줄 수 없다.** 집계는 코드가 바뀌면 바뀌어야 하는 값이다. 그것을
  굳히면 코드 변경의 효과가 아예 안 보인다. 자료를 굳히는 목적과 반대다.

### C. 경기 ID 목록을 굳힌다 ← **선택**

- 어느 경기를 셌는지만 고정하고 집계는 그때그때 다시 한다. 코드가 바뀌면 숫자가
  바뀌고, **그 차이가 곧 코드의 효과다.**
- 원자료를 커밋하지 않는 규칙과 부딪히지 않는다 — ID 목록은 `data/` 에 두고
  **해시와 셈만 커밋한다.**
- 다른 기계에서는 다시 받아야 한다. 해시가 다르면 다른 묶음이라고 말할 수 있다.

### D. 원자료를 통째로 복사해 둔다

- 가장 확실하다.
- 패치당 수십 MB 다. 커밋도 못 하고, 묶음을 만들 때마다 늘어난다.
- C 가 주는 것을 같은 값으로 준다 — ID 로 원본을 다시 고를 수 있다.

## 결정

**C 를 택한다.** `scripts/freeze-eval` 이 묶음을 만든다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 굳히는 것 | **경기 ID 목록** | 집계는 코드가 정한다 |
| ID 목록 | `data/snapshots/<이름>/<패치>.txt` | 원자료라 커밋하지 않는다 |
| 해시·셈 | `ground_truth/snapshots/<이름>.json` | 커밋한다 |
| 같이 적는 것 | 기준 시각 · 포함·제외 기준과 그 셈 · 서버별·버전별 수 · 첫·마지막 경기 시각 · 코드 커밋과 **작업 트리 더러움** · 시드 · 모델 식별자 · 저장 형식 판 | 「무엇으로 냈나」가 숫자 옆에 없으면 재현이 안 된다 |
| 덮어쓰기 | **안 한다** — 같은 이름이면 멈춘다 | 묶음이 움직이면 묶음이 아니다 |
| 읽는 쪽 | `--snapshot <이름>` (`run-live-predict` · `diagnose-predict`) | 안 주면 최신을 읽고, 그렇다고 화면에 적는다 |

**쓰는 자리를 나눈다.**

| 자리 | 무엇을 읽나 |
| --- | --- |
| 현황 화면 | 최신. 기준 시각과 표본 수를 같이 적는다 |
| 코드·모델 비교 | **같은 고정 묶음** |
| 미리 적는 예측 | 적을 때의 묶음(또는 `--until`). 사후에 안 고친다 |

## 영향

- **ADR 0010** — 매일 수집은 그대로다. 묶음은 읽는 쪽 장치다.
- **ADR 0012** — 미리 적는 예측에 자른 날짜와 판수를 적기로 한 것이 여기로 이어진다.
- **첫 묶음** `eval-2026-09-21` — 경기 21,811 · 다섯 패치. 이 묶음으로 낸 진단이
  [results](../results/README.md#예측이-왜-안-맞나--절반은-평가-대상에-있지도-않다-2026-09-21)에 있다.
- **한계** — ID 목록이 없는 기계에서는 해시만 읽힌다. 다시 받아 같은 이름으로
  굳히고 해시를 견줘야 같은 묶음이라고 말할 수 있다. 완전한 재현은 아니다.

## 재검토 조건

- **묶음이 열 개를 넘으면** → 이름 규칙과 지우는 규칙을 정한다.
- **다른 기계에서 해시가 안 맞으면** → 원자료를 어디에 둘지 다시 본다(선택지 D).
- **매일 수집이 멈추면** → 굳힐 이유가 줄어든다. 그때 다시 본다.
