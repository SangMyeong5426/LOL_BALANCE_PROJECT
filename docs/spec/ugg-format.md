# u.gg 응답 형식 — `champion_ranking`

**문서가 없는 형식이다.** 필드 이름이 없는 위치 기반 배열이라 각 숫자가 무엇인지 직접 알아냈다. 이 문서는 그 근거를 남긴다 — 근거가 없으면 다음에 형식이 바뀌었을 때 무엇이 틀어진 것인지 알 수 없다.

구현은 [`src/patchlens/ugg.py`](../../src/patchlens/ugg.py), 검사는 [`tests/test_ugg.py`](../../tests/test_ugg.py).

## 받는 법

```
원본   https://stats2.u.gg/lol/1.5/champion_ranking/{지역}/{패치}/{큐}/{티어}/1.5.0.json
경유   https://web.archive.org/web/{타임스탬프}id_/{원본}
```

**`--compressed` 가 없으면 압축 바이너리가 그대로 온다.** JSON 파싱이 실패하고 「형식이 깨졌다」로 오판하게 된다.

## 구조

최상위는 길이 4의 배열이다.

| 자리 | 내용 |
| --- | --- |
| `[0]` | 역할별 챔피언 목록. 키는 `top` · `jungle` · `mid` · `adc` · `supp` |
| `[1]` | 밴 표. `{챔피언ID: 밴수}` + `total_matches` + `-1` |
| `[2]` | 갱신 시각 (ISO 8601) |
| `[3]` | **게임 수** |

챔피언 한 항목은 이렇게 생겼다.

```json
["112", [[61, 0, 1], [157, 0, 1]], 2952, 5948, 160297239, 67576675, 31899, 38685, 33293, 1231068]
```

| 자리 | 뜻 |
| --- | --- |
| 0 | 챔피언 ID (문자열) |
| 1 | 매치업 `[[상대ID, 승, 판], ...]` — **전체가 아니라 일부만 실린다** |
| 2 | **승** |
| 3 | **판** |
| 4 | 누적 딜량 |
| 5 | 누적 골드 |
| 6 | 누적 킬 |
| 7 | 누적 데스 |
| 8 | 누적 어시스트 |
| 9 | 누적 CS |

4~9 는 **누적값이다.** 게임당 값을 보려면 판수로 나눈다.

## 근거

### 1. 전체 승률이 정확히 50.00% 로 떨어진다 — 결정적

한 게임에 승자와 패자가 다섯 명씩이므로 **모든 챔피언·모든 역할을 합치면 승률은 반드시 50%** 여야 한다.

```
승 365,585 / 판 731,170 = 50.0000%
```

역할별로 갈라도 각각 정확히 50.00% 다. **우연히 맞을 수 없는 값이고, 자리 2·3 의 해석이 맞다는 증명이다.**

### 2. 판수 합계가 게임 수의 열 배다

```
선수-게임 합계 731,170  ÷ 10 = 73,117
배열 [3] 값             = 73,117      ← 일치
```

한 게임에 열 명이 들어가므로 그래야 한다. `[3]` 이 게임 수라는 근거다.

### 3. 게임당 평균이 상식적이다

미드 상위 다섯 종 기준.

| 챔피언 | 승률 | 딜/판 | 골드/판 | 킬 | 데스 | 어시 | CS |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 103 | 51.1% | 23,173 | 11,355 | 6.3 | 7.1 | 5.3 | 198 |
| 112 | 49.6% | 26,950 | 11,361 | 5.4 | 6.5 | 5.6 | 207 |
| 238 | 52.5% | 28,384 | 12,564 | 8.5 | 5.1 | 5.9 | 191 |

**미드 CS 190~210, 골드 11~13k** 는 실제 게임과 맞는 범위다. 자리를 하나만 밀어도 이 값이 전부 깨진다.

### 4. 밴 표

```
밴 총합 575,452 ÷ total_matches 63,492 = 게임당 9.06밴   (밴 슬롯 10개)
```

`-1` 은 밴을 하지 않은 슬롯이라 챔피언 표에서 뺀다.

**밴 표의 분모는 게임 수가 아니라 `total_matches` 다.** 둘이 다르다 — 게임 수 73,117 vs `total_matches` 63,492. 게임 수로 나누면 게임당 7.87밴이 되어 슬롯 열 개와 덜 맞는다.

## 픽률의 분모

세 가지로 정의할 수 있고 **어느 것도 틀리지 않다.**

| 분모 | 챔피언 103 (mid) | 성질 |
| --- | --- | --- |
| **역할 총 판수** (146,234) | **5.38%** | 역할 안에서 합이 정확히 100% |
| 게임 수 (73,117) | 10.75% | "이 챔피언이 나온 게임 비율" |
| `total_matches` (63,492) | 12.38% | 밴 표의 분모를 빌린 것 |

**역할 총 판수를 쓴다.** 합이 1 이 되어 해석이 쉽고, 예측 모델에서는 어차피 단조 변환이라 결과가 달라지지 않는다. **다만 화면에 표시된 값과 비교할 때는 정의가 다를 수 있다는 것을 기억한다.**

## 수집할 때마다 항등식을 돌린다

형식이 조용히 바뀌면 파싱은 성공하는데 값만 틀어진다. 그래서 두 항등식을 검사로 넣었다.

| 검사 | 잡아내는 것 |
| --- | --- |
| `check_win_rate_identity` | 승·판 자리가 밀리거나 응답이 잘림 |
| `check_games_identity` | 역할이 빠지거나 응답이 잘림 |

`tests/test_ugg.py` 가 **자리를 일부러 밀었을 때 검사가 실제로 걸리는지**까지 확인한다.

## 아직 안 한 것

**`rankings` 엔드포인트는 형식이 다르다.** 지역·티어가 경로가 아니라 JSON 중첩 키로 들어가고, 그 키가 숫자다. 결측 17패치를 메우려면 그쪽도 해독해야 한다.

**겹치는 패치 35개로 검증할 수 있다** — 같은 패치에서 두 엔드포인트가 같은 승률을 주면 두 해독이 다 맞은 것이다. 이 문서의 해독이 그 검증의 정답지가 된다.
