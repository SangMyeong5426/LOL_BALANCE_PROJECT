# 게임에서 확인해야 할 항목

명세를 쓰다 확정하지 못한 것을 여기 모은다. **Phase 0-B-3 이 이 목록을 일괄 검증한다.**

임의로 채워 넣지 않는 이유는 단순하다 — 데미지 공식 하나가 틀리면 수천 판의 결과가 통째로 무의미하고, 그 사실을 알아챌 방법이 없다.

원자료와 출처는 [`research-notes.md`](research-notes.md)에 있다.

## 적는 법

| 열 | 내용 |
| --- | --- |
| 항목 | 무엇이 확정되지 않았는지 |
| 왜 모르는가 | 출처에 없음 / 출처끼리 다름 / StS1 기준이라 StS2 에 유효한지 모름 |
| 확인 방법 | 직접 플레이 / 디컴파일 / 추가 출처 대조 |
| 못 확인하면 | 그 항목을 피해 가는 대안 |

## 목록 (2026-08-24 웹 조사 결과)

### 1. 다중 타격 시 블록이 타격마다 차감되는가 — **최우선**

| | |
| --- | --- |
| **왜 모르는가** | **출처가 정면으로 반대다.** spire-codex 는 "타격마다 전체 파이프라인, 블록도 타격당 차감", 다른 요약은 "블록은 합산 피해에서 한 번 차감". wiki.gg Block 페이지는 이 경우를 **아예 언급하지 않는다** |
| **왜 중요한가** | Vine Shambler 의 Swipe(6×2), Cubex 의 Expel Blast(5×2)가 전부 다중 타격이다. 블록 5를 든 상태에서 6×2를 맞을 때 결과가 **2 피해**(타격당) 또는 **7 피해**(합산)로 갈린다. 페르소나 2단계(생존 판단)가 여기서 통째로 뒤집힌다 |
| **확인 방법** | 블록을 정확히 든 상태로 다중 타격 적에게 맞아 보면 한 판에 확정된다 |
| **못 확인하면** | 다중 타격 적을 3종 후보에서 제외한다. 단 그러면 Vine Shambler·Cubex 가 빠져 후보가 크게 준다 |

**부분적으로는 이미 확인됐다.** 약화 상태 5뎀 3연타가 25%가 아니라 40% 감소한다는 사실은 **피해 계산과 내림이 타격마다 일어남**을 증명한다. 그러나 그것이 **블록 차감도 타격마다**임을 뜻하지는 않는다. 둘은 다른 질문이다.

### 2. 취약이 스택마다 배율이 커지는가

| | |
| --- | --- |
| **왜 모르는가** | **출처가 반대다.** wiki.gg 취약 페이지는 "스택마다 배율 +50% 가산 중첩", spire-codex 는 "스택 수와 무관하게 배율 고정, 스택은 지속 턴 수" |
| **왜 중요한가** | StS1 은 후자다. 전자가 맞다면 StS2 의 큰 변경이고, Bash(취약 2 부여)의 가치 평가가 완전히 달라진다. Bash 는 시작 덱 카드다 |
| **확인 방법** | 취약 2 를 부여한 뒤 Strike 로 때려 보면 확정된다 |
| **못 확인하면** | StS1 동작(배율 고정)으로 구현하고 README 에 명시한다 |

### 3. Shrink(-30%)가 파이프라인 어디에 끼는가

| | |
| --- | --- |
| **왜 모르는가** | Shrink 가 "공격 피해 30% 감소"라는 것만 확인됐다. **약화(-25%)와 함께 걸렸을 때** 곱연산인지(×0.75×0.70), 더 큰 쪽만 적용인지, 가산인지(-55%) 모른다. 내림이 몇 번 일어나는지도 모른다 |
| **왜 중요한가** | Shrinker Beetle 이 **첫 턴에 반드시** Shrink 를 건다. 3종 후보 중 하나이므로 이 값이 틀리면 그 적의 모든 판정이 틀린다 |
| **확인 방법** | Shrinker Beetle 전투에서 약화를 함께 걸고 피해를 재 본다 |
| **못 확인하면** | Shrinker Beetle 을 후보에서 뺀다 |

### 4. Act 1 변종을 무엇으로 정할 것인가 — **범위 결정이지 게임 확인이 아니다**

Act 1 은 **Overgrowth** 와 **Underdocks** 로 갈리고 적 풀·엘리트·보스가 통째로 다르다. 상호 배타적이다.

**이것은 게임에서 확인할 항목이 아니라 [`../plan.md`](../plan.md) 2장에 들어갈 범위 결정이다.** 다만 변종 선택 방식(플레이어 선택인지 무작위인지)은 출처에 없어 확인이 필요하다 — 무작위라면 실측 통계가 두 변종에 섞여 있다는 뜻이고, 그러면 3-4 축 1 대조에 교란이 하나 더 붙는다.

### 5. Cubex Construct 의 Ascension 수치

출처의 Ascension 8 표기가 일관되지 않았다(`8/9` 같은 형태). 3종 후보로 쓴다면 재확인한다. **Ascension 을 범위에 넣지 않으면 이 항목은 사라진다** — 그것도 아직 정해지지 않았다.

## 계획서로 돌려보낼 것

게임 확인이 아니라 **결정**이 필요한 항목이다. [`../plan.md`](../plan.md) 2장 확정 범위에 들어가야 한다.

| # | 항목 | 왜 지금 정해야 하나 |
| --- | --- | --- |
| A | **Act 1 변종** (Overgrowth / Underdocks) | 적 구현량이 두 배로 갈린다 |
| B | **유물 범위** — 시작 유물만인지, Act 1 획득분까지인지 | Burning Blood(전투당 6 회복)는 클리어율에 직접 영향을 준다. 뺄 수 없다 |
| C | **Ascension 레벨** | 적 HP·피해가 전부 달라지고, 실측 통계와 대조할 때 어느 구간과 맞출지가 여기서 갈린다 |

**C 가 특히 조용한 함정이다.** 계획서 어디에도 Ascension 이 없는데, 실측 승률 통계는 Ascension 구간별로 크게 다르다. 시뮬레이터를 A0 로 만들고 A20 통계와 대조하면 상관이 낮게 나오고, 그 원인을 "교란 요인"으로 오진하게 된다.
