# 예측 신호 — 무엇이 무엇을 가르는가

**과제가 둘인데 필요한 피처가 다르다.** 이 문서는 실측한 것만 적는다.

```
① 대상   다음 패치에 조정될 것인가        너프·버프가 섞인 이진 분류
② 방향   조정된다면 너프인가 버프인가      ① 을 맞힌 뒤의 문제
```

측정은 [`baseline.py`](../../src/lol_balance/baseline.py) · 패널은 [`panel.py`](../../src/lol_balance/panel.py).

## 같은 피처가 두 과제에서 반대로 움직인다

| 피처 | ① 대상 | ② 방향 |
| --- | --- | --- |
| 승률 | AUC **0.451** — 무작위보다 못하다 | AUC **0.800** |
| **\|승률 − 0.5\|** | AUC **0.567** | AUC **0.402** — 뒤집힌다 |
| 픽률 | AUC 0.548 | AUC 0.749 |
| 밴율 | — | AUC 0.772 |

**이게 이 문제의 구조다.**

- **대상**은 U자다. 강해도 약해도 조정된다. 그래서 승률로 줄 세우면 안 되고 거리로 바꿔야 한다.
- **방향**은 단조다. 강하면 너프, 약하면 버프. 그래서 승률이 바로 쓰이고, 거리는 오히려 해가 된다.

`|승률 − 0.5|` 가 방향에서 0.402 인 것은 **버프 대상이 너프 대상보다 5할에서 더 멀기 때문**이다. 라이엇은 명백히 약한 챔피언(45%)을 버프하고, 너프는 더 작은 차이(52%)에서 시작한다.

```
너프 대상 평균 승률 0.5071   ← 5할에서 +0.7%p
버프 대상 평균 승률 0.4866   ← 5할에서 −1.3%p
```

## 밴율이 승률에 거의 맞먹는다

방향 판정에서 밴율 AUC 0.772 는 승률 0.800 에 근접한다. **밴율은 「플레이어가 강하다고 느끼는가」를 담는다** — 승률에 안 잡히는 체감 강함이 여기 들어온다.

```
너프 대상 평균 밴율 0.1419   버프 대상 0.0458   3.1배
너프 대상 평균 픽률 0.0922   버프 대상 0.0516   1.8배
```

**밴 데이터가 통째로 빠진 패치(14_5)가 있다.** 0 으로 채우지 않고 결측 표시 열을 따로 둔다.

## 방향 예측에서는 **가장 단순한 것이 이긴다**

arm 을 만들어 돌렸다 — [`run-direction`](../../scripts/run-direction). 표본은 조정된 챔피언 396건(학습 271 · 평가 125).

| arm | 방법 | AUC | 정확도 |
| --- | --- | ---: | ---: |
| B0 | 무작위 | 0.530 | 53.6% |
| **B0b** | **승률 높은 순** | **0.813** | — |
| B0c | 밴율 높은 순 | 0.734 | — |
| B0d | 픽률 높은 순 | 0.743 | — |
| B1 | 로지스틱 회귀 — 수준 | 0.777 | 68.8% |
| B2 | 로지스틱 회귀 — 수준 + 추세 | 0.781 | 69.6% |
| B3 | 유사 사례 25개 (k-NN) | 0.710 | 60.0% |

**피처 열한 개를 쓴 회귀가 승률 하나를 못 이긴다.** 분할 지점을 다섯 군데로 바꿔도 같다.

| 분할 | 평가 | 승률 순 | 회귀(수준) | 회귀(+추세) |
| --- | ---: | ---: | ---: | ---: |
| 14_23 | 172 | **0.820** | 0.791 | 0.791 |
| 15_1 | 166 | **0.811** | 0.785 | 0.783 |
| 15_13 | 125 | **0.813** | 0.777 | 0.781 |
| 15_20 | 90 | **0.808** | 0.794 | 0.794 |
| 16_1 | 62 | **0.832** | 0.724 | 0.720 |

승률 순은 0.808~0.832 로 흔들리지 않고, 회귀는 0.720~0.794 로 표본이 작아질수록 무너진다. 학습 표본이 271건인데 피처가 열한 개라 과적합하는 것으로 보인다.

**이 숫자가 LLM arm 이 넘어야 할 선이다.** 「조정된다면 어느 쪽인가」는 **한 줄짜리 규칙(승률로 줄 세운다)이 AUC 0.81** 을 낸다. 여기에 무엇을 더해야 나아지는지가 이 프로젝트가 답할 질문이다.

대상 예측과 정반대라는 점도 적어 둔다 — 거기서는 회귀(0.590)가 단일 피처(0.567)를 이겼다. **과제가 다르면 이기는 방법도 다르다.**

## 측정 근거와 한계

| | 표본 | 라벨 출처 |
| --- | --- | --- |
| ① 대상 | 8,767행 · 52패치 | 패치 노트 (전수) |
| ② 방향 | 너프 154 · 버프 205 | **Data Dragon 자동 판정** |

**② 의 표본은 치우쳐 있다.** Data Dragon 이 보는 것은 스탯·쿨다운·코스트·사거리뿐이고, 그것은 노트에 나온 조정의 **26%** 다. 나머지 74%인 피해량 조정에서도 같은지는 손으로 붙인 라벨이 쌓여야 안다.

파일럿 91종으로 미리 봤을 때는 승률 AUC 0.649(p=0.20)로 유의하지 않았다. **모순이 아니라 표본 부족이다** — n=19/39 에서 0.649 는 0.800 과 구분되지 않는다. 다만 그 작은 표본에서도 **밴율은 유의했다**(AUC 0.765, p=0.0055).

**방향 라벨을 늘리면 이 표가 확정된다.** 그때까지 ② 의 숫자는 자동 판정 기준임을 밝혀 둔다.

# 조정은 먹혔나 — 효과 측정

사슬의 세 번째 칸이다. 측정은 [`effect.py`](../../src/lol_balance/effect.py) · 실행은 [`run-effect`](../../scripts/run-effect).

인접 패치 쌍 42개에서 **방향이 분명한 조정 328건**을 쟀다.

| | n | 원변화 | 대조군 뺀 뒤 | 의도대로 |
| --- | ---: | ---: | ---: | ---: |
| 너프 | 134 | −1.066%p | **−1.069%p** | **80.6%** |
| 버프 | 194 | +1.133%p | **+1.168%p** | **79.9%** |

**조정의 약 80% 가 의도한 방향으로 간다.** 뒤집어 말하면 **다섯 건 중 하나는 안 간다.**

효과 크기(대조군 뺀 뒤 절댓값, %p)

```
10% 분위 0.239 · 25% 0.565 · 중앙 1.258 · 75% 2.244 · 90% 3.368
```

## 대조군 보정이 사실상 아무 일도 안 했다

정직하게 적어 둔다. 원변화와 대조군 뺀 값이 거의 같다(−1.066 vs −1.069). **승률은 구조적으로 5할 근처에 모이므로 전 챔피언 평균 변화가 0 에 가깝기 때문**이다.

그래도 빼는 것을 유지한다 — 전체 분포가 실제로 이동한 패치에서는 이 보정이 필요하고, 그런 패치가 없다는 것을 **확인해서** 아는 것과 가정하는 것은 다르다.

## 라벨 출처에 따라 다르다

| 출처 | n | 의도대로 | 평균 \|효과\| |
| --- | ---: | ---: | ---: |
| auto (Data Dragon) | 270 | 81.1% | 1.696%p |
| label (손) | 58 | 75.9% | 1.051%p |

손 라벨 쪽이 성공률도 효과 크기도 작다. **자동 판정은 스탯·쿨다운처럼 승률에 직접 걸리는 조정만 보고, 손 라벨은 피해량·동작 변경까지 포함**하기 때문으로 보인다. 표본이 58건이라 확정할 수는 없다.

## 이 표가 말하지 않는 것

**측정이지 판정이 아니다.** 「너프했는데 승률이 올랐다」는 적어도 「그러니 이렇게 했어야 한다」는 적지 않는다. [`README.md`](../../README.md) 의 「증명하지 않는 것」에 있는 선이다.

# 검증 — 무엇을 확인했고 무엇이 남았나

## 확인한 것

### 누출이 없다

라벨을 패치 안에서 섞으면 성능이 기준선으로 무너져야 한다. 남으면 피처 어딘가가 답을 보고 있다는 뜻이다. 도구는 [`check-leakage`](../../scripts/check-leakage).

| | 원본 | 대상 섞음 | 방향 섞음 | 기준선 |
| --- | ---: | ---: | ---: | ---: |
| A1 R-정확도 | 0.256 | **0.143** | 0.256 | 0.145 |
| A3 AUC | 0.613 | **0.482** | 0.613 | 0.500 |
| B0b AUC | 0.813 | 0.813 | **0.443** | 0.500 |
| B1 AUC | 0.777 | 0.777 | **0.461** | 0.500 |

**교차 영향이 0 인 것도 중요하다** — 방향을 섞어도 대상 arm 이 안 변하고 그 반대도 같다. 두 과제가 어딘가에서 섞여 있으면 여기서 걸린다.

### 피처 설계가 평가 데이터에 기대지 않았다

`|승률 − 0.5|` 는 U자를 보고 나서 넣은 피처다. 그 U자가 **학습 구간만 봐도 보이는지** 확인했다.

```
[학습 구간만]  승률 0.485 미만 30.5% · 0.505~0.515 16.2% · 0.515 초과 20.8%
[평가 구간]    승률 0.485 미만 26.0% · 0.505~0.515 12.8% · 0.515 초과 15.1%
```

양쪽 다 U자다. 평가 구간을 안 봤어도 같은 피처를 설계했을 것이다.

### 판수 문턱이 결과를 좌우하지 않는다

`MIN_MATCHES = 200` 은 임의로 고른 값이다. 바꿔 봤다.

| 문턱 | 행 | A1 R-정확도 | A3 AUC | B0b AUC |
| ---: | ---: | ---: | ---: | ---: |
| 200 | 8,767 | 25.6% | 0.613 | 0.813 |
| 1,000 | 8,535 | 24.5% | 0.614 | 0.811 |
| 2,000 | 7,949 | 24.6% | 0.620 | 0.804 |
| 5,000 | 6,555 | 27.4% | 0.630 | 0.773 |

200~2000 에서 안정적이다. 5,000 에서는 표본이 2,200행 줄면서 흔들린다.

### 결측이 결과를 무너뜨리지 않았다

[`data-sources.md`](data-sources.md) 가 약속한 대조군이다 — 25패치 완전 구간(`13_14~14_14`)만으로 돌려 53패치 결과와 비교한다.

| 구간 | 패치 | 행 | A1 R-정확도 | A3 AUC |
| --- | ---: | ---: | ---: | ---: |
| 53패치 전체 | 52 | 8,767 | 25.6% | 0.613 |
| 25패치 완전 구간 | 25 | 4,146 | 30.5% | 0.603 |

**AUC 는 거의 같다**(0.603 vs 0.613). R-정확도가 더 높은 것은 분할 지점이 달라(`14_5` vs `15_13`) 완전한 대조가 아니기 때문으로 보인다. 「결측 때문에 성능이 무너졌다」는 징후는 없다.

## 이력 피처는 신호가 있는데도 안 먹는다 (2026-08-25)

「최근 N패치 중 몇 번 조정됐나」를 넣어 봤다. 대상 예측(25.8%)이 가장 약한 고리라 직접 공략한 것이다.

**신호는 분명히 있다.**

```
최근 5패치 조정 횟수 → 다음 패치 조정률   (학습 구간, 전체 19.6%)
  0회  n=2,037  16.4%      2회  n=886  23.5%
  1회  n=1,882  19.3%      3회  n=266  27.4%
                           4회  n= 84  33.3%
```

**기존 피처와 겹치지도 않는다** — `pick_rate` 와 +0.149, `ban_rate` 와 +0.190 이다. 픽률 구간을 나눠 봐도 이력이 여전히 +4.1~10.1%p 를 가른다.

**그런데 성능이 안 오른다.**

| arm | R-정확도 | AUC |
| --- | ---: | ---: |
| A7 부스팅 — 수준 + 추세 | **25.8%** | 0.611 |
| A7h 부스팅 — + 이력·역할 | 25.6% | 0.611 |
| A2 회귀 — 수준 + 추세 | **25.5%** | 0.596 |
| A2h 회귀 — + 이력·역할 | 23.7% | 0.606 |

### 왜 그런가 — 신호의 결이 과제와 다르다

R-정확도는 **한 패치 안에서 172종을 줄 세우는** 과제다. 이력을 그 안에서만 재면 이렇다.

```
전체에서 잰 관계        평가 구간에서도 유지  (2회+ 가 0~1회보다 +5.8%p)
패치 안에서 잰 AUC      학습 0.568 · 평가 0.530   ← 거의 무작위
```

**이력은 「이 챔피언이 자주 손대는 축인가」를 말하지 「이번 패치에 손댈까」를 말하지 않는다.** 자주 조정되는 챔피언도 한 패치에서 조정될 확률은 여전히 20% 대이고, 그 순서를 패치 안에서 가르지 못한다.

순열 중요도가 같은 것을 보여 준다. 부스팅 모델의 R-정확도가 그 열을 섞었을 때 얼마나 떨어지나.

```
ban_rate   +3.73%      ← 압도적
win_rate   +2.90%
wr_gap     +1.09%
damage     +0.98%
...
이력·역할 9개 합계  −0.93%   ← 오히려 방해한다
```

### 그래서 남는 교훈

**전체에서 보이는 연관과 그룹 안에서의 변별은 다르다.** 2×2 표로는 훌륭해 보이는 피처가 실제 과제에서는 쓸모가 없을 수 있다. 이 프로젝트의 평가 단위가 「패치 안 줄 세우기」라는 것을 피처 설계에서 먼저 봤어야 했다.

## 아직 확인 못 한 것

### ✅ 1. 피해량 조정에서도 신호가 있다 (2026-08-25 확인)

**답: 그렇다.** 손 라벨을 242종으로 늘려 확인했다.

무작위로 뽑은 패치 안에서, 손으로 붙인 라벨을 **Data Dragon 가시성으로 갈랐다.**

| | 너프 | 버프 | AUC | p |
| --- | ---: | ---: | ---: | ---: |
| 자동 판정 | 9 | 15 | 0.763 | 0.059 |
| 손 라벨 — DD 가 **보는** 변경 | 7 | 11 | 0.922 | 0.0007 |
| 손 라벨 — DD 가 **못 보는** 변경 | 9 | 10 | **0.933** | **0.0005** |

**둘이 같다.** 스탯·쿨다운 조정이든 피해량 조정이든 승률로 방향이 갈린다. 자동 판정 기준 결과(AUC 0.828)를 그대로 믿어도 된다는 뜻이다.

표본이 작아(n=19) 폭은 넓지만 유의하다. 그리고 손 라벨이 자동보다 높은 것도 설명된다 — 노트 전체를 읽으므로 `mixed` 를 제대로 갈라낸다.

전체 손 라벨(130건)로 봐도 **0.643 → 0.725 (p=0.0004)** 로 올랐다. 앞서 낮았던 것은 패치를 크기로 골라 편향된 탓이었다.

### ✅ 2. `mixed` · `adjust` 를 뺀 것 — 절대 수치는 부풀지만 주장은 안 부푼다 (2026-08-25 확인)

② 방향 과제는 조정된 챔피언 중 `nerf` · `buff` 만 본다. 손 라벨에서 나머지 둘이 **46%** 라, 그만큼 빼고 재는 것이 실제보다 쉬운 문제일 수 있었다.

**먼저 둘이 피처 공간에서 어디 있는지 봤다.**

| | n | 승률 평균 | 픽률 | 밴율 | 5할 초과 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `nerf` | 49 | 0.5052 | 0.0890 | **0.1263** | 71.4% |
| `buff` | 81 | 0.4918 | 0.0546 | 0.0389 | 35.8% |
| `mixed` | 36 | 0.4959 | 0.0564 | 0.0732 | 47.2% |
| `adjust` | 75 | 0.4994 | 0.0700 | 0.0661 | 53.3% |
| (안 조정) | 7,221 | 0.5011 | — | — | 54.8% |

**`adjust` 는 안 조정된 챔피언과 사실상 구별이 안 된다**(0.4994 vs 0.5011 · 53.3% vs 54.8%). 밸런스 결정이 아니라 결함 수정이니 당연하고, **빼는 것이 옳다.**

**`mixed` 는 진짜 중간이다** — 너프와 버프 사이에 있고 버프 쪽에 가깝다. 빼면 문제가 쉬워진다.

**얼마나 쉬워지는지 쟀다.** 시간순 분할 `15_13`, 균형정확도.

| 과제 | 균형정확도 | 최빈 기준선 | 기준선 대비 |
| --- | ---: | ---: | ---: |
| ① `nerf` vs `buff` (지금 쓰는 것) | **69.6%** | 50.0% | 1.39배 |
| ② + `mixed` | 49.4% | 33.3% | 1.48배 |
| ③ + `mixed` + `adjust` | 37.2% | 25.0% | 1.49배 |

**절대 수치는 69.6% → 37.2% 로 떨어지지만 기준선 대비 향상폭은 1.39~1.49배로 일정하다.** 「모델이 신호를 잡는다」는 주장 자체는 부풀지 않았다.

**혼동행렬이 더 중요한 것을 말한다** (행=실제, 열=예측).

```
            nerf   buff  mixed adjust
nerf          57      4      4      5     ← 잘 잡는다
buff          25     28      3      9     ← 절반이 nerf 로 샌다
mixed         12      6      1      5     ← 24건 중 1건.  거의 못 잡는다
adjust        23      0      1      6     ← 대부분 nerf 로 샌다
```

**`mixed` 는 현재 통계로 사실상 예측되지 않는다.** 이것 자체가 결과다 — 「어디까지 예측되고 어디부터 안 되는가」의 경계가 여기다.

### 그래서 숫자를 어떻게 적어야 하나

`AUC 0.83` 은 **거른 부분집합의 값**이다. 리포트에는 둘 다 적는다.

```
조정된 챔피언 중 방향이 분명한 것만   AUC 0.83 · 균형정확도 69.6%
조정된 챔피언 전부 (네 갈래)          균형정확도 37.2% (기준선 25.0%)
```

## 이력 피처는 신호가 있는데도 안 먹는다 (2026-08-25)

「최근 N패치 중 몇 번 조정됐나」를 넣어 봤다. 대상 예측(25.8%)이 가장 약한 고리라 직접 공략한 것이다.

**신호는 분명히 있다.**

```
최근 5패치 조정 횟수 → 다음 패치 조정률   (학습 구간, 전체 19.6%)
  0회  n=2,037  16.4%      2회  n=886  23.5%
  1회  n=1,882  19.3%      3회  n=266  27.4%
                           4회  n= 84  33.3%
```

**기존 피처와 겹치지도 않는다** — `pick_rate` 와 +0.149, `ban_rate` 와 +0.190 이다. 픽률 구간을 나눠 봐도 이력이 여전히 +4.1~10.1%p 를 가른다.

**그런데 성능이 안 오른다.**

| arm | R-정확도 | AUC |
| --- | ---: | ---: |
| A7 부스팅 — 수준 + 추세 | **25.8%** | 0.611 |
| A7h 부스팅 — + 이력·역할 | 25.6% | 0.611 |
| A2 회귀 — 수준 + 추세 | **25.5%** | 0.596 |
| A2h 회귀 — + 이력·역할 | 23.7% | 0.606 |

### 왜 그런가 — 신호의 결이 과제와 다르다

R-정확도는 **한 패치 안에서 172종을 줄 세우는** 과제다. 이력을 그 안에서만 재면 이렇다.

```
전체에서 잰 관계        평가 구간에서도 유지  (2회+ 가 0~1회보다 +5.8%p)
패치 안에서 잰 AUC      학습 0.568 · 평가 0.530   ← 거의 무작위
```

**이력은 「이 챔피언이 자주 손대는 축인가」를 말하지 「이번 패치에 손댈까」를 말하지 않는다.** 자주 조정되는 챔피언도 한 패치에서 조정될 확률은 여전히 20% 대이고, 그 순서를 패치 안에서 가르지 못한다.

순열 중요도가 같은 것을 보여 준다. 부스팅 모델의 R-정확도가 그 열을 섞었을 때 얼마나 떨어지나.

```
ban_rate   +3.73%      ← 압도적
win_rate   +2.90%
wr_gap     +1.09%
damage     +0.98%
...
이력·역할 9개 합계  −0.93%   ← 오히려 방해한다
```

### 그래서 남는 교훈

**전체에서 보이는 연관과 그룹 안에서의 변별은 다르다.** 2×2 표로는 훌륭해 보이는 피처가 실제 과제에서는 쓸모가 없을 수 있다. 이 프로젝트의 평가 단위가 「패치 안 줄 세우기」라는 것을 피처 설계에서 먼저 봤어야 했다.
