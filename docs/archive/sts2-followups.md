**결함 목록이 아니다.** 지금 잘못 돌고 있는 것은 고치고, 여기에는 **지금은 판단할 근거가 없어 미뤄 둔 것**만 적는다.

미뤘다는 사실을 적어 두지 않으면 조건이 갖춰진 뒤에도 아무도 다시 오지 않는다.

## 규칙

- 항목을 지울 때는 무엇을 확인했고 결론이 무엇이었는지를 관련 문서에 먼저 남기고 지운다. 그냥 지우면 확인한 것인지 잊은 것인지 구분되지 않는다.
- 조건이 갖춰졌는데 아직 안 한 것과, 조건이 아직인 것을 섞지 않는다. `언제` 칸이 그 구분이다.

### 1. 강의 자료 4종의 본문을 아직 읽지 못했다

다음 PDF 는 슬라이드 본문이 이미지로 들어가 있어 텍스트 추출이 되지 않는다. 워터마크와 불릿만 나온다.

- `4) 생성형AI_1.Prompt 설계 및 Context Engineering_박병선p.pdf`
- `4) 생성형AI_2.LLM과 Transformer 아키텍처_Day1/Day2_박병선p.pdf`
- `2) 데이터분석 및 AIOps_2.데이터 분석 개요 및 기초통계_Day1/Day2_박병선p.pdf`
- `2) 데이터분석 및 AIOps_3.실전 Feature Engineering_이은호.pdf`

**Prompt 설계는 Phase 2-3·2-4(페르소나 인지 한계 차등, 정책 생성 프롬프트)에, 기초통계는 Phase 3-4(스피어만 순위 상관, 교란 요인 해석)에 직결된다.** 페이지 이미지로 읽어야 한다. 텍스트가 나오는 나머지 자료(Python 이해, Docker 가이드, sLLM 가이드)는 이미 반영했다.

### 2. 계획서의 범위 결정을 ADR 로 옮긴다

[`plan.md`](plan.md) 2장이 이미 정해 둔 것들 — 아이언클래드 단일 캐릭터, Act 1 한정, 적 3종, 카드 12~15장, LLM 과 결정론적 로직의 분리, 데이터·코드 분리, Vector DB·LangChain·FastAPI 미도입 — 은 전부 "되돌리려면 코드를 다시 써야 하는" 결정이다. 근거도 계획서에 이미 있다. 계획서 쪽에도 이 이관 예정을 인용구로 적어 뒀다.

지금 옮기지 않은 이유는 코드가 한 줄도 없어서 후보 비교가 공허하기 때문이다. **Phase 1 착수 전에는 옮긴다.** 그때가 이 결정들이 실제로 코드를 구속하기 시작하는 시점이다.

### 3. Phase 2 설계 — AI 를 어디까지 중심에 놓을 것인가

**2026-08-24 에 AI 비중을 늘리기로 정했다.** 방향은 정해졌고 구체는 미정이다. Phase 2 착수 전에 ADR 로 확정한다.

| 항목 | 후보 | 걸린 것 |
| --- | --- | --- |
| AI 관여 범위 | ① 매 턴 직접 조작 / ② 정책 자기 개선 루프 / ③ 시뮬레이터를 도구로 쓰는 분석 에이전트 / ④ 역할 분담 멀티 에이전트 | ① 만으로는 통계가 안 나온다 — Act 1 한 판이 약 80턴이라 1,000판이면 8만 호출이다 |
| 페르소나 조합 수 | 9조합(정보 3 × 고민 3) / 대각선 3조합 | 9조합이면 "몰라서 못 하나 안 따져봐서 못 하나"를 분리할 수 있다 |
| **API 예산** | — | ① 을 몇 판까지 돌릴지가 여기서 갈린다 |
| 구조화 출력 강제 방식 | tool use / `output_config.format` | — |

제공자는 Anthropic Claude 로 정했고 `requirements.txt` 와 `.env.example` 에 반영했다. **아직 아무것도 호출하지 않는다.**

### 5. Docker 이미지와 Streamlit 대시보드

계획서에서 둘 다 **권장**이지 필수가 아니다. 재현 가능한 실행 환경과 결과 대시보드는 **보여 줄 결과가 있어야 의미가 있다.** Phase 3 에서 지표가 나온 뒤에 붙인다.
