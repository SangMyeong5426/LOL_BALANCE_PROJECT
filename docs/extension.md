# 확장 작업 규칙

[ADR 0016](adr/0016-static-api-and-local-qa.md) 의 결정을 지키며 확장하기 위한 규칙이다.
**정적 API · 배포 페이지 · 로컬 화면의 Q&A · 재현 패키징을 건드리는 작업은 이 문서를 먼저 읽는다.**
사람이 하든 AI 에게 맡기든 같다.

**규칙을 넘어야 하면 구현 전에 ADR 을 쓰고 주인의 승인을 받는다.** 조용히 넘지 않는다.

## 이 문서를 읽는 때

| 건드리는 곳 | 먼저 볼 절 |
| --- | --- |
| `docs/site/**`, `scripts/make-site` | 1 · 2 · 5 · 6 |
| `scripts/app`, `src/lol_balance/agent/**`, `src/lol_balance/retrieval.py` | 1 · 3 · 4 · 6 |
| `Dockerfile`, 새 스크립트, 새 의존성 | 1 · 4 · 6 · 7 |
| 새 서버 · 새 언어 · 새 저장소를 들이자는 제안 | 7 |

## 1. 경계 — 무엇을 어디에 두는가

1. **언어는 Python 하나다.** 새 언어나 런타임(Java/Spring, Node 서버 등)을 들이지 않는다.
2. **계산은 Python 함수 한 곳에서만 한다.** 정적 API, 배포 페이지, 로컬 화면, Q&A 도구가 같은
   함수를 부른다. 같은 계산을 두 번 만들지 않는다 — 다른 파일에서도, 페이지의 JavaScript 에서도.
3. **공개와 로컬의 경계는 Riot 개인 키 규정이 정한다**([ADR 0010](adr/0010-riot-api-direct-aggregation.md#키는)).

   | | 배포 페이지 · 정적 API | 로컬 화면 |
   | --- | --- | --- |
   | 자료 | u.gg 패널 구간(`16_13` 패치까지) | 직접 집계를 포함한 전부 |
   | 직접 집계에서 나온 값 · 목록 · 파생 지표 | **한 글자도 싣지 않는다** | 쓴다 |
   | LLM 호출 | 없다 | 4절의 비용 규칙 아래에서만 |

4. **들이지 않는 것**: 상시 서버, DB 서버, 메시지 큐, 별도 프런트엔드 앱, 벡터 DB, K8s.
   7절의 조건이 오기 전까지다.
5. **화면을 늘리지 않는다.** 공개는 배포 페이지, 로컬은 로컬 화면, 터미널은 `ask` 하나씩이다.
   새 기능은 이 셋 중 하나에 넣는다.

## 2. 정적 API 와 배포 페이지

1. 응답은 `docs/site/api/v1/` 아래 JSON 이다. `make-site` 가 빌드 때 만든다. 페이지는 정렬과
   필터만 하고 **다시 계산하지 않는다.**
2. **같은 버전 안에서는 칸을 더하기만 한다.** 칸을 빼거나 뜻을 바꾸려면 `v2` 새 경로로 내고,
   페이지가 옮겨 간 뒤에 `v1` 을 지운다.
3. 응답마다 JSON Schema 를 두고, **계약 테스트**가 생성물 전부를 검사한다.
4. 계약 테스트는 **공개 범위를 넘는 자료가 0건**인지 본다 — `16_13` 뒤의 패치, 직접 집계 출처.
   실패하면 배포하지 않는다.
5. **숫자는 스크립트 출력에서만 온다.** 공개 목록은 `make-site` 와 `run-report` 가 낸 것과 같아야
   하고, 테스트로 맞춰 본다. 손으로 옮기지 않는다.
6. **점수는 확률이 아니다.** 화면에 「확률」로 적지 않고, 표본 수와 출처를 함께 보인다.
7. 크기 예산은 `api/v1` 전체 5 MB, 파일 하나 500 KB 다. 넘으면 나눈다.
8. Pages 는 10분 캐시를 준다. 자료는 `cache: 'no-cache'` 로 읽는다(지금 페이지와 같다).
9. **위키 노트 원문을 공개 JSON 에 싣는다면** CC BY-SA 3.0 출처 표기를 함께 싣는다. 아니면 노트로
   가는 링크만 둔다.
10. 화면이 바뀌면 미리보기로 데스크톱 폭과 휴대폰 폭(375px)을 본다 — 가로 넘침 0, 콘솔 오류 0.

## 3. 로컬 Q&A

1. **숫자는 도구가 계산한다.** 모델이 숫자를 새로 만들거나 계산하지 않는다.
2. 답은 구조화 출력이다 — 답 · 근거로 쓴 노트 블록 · 답에 쓴 숫자.
3. **코드가 대조한다.**

   | 표시 | 뜻 |
   | --- | --- |
   | ⚠ | 도구 결과에 없는 숫자를 썼거나, 없는 노트 블록을 인용했다 |
   | ⚪ | 대조할 수 없다 — 인용이 비었거나 형식이 맞지 않는다 |
   | ✅ | 대조를 통과했다. **실제로 확인한 것만 말한다** |

4. 후속 질문의 답도 같은 대조를 거친다.
5. 도구는 **기준 패치 뒤의 자료를 보지 않는다.** 누출 테스트를 둔다.
6. **벡터 검색을 넣지 않는다.** 챔피언과 패치로 정확히 찾고, 글 검색은 BM25 로 한다(MRR@10 0.946
   대 임베딩 0.488). 넣으려면 먼저 `score-retrieval` 에서 이겨야 한다.
7. 표본이 작으면 답에 그 사실을 적는다. 직접 집계는 챔피언당 수백 판이다.
8. 조정 효과를 「먹혔다 · 안 먹혔다」로 단정하지 않는다. 전후 변화와 표본 수를 보인다.
9. 모델이나 검색을 바꾼 것을 **적중률이 올랐다고 쓰지 않는다.**

## 4. 비용 · 키 · 자료

1. 유료 호출은 모두 장부(`data/spend.jsonl`)를 거친다. **상한은 호출 전에 실제로 막아야 한다** —
   가짜 모델로 상한을 넘겨 호출이 0회인지 테스트한다. 단가표에 없는 유료 모델은 거절한다.
2. 크레딧은 반 전체가 나눠 쓴다. 이 실험의 누적 상한은 $1 이다. 호출당 출력 1,000 토큰, 재시도
   1회, 같은 입력은 캐시한다. **페이지를 열 때와 일반 테스트에서는 유료 호출을 하지 않는다.**
   상한에 닿으면 멈추고 거기까지를 보고한다.
3. 반복과 개발은 로컬 모델로 한다. 유료 모델은 고정 질문 세트를 잴 때만 쓴다.
4. 이름이 정해진 모델을 쓸 수 없으면 다른 모델로 바꾸지 않고 그 사실을 적는다.
5. **키는 `.env` 에만 둔다.** 출력 · 로그 · 커밋 · 이미지 · JSON 어디에도 넣지 않는다.
6. `data/` · `runs/` · `.env` 는 커밋하지 않는다. Docker 이미지에도 넣지 않고 볼륨으로 붙인다.
7. **매일 수집의 양과 주기, 기본 모델은 주인이 정한다.** 확장 작업이 바꾸지 않는다.

## 5. 평가와 기록

1. 고정 묶음과 기록한 예측은 **덮어쓰지 않는다.** 새 이름으로만 만든다.
2. 전향 평가는 미리 적은 규칙으로, 라벨을 커밋한 뒤 한 번 채점한다. **고친 코드로 지난 지점을
   다시 채점해 「올랐다」고 쓰지 않는다.**
3. **학습 구간에서 고르고, 평가 구간은 재현에만 쓴다.** 평가 구간을 다시 봤으면 그렇게 적는다.
4. 기존 원자료 · 예측 · 평가 기록은 지우지 않는다.
5. 날짜와 시각에는 시간대(KST · UTC)를 붙인다. 붙이지 않아 헷갈린 적이 있다.

## 6. AI 에게 구현을 맡길 때

이 저장소에서 나온 결함 상당수가 **오류 없이 그럴듯하게 틀리는 코드**였다.

| 결함 | 겉보기 | 잡은 방법 |
| --- | --- | --- |
| 유료 호출 상한 | 예외를 던지는데 LangChain 이 삼켜 호출이 그대로 나갔다 | 가짜 모델로 상한을 넘겨 시험 |
| 수집 대기 루프 | `pgrep -f` 가 자기 명령줄을 잡아 끝나지 않았다 | 프로세스 목록을 직접 확인 |
| 데스 · 어시스트 칸 | 테스트는 통과했는데 직접 집계 예측에만 거꾸로 들어갔다 | 한 패치의 킬 합과 데스 합 비교 |
| `16_19` 채점 | 버그 수정까지 적중으로 셌다 | 패치 노트 원문 확인 |

그래서 이 순서로 한다.

1. **완료 기준을 테스트로 먼저 쓴다.** 무엇을 검사할지는 사람이 정하고 확인한다. 구현은 그
   테스트를 통과시키는 쪽으로 맡긴다.
2. **조용한 결함을 잡는 장치를 같이 둔다** — 합계 대조, 알려진 출력과 대조(머리 숫자,
   `16_13 → 16_14` 후보 목록), 가짜 모델 시험, 원문 대조.
3. PR 하나에는 한 단계의 한 가지 변경만 담는다. 브랜치와 커밋은 [CLAUDE.md](../CLAUDE.md) 를
   따른다. **push · PR · 머지는 매번 승인을 받는다.**
4. 코드를 바꾸면 `ruff` · `pytest` · `mypy` · `check-docs` · `check-links` · `check-rule-docs` 를 돌린다.
5. 프로세스를 기다릴 때는 PID 로 기다린다. `pgrep -f "<패턴>"` 은 자기 자신을 잡는다.
6. **면접에서 설명할 코드는 사람이 줄 단위로 읽는다** — 정적 API 빌드와 계약 테스트, 답 대조,
   킬 합 = 데스 합 검사. 설명할 수 없으면 머지하지 않는다.

## 7. 서버나 새 스택을 들이는 때

[ADR 0016](adr/0016-static-api-and-local-qa.md) 의 재검토 조건 중 하나가 생겨야 한다.

1. Production 키를 받아 최신 자료를 공개할 수 있게 된다
2. 로그인 · 저장처럼 쓰는 기능이 필요해진다
3. Q&A 를 공개하고 그 비용을 댈 수 있게 된다
4. 벡터 검색이 `score-retrieval` 에서 BM25 를 이긴다 — 이때는 검색만 다시 본다

그때도 **새 ADR 을 먼저 쓴다.** 서버를 두게 되면 FastAPI 로 같은 함수를 감싼다 — 계산을 옮기지 않는다.

## 8. 단계와 완료 기준

순서대로 한다. 앞 단계의 결과 위에 다음 단계가 선다.

### 0단계 — 바로잡기

확장이 틀린 숫자 위에 서지 않게 한다.

- [ ] 데스 · 어시스트 칸을 고치고, 모든 패치가 「킬 합 = 데스 합」 검사를 통과한다
- [ ] 고친 뒤에도 u.gg 머리 숫자(27.4% · 22.9% · 0.900)가 그대로다
- [ ] 상한을 넘기면 유료 호출이 0회다(가짜 모델 시험)
- [ ] 문서끼리 어긋난 숫자를 맞춘다 — README 의 1.8배와 CLAUDE.md 의 1.9배 등

### 1단계 — 정적 API 와 배포 페이지

배포 페이지를 「패치별 후보 목록」에서 「챔피언 이력과 조정 효과까지」로 넓히고, 같은 자료를 정적 API 로도 연다.

- [ ] `api/v1/` 에 패치 목록, 패치별 후보, 챔피언 이력, 조정 효과가 있다
- [ ] 모든 화면이 `api/v1` 만 읽는다
- [ ] 계약 테스트를 통과한다 — 스키마, 공개 범위를 넘는 자료 0건
- [ ] `16_13 → 16_14` 후보 목록이 지금 페이지와 같다
- [ ] 휴대폰 폭에서 가로로 넘치지 않는다

### 2단계 — 근거를 붙인 로컬 Q&A

「이 챔피언 너프 후에 뭐가 바뀌었나」에 도구가 계산한 숫자와 노트 블록으로 답한다.

- [ ] 로컬 화면의 자료 결함을 먼저 고친다 — `16_15` 라벨, 최신 노트 색인, 학습 행 섞임
- [ ] 도구 `effect_of(챔피언, 패치)` 가 조정 전후의 승률 · 픽률 · 밴율과 표본 수를 낸다
- [ ] 학습 구간에서 고른 고정 질문 20~30개에서 도구에 없는 숫자 0개, 없는 노트 블록 0개다
- [ ] 표본이 작으면 작다고 답한다
- [ ] 쓴 비용이 장부에 남는다

### 3단계 — 재현 패키징 (선택)

- [ ] Dockerfile 하나. 자료와 키는 볼륨으로 붙인다
- [ ] 새 머신에서 테스트가 통과하고, 같은 자료로 빌드한 배포 페이지가 커밋된 것과 바이트까지 같다
