### 스냅샷 전에 풀어야 할 것

**1. 표본 수를 못 구한다.** 두 출처 모두 공개하지 않는다. 표본 수 없이는 저표본 카드를 거를 수 없고, 순위 상관에 가중치도 못 준다. 카드 하나가 30판 기준 60% 승률인지 3만 판 기준 60% 인지 구분되지 않는다.

대안 세 가지 — (a) 표본 수를 공개하는 다른 출처를 더 찾는다, (b) Pick Rate 를 표본 수의 대리 지표로 쓴다(픽률이 낮으면 표본도 적다), (c) 표본 수 없이 진행하되 **README 와 리포트에 그 한계를 명시한다.**

(b)가 현실적이다. 다만 픽률은 표본 수와 상관이 있을 뿐 같은 것이 아니므로, 그렇게 썼다는 사실을 리포트에 적는다.

**2. Act 별 분리가 필요하다.** 이 프로젝트는 Act 1 한정인데 대부분의 출처는 Run 전체 승률을 준다. untapped.gg 의 Act 상대 지표가 이 문제를 푸는 유일한 후보로 보인다. 실제로 무엇을 재는 값인지 확인해야 한다.

**3. Ascension 구간을 맞춰야 한다.** [`../docs/spec/open-questions.md`](../docs/spec/open-questions.md) C 항목. 시뮬레이터의 Ascension 과 통계의 Ascension 이 다르면 상관이 낮게 나오고, 그 원인을 교란 요인으로 오진한다.

## 백테스트 창

**v0.111.0 이 최신이다** (2026-08-13). 창 안에 패치 7개가 있다.

```
v0.107.1 (Major Update 2) → v0.108.0 → v0.109.0 → v0.109.1
                          → v0.110.0 → v0.110.1 → v0.111.0
```

v0.111.0 의 아이언클래드 변경 3건(Expect a Fight 리워크, Forgotten Ritual 버프, Rampage 버프)은 [`../docs/spec/research-notes.md`](../docs/spec/research-notes.md)에 수치까지 적어 뒀다. **나머지 6개 패치의 변경 내역을 모아야 정답지가 완성된다.** 한 패치의 카드 3장으로는 탐지율·오탐률이 통계적으로 의미가 없다.
